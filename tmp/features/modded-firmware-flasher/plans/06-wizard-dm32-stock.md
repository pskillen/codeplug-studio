## Series rules (apply to every change in this phase)

## Context

This is the first operator-facing slice: a wizard at **`/firmware`** that flashes **stock firmware only**, to a
**DM-32UV**. It needs no release catalog (that's phase 7). It proves the risky app pieces on the shorter protocol:

- re-picking the port with USB filters after the radio enters update mode;
- the wake lock;
- the navigation block;
- the cancel confirmation;
- the recovery screen.

It also adds the **per-radio prod gate resolver**. Both radios' updaters start with `prodFlashDisabled: true`, so on
the prod build the flasher shows no radios, and the Tools strip omits it. On next, dev and staging it is fully
available. Later phases add releases (phase 8) and the AT-D890UV (phase 11) to the same wizard, without
restructuring it.

Firmware belongs to the physical radio, not to a project or build. The route sits **outside**
`RequireActiveProject`, and nothing is persisted.

**Layer rules for this phase:**

- `src/app/` imports radio I/O only from `@integrations/radio-io` (the barrel), and core from `@core/...`.
- **No radio literals in the app.** That covers USB IDs, model IDs, entry steps, verify hints and durations: all
  come from `FirmwareUpdaterDescriptor` / `StockFirmwareDescriptor`.
- The wizard renders the descriptor's `bootloaderEntry` generically.

**Vendor firmware rule:** the app holds the user's stock bytes in memory only, and drops them when the user leaves
the page. Tests use synthetic bytes. Nothing is committed.

## Slice 3: orchestration service

`src/app/services/firmwareFlash.ts` is thin. It holds no protocol or radio knowledge.

```ts
export async function filesToNamedBytes(files: readonly File[]): Promise<NamedBytes[]>;
export async function verifyStockFiles(radioId: FirmwareRadioId, files: readonly NamedBytes[]): Promise<VerifiedStockFirmware>;
//   uses resolveStockFirmware(getStockFirmwareDescriptor(radioId), files,
//        { otherDescriptors: others, knownPatchedResults: [] })   // phase 8 supplies catalog results
export async function prepareStockFlash(radioId: FirmwareRadioId, stock: VerifiedStockFirmware): Promise<PreparedFirmwareImage>;
//   prepareFirmwareImage({ descriptor, stock, target: { kind: 'stock' } }), then
//   getFirmwareUpdater(radioId)!.createUpdater().checkImage(image)  (interlocks run before any radio contact)
export async function grantFirmwarePort(radioId: FirmwareRadioId): Promise<SerialPortLike>;
//   requestWebSerialPort(true, descriptor.link.usbFilters) — always force a fresh pick
export type FirmwareFlashOutcome =
  | { ok: true; radioId; image: PreparedFirmwareImage; ident: FirmwareBootloaderIdent; result: FirmwareFlashResult; startedAt: string }
  | { ok: false; radioId; image: PreparedFirmwareImage; ident?: FirmwareBootloaderIdent; code: string; message: string;
      position: string; radioTouched: boolean; startedAt: string };
export async function runFirmwareFlash(input: {
  radioId: FirmwareRadioId; image: PreparedFirmwareImage; port: SerialPortLike;
  onIdent?: (ident: FirmwareBootloaderIdent) => void;
  onProgress: (p: FirmwareFlashProgress) => void; signal: AbortSignal;
}): Promise<FirmwareFlashOutcome>;
//   open pipe at descriptor.link.baudRate → updater = createUpdater() → identify → onIdent → flash
//   → ALWAYS close the pipe in finally (swallow close errors) → outcome. Never throws for flash failures.
//   Errors before identify completes (open, ident mismatch) → ok:false with radioTouched:false.
export function formatFirmwareFlashSummary(outcome: FirmwareFlashOutcome): string;
```

The summary is plain text. It contains:

- radio label;
- provenance (`stock`; later also "bundled release X" / "user-supplied patch, sha256 …");
- stock version and member sha256s, and result sha256s by role;
- the version stamp if any;
- the ident (model, raw hex);
- frames, elapsed time and end kind;
- on failure: code, message, position and `radioTouched`;
- `Studio __BUILD_VERSION__ (__BUILD_ENV__)` and the date.

It **is not persisted**.

> CPS.
>
> 1. Wait for the `dev` deploy, then open `https://dev.codeplug.mm9pdy.net/firmware` in Chrome or Edge.
> 2. Have the vendor zip `Baofeng_DM-32UV_Firmware_v1.01.048.zip`, or the extracted `DM32_L01_048_20250821.bin`.
>    Optionally, back up the codeplug first from a build's Backup tab.
> 3. Pick **Baofeng DM-32UV** → **Stock firmware (v1.01.048)** → drop the zip. Check it shows "verified".
> 4. Tick the preflight boxes. Follow the update-mode steps: radio off, cable out; hold SK1+PTT and power on; at the
>    green LED, release; plug the cable in.
> 5. **Connect and flash.** The port picker should list only the CH340 cable. Watch Handshake → Erase (about 13 s) →
>    Transfer → Finish. It takes about 2 minutes.
> 6. Check the radio boots to its normal screen with your channels.
> 7. Reply with: OK or FAIL, the duration, the copied summary, and anything odd (picker, wake lock, progress, wording).
>    Optional: also test cancel before the erase on a second attempt ("Nothing was written").
