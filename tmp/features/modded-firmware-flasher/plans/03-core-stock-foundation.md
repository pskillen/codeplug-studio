## Context

Studio will flash firmware that the **user supplies**. The user gives either the vendor zip or the files extracted
from it. Studio verifies them against pinned SHA-256s, optionally applies a release patch (later phases), and hands
the image to a bootloader updater (later phases). This phase lays the **pure core foundation**:

- firmware types, a SHA-256 helper, a strict hex parser, and typed errors (`src/core/firmware/`);
- each radio's **pinned stock descriptor**, next to its `limits.ts` (`src/core/radios/<mfr>/<model>/firmware.ts`);
- a tiny stock catalog listing both descriptors;
- **stock resolution**: unzip only the needed members, match by basename, verify size and hash, and diagnose
  wrong-radio and already-patched inputs;
- a `StockSource` interface with a user-file implementation (the seam for a future remote source);
- `prepareFirmwareImage` for the **stock target only**. A later phase (#1362) adds the patch target. That's what lets
  a stock-only DM-32UV wizard ship before the release catalog.

**Vendor-neutral note:** generic code (`src/core/firmware/*.ts`, `stock/`, `services/firmware/`) works on member
**roles** and hashes. It never names `.CDD`, `.bin` or offsets. File names and sizes appear only in the radios'
`firmware.ts`. There are no library, build or persistence changes, and no FKs.

**Vendor firmware rule:** tests use **synthetic** descriptors and synthetic bytes (seeded random arrays), with hashes
computed in the test. The real pins in `firmware.ts` are never matched by any test, because that would need vendor
bytes. Never download, fetch or commit stock firmware.

## Target shapes (create exactly these; later phases depend on them)

`src/core/firmware/types.ts`:

```ts
export type FirmwareRadioId = 'baofeng-dm32uv' | 'anytone-at-d890uv';

/** A file the user gave us (or, later, a remote source fetched). Name is the basename only. */
export interface NamedBytes {
  readonly name: string;
  readonly bytes: Uint8Array;
}

export interface StockFirmwareMember {
  /** Stable role key used by patch formats and updaters. Declared per radio; generic code never hard-codes one. */
  readonly role: string;
  readonly fileName: string;
  readonly size: number;
  readonly sha256: string; // lowercase hex
}

export interface StockFirmwareDescriptor {
  readonly radioId: FirmwareRadioId;
  readonly label: string;
  readonly version: string;
  /** Shown as a link only. Never fetched by Studio code. */
  readonly vendorDownload: { readonly url: string; readonly host: string; readonly note?: string };
  /** The vendor zip as published. Diagnostic: member hashes are authoritative. */
  readonly zip: { readonly fileName: string; readonly sha256: string };
  readonly members: readonly StockFirmwareMember[];
  /** Patch `name` values whose releases apply to this radio. */
  readonly patchNames: readonly string[];
  /** Human-facing update-mode entry, rendered generically by the wizard. */
  readonly bootloaderEntry: {
    readonly steps: readonly string[];
    readonly indicator: string;
    readonly warnings: readonly string[];
  };
  /** How the operator confirms stock is running after a flash. */
  readonly stockVerifyHint: string;
}

/** Bytes keyed by member role. Stock and patched packages share this shape. */
export interface FirmwarePackage {
  readonly radioId: FirmwareRadioId;
  readonly files: Readonly<Record<string, Uint8Array>>;
}

export type FirmwareProvenance = 'stock' | 'bundled' | 'unreviewed';

/** Result hashes of a known patched build, so stock resolution can say "this is already-patched firmware". */
export interface KnownPatchedResult {
  readonly radioId: FirmwareRadioId;
  readonly label: string; // e.g. 'release 1.0.0'
  readonly sha256: Readonly<Record<string, string>>; // by role
}
```

`src/core/firmware/hash.ts`: `export async function sha256Hex(bytes: Uint8Array): Promise<string>` (lowercase hex).
`src/core/firmware/hex.ts`:

- `export function hexToBytes(hex: string): Uint8Array`. Strict: lowercase or uppercase `[0-9a-f]` only, even
  length. Otherwise it throws `FirmwareError('patch-malformed', …)`.
- `export function bytesToHex(bytes: Uint8Array): string`.

`src/core/firmware/errors.ts`:

```ts
export type FirmwareErrorCode =
  | 'stock-corrupt-zip'
  | 'stock-missing-member'
  | 'stock-duplicate-member'
  | 'stock-wrong-version' // right file names, wrong hashes or sizes
  | 'stock-wrong-radio' // matches another radio's pinned stock
  | 'stock-is-patched' // matches a known patched result
  | 'patch-unreadable'
  | 'patch-unknown-format'
  | 'patch-wrong-radio'
  | 'patch-wrong-stock'
  | 'patch-malformed'
  | 'patch-original-mismatch'
  | 'patch-result-mismatch';

export class FirmwareError extends Error {
  constructor(
    readonly code: FirmwareErrorCode,
    message: string,
  ) {
    super(message);
    this.name = 'FirmwareError';
  }
}
```

Every message names the problem in user terms. For example: "This is AT-D890UV firmware, but you picked the
DM-32UV." or "This zip is not stock v1.01.048."

## Slice 3: stock resolution and `StockSource`

`src/core/firmware/stock/resolveStockFirmware.ts`:

```ts
export interface VerifiedStockFirmware {
  readonly descriptor: StockFirmwareDescriptor;
  readonly package: FirmwarePackage; // copies, keyed by role
  readonly sha256: Readonly<Record<string, string>>; // by role
  readonly via: 'zip' | 'files';
  /** Zip hash differed from the pinned one, but every member matched (re-zipped download). */
  readonly zipMismatchNoted: boolean;
}

export interface ResolveStockContext {
  /** Every other radio's descriptor, for 'stock-wrong-radio'. */
  readonly otherDescriptors: readonly StockFirmwareDescriptor[];
  /** Known patched results (later: from the release catalog), for 'stock-is-patched'. */
  readonly knownPatchedResults?: readonly KnownPatchedResult[];
}

/** Pure. Every source, present and future, goes through this one verifier. */
export function resolveStockFirmware(
  descriptor: StockFirmwareDescriptor,
  inputs: readonly NamedBytes[],
  context: ResolveStockContext,
): Promise<VerifiedStockFirmware>;
```

**Behaviour:**

1. **Zip detection.** An input starting with `50 4B 03 04` (`PK\x03\x04`) is a zip.
   - Hash the whole zip; this is diagnostic.
   - Call `unzipSync(bytes, { filter: (f) => wanted.has(basename(f.name)) })` (fflate). `basename` normalises `\`
     to `/` and takes the last segment. **Only member entries are inflated**: the 44.5 MB D890 zip's ICON pack must
     never be inflated.
   - Exactly one entry per member is required: `stock-missing-member` or `stock-duplicate-member`.
   - An fflate exception becomes `stock-corrupt-zip`.
   - If the zip hash differs from `descriptor.zip.sha256` but every member then verifies, set
     `zipMismatchNoted: true`.
2. **Extracted files.** Non-zip inputs are matched to members by basename. Several inputs may be given, and a zip may
   be mixed with loose files (the zip's members win; note duplicates). A missing member gives
   `stock-missing-member`; two inputs for one member give `stock-duplicate-member`.
3. **Verify every member:** the size first, then `sha256Hex`. On a mismatch, check in this order before reporting:
   - the bytes match a `knownPatchedResults` entry for this radio → `stock-is-patched` ("This is already-patched
     firmware (release 1.0.0); supply the vendor download");
   - the bytes, or the input zip's hash, match another descriptor's member or zip hashes → `stock-wrong-radio`;
   - otherwise → `stock-wrong-version` ("…is not stock v1.01.048").

   A zip that contains another radio's member names (none of this radio's) counts as `stock-wrong-radio`.
4. Return role-keyed **copies** (`bytes.slice()`), so later patching can never mutate the user's buffers.

`src/core/firmware/stock/stockSource.ts`:

**Tests** (`resolveStockFirmware.test.ts`). Use **synthetic descriptors**: build them in the test from seeded random
bytes, and compute the hashes with `sha256Hex`. Use `zipSync` from fflate to build zips in memory.

- one-member radio: the zip passes; the extracted file passes;
- three-member radio: the zip passes; three loose files pass; a zip plus a loose duplicate is handled;
- hash mismatch → `stock-wrong-version`;
- size mismatch → `stock-wrong-version`;
- missing member → `stock-missing-member`;
- duplicate member (two entries with the same basename in different folders) → `stock-duplicate-member`;
- corrupt zip (valid magic, garbage body) → `stock-corrupt-zip`;
- the other radio's synthetic stock → `stock-wrong-radio`;
- bytes equal to a `knownPatchedResults` hash → `stock-is-patched`;
- a re-zipped zip (members fine, zip hash different) passes with `zipMismatchNoted: true`;
- the decoy-entry test: a zip with a large non-member entry. Assert the filter callback was never asked to inflate it
  (wrap the filter with a spy and check the result has no such key);
- the returned buffers are copies: mutate the output and check the input is unchanged.
