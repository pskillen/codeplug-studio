## Series rules (apply to every change in this phase)

- **Read `AGENTS.md` and `DESIGN.md`** before the first edit. From phase 2 on, read DESIGN.md's "Firmware flashing"
  section, and `.claude/rules/firmware-flashing.md` if present.
- **No vendor firmware, ever, in any committed path.** That means no stock `.bin`, `.CDD`, `.CDI` or `.spi`, no
  vendor zip, and no slice of one: not in `src/`, test fixtures, docs, scripts or the planning branch. Tests build
  **synthetic** images in memory, and compute hashes on the fly. Studio's own release patch files are allowed, and
  only phase 7 adds them.
- **Hard interlocks are code.** No setting, flag, env value, query parameter or patch field may disable one.
- **Layers:**
  - `src/core/` has no React, DOM, `@app` or `@integrations` imports;
  - `src/integrations/` has no React and no `@app` imports;
  - `src/app/` imports radio I/O only from `@integrations/radio-io` (the barrel), and has **no radio literals**: no
    USB IDs, model IDs, entry steps or verify hints. Those come from descriptors.
- **Docs ship in the same PR** as the behaviour they describe.
- **Never touch hardware**, and never ask anyone to except through the "Hardware gate" section, which the
  orchestrator handles. Do not start the next phase.

## Context

"Flash stock firmware" is the zero-patch case of the same pipeline, and it is the **documented way back** on both
radios. The wizard has offered a stock entry since phase 6. This phase:

- writes the **Recovery** section of the feature hub;
- links it from the wizard's failure and recovery screen, and from the modded-firmware hub;
- puts the hardware stock proof for the **AT-D890UV** in front of the owner (H5). The DM-32UV's stock flash was
  already proven in phase 6 (H2).

Background: the firmware repo's own D890 sender has written modded images, but **never stock**. That runbook step
was dropped in favour of the vendor CPS. Stock is the zero-hook, zero-append case of the same frame stream, but it
must be proven once on hardware before Studio calls it the recovery route.

This phase does **not** clear the D890 `stockFlashHardwareProven` label or its prod flag. Phase 13 does both, after
the owner confirms H5.

## Slice 1: hub Recovery section

Write `## Recovery` in the hub (tier 1: product behaviour, no wire tables):

- **If a flash fails before the radio was touched** ("Nothing was written"): power-cycle and try again.
- **If it fails after** (`radioTouched`):
  - don't keep power-cycling;
  - re-enter update mode with the radio's steps (link the tier-3 `firmware.md` update-mode sections);
  - flash the same release again, or flash **stock** from the wizard's "Stock firmware" entry;
  - you need the vendor stock download either way.
- **Going back to stock on purpose:** the same stock entry.
- **Fallback:** the vendor CPS, for both radios. Name the CPS, and link to the vendor download only as a plain link,
  the same URL as the descriptor.
- **Status per radio:**
  - DM-32UV stock via Studio: proven on hardware (H2);
  - AT-D890UV stock via Studio: "being proven"; phase 13 updates this line. Until then the wizard labels the D890
    stock entry.
- Add a short "What Studio checks before any byte is sent" list (stock hashes, result hashes, interlocks), linking
  `DESIGN.md#firmware-flashing`.

**Commit checkpoint:** `docs(firmware): add the firmware recovery guide`

## Hardware gate (H5): the orchestrator does this after the PR is open

The orchestrator force-pushes this branch to `dev`, then stops and sends the owner this script.

> **H5, AT-D890UV stock V1.05 flash from `dev` (the D890 stock proof).** This writes firmware. Studio has never
> flashed D890 stock before. Have the vendor CPS ready as a fallback.
>
> 1. Open `https://dev.codeplug.mm9pdy.net/firmware`. Pick **AnyTone AT-D890UV** → **Stock firmware (V1.05
>    (20260521))**. It still shows the "not yet hardware-proven" label; that's expected.
> 2. Drop the vendor zip or the three extracted files. Check it shows "verified".
> 3. Preflight → update mode (PTT+PF3 at power-on, red LED blinking) → **Connect and flash**.
> 4. After the restart, check **Menu > Device Info > Version shows "Ver 1.05"**.
> 5. Reply with: OK or FAIL, the duration, the copied summary, and anything odd.
>
> **If H4 (`1.0.0`) and H5 both passed, the AT-D890UV is proven.** Say so explicitly ("D890 proven, enable prod") so
> the orchestrator can run phase 13.
>
> To leave the radio on the mod afterwards, flash `1.0.0` again from the same page.
