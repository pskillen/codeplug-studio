# Modded firmware flasher: plan series index

Execution plans for epic [#1358 Modded firmware flasher](https://github.com/pskillen/codeplug-studio/issues/1358),
under [#594 Browser radio I/O](https://github.com/pskillen/codeplug-studio/issues/594).

- Design rationale: [../hl-delivery-plan.md](../hl-delivery-plan.md)
- Ticket map: [../ticket-management.md](../ticket-management.md)
- Phase sequencing and the delivery model: [../phase-plan.md](../phase-plan.md)

**4 phases, one PR each, stacked.**

- The orchestrator spawns one `implementor` per phase. Phase 1 branches from `origin/main`; phase N branches from
  phase N-1's branch, and its PR targets that branch. The orchestrator never merges.
- **After every phase, and at every hardware gate inside a phase, the orchestrator stops, notifies the owner and
  waits.**
- In phases 3 and 4 the implementor pushes the branch to `dev` (`https://dev.codeplug.mm9pdy.net`), stops at the
  hardware gate, and returns the owner's test script. Only the owner touches hardware.
- In phases 3 and 4, after the owner confirms the gate, an implementor adds **one final commit** on the same branch
  that turns that radio on in prod (`prodFlashDisabled: false`).

Each plan file is self-contained for a fresh agent on a **fresh cloud container**. It starts with a Bootstrap that:

- fetches the orphan planning branch `plan/modded-firmware-flasher`;
- re-clones the private firmware repos read-only when needed;
- uses the GitHub MCP tools, because `gh` is unauthenticated.

The phases are large, so commits stay atomic per slice.

**Exclusions:**

- no Android flashing (hidden on Capacitor; follow-up [#1367](https://github.com/pskillen/codeplug-studio/issues/1367));
- no DM-32UV read-back verify ([#1368](https://github.com/pskillen/codeplug-studio/issues/1368));
- no runtime fetch;
- no resource-mode (ICON pack) flashing;
- **no vendor firmware committed anywhere, ever**;
- no internal or test-provenance copy in the UI (no tested/untested pills); a risk acknowledgement on every flash.

## Git workflow (applies to every phase; each phase file restates its own values)

- **Repo:** `pskillen/codeplug-studio`.
- **GitHub:** use the GitHub MCP tools (`gh` is unauthenticated). Comments end with the footer `---` /
  `_Generated by [Claude Code](https://claude.ai/code)_`.
- **Branches:** check out from `origin/<prior phase branch>` (phase 1: `origin/main`). The PR base is the prior phase
  branch (phase 1: `main`).
- **Commits:** atomic conventional commits at each slice checkpoint (`feat`, `fix`, `docs`, `style`, `refactor`,
  `chore`).
- **Before the PR:** `npm run format`, then `npm run format:check && npm run lint && npm run test && npm run build`.
- **Docs** ship with the behaviour.
- **Dev deploy:** `git push --force origin HEAD:dev`. This epic owns `dev` for its duration.
- **Never merge.** Never commit vendor firmware.
