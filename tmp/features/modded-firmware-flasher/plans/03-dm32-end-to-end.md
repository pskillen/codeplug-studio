## Part A: FirmwareUpdater seam and DM-32UV updater (#1363)

### Background

Studio's radio I/O contracts are codeplug-shaped: `CloneImageRadio` is connect → download a memory map → upload one.
A bootloader firmware update is different: a one-way, precomputed frame stream with a destructive erase part-way
through. This part adds:

1. A **sibling seam**, `FirmwareUpdater`, in `src/integrations/radio-io/firmware/`, with:
   - a separate firmware registry;
   - one **guarded send** helper, which is the only `pipe.write` call site in firmware code;
   - `FirmwareFlashError`.
2. A kit error code `'interlock'` and `RadioInterlockError`.
3. **USB filters** on Web Serial port picking, so the flasher can make the user pick the cable's port again after
   the radio enters update mode.
4. The **DM-32UV updater**: a byte-exact port of `baofeng-dm32-firmware/tools/flash/dm32_fw_send.py`. That sender's
   plan equals a USB capture of the official CPS byte for byte, and it has written stock 048 to a real radio. It
   comes with a TS port of `tools/flash/bootloader_mock.py` as the test bootloader.
5. A **per-radio prod gate field** on the descriptor: `prodFlashDisabled: true`. The app resolver comes later in this
   phase (Part B). The flag is cleared by the **final commit** of this part, after the owner's hardware gate.

The Python senders' **policy** gates (dry-run default, typed phrases, `--gate` result files, the stock-only default)
are **not** ported. In Studio, pinned stock hashes plus a patch's result hash do that job. The **hard interlocks**
are ported, and they are never configurable.

**Android:** `capacitorSupported: false`. The flasher is hidden on Capacitor in this epic (follow-up #1367).

**Vendor firmware rule:** tests use **synthetic** 860,416-byte images: `BFUV32-V2` at offset 0, `END` at `0xFD`, and
seeded random bytes elsewhere. Never real stock.

### Slice 3: DM-32UV plan, CRC and interlocks

The Python plan (`dm32_fw_send.py build_plan`) is the spec. Port it byte for byte:

```python
HEADER_LEN = 0x100; MODEL_ID = b"BFUV32-V2"; SOH, STX, EOT, ACK, C = 0x01, 0x02, 0x04, 0x06, 0x43; PAD = 0x1A
def block0(name, body_len): meta = name.encode("latin-1") + b"\0" + str(body_len).encode(); return meta padded with 0x00 to 0x80
def build_plan(image, name=STOCK_NAME, erase_timeout=60.0):
    body = image[HEADER_LEN:]
    steps = [Step("init", b"\x52", b"\x06", 0.5), Step("model-query", b"\x4D\x00\x00\x00\x01", b"\x4D\x01\x09", 0.5),
             Step("model-id", b"\x06", image[:9], 0.5), Step("prelude-45", b"\x45\x00\x00\x00\x00", b"\x06", 0.5),
             Step("prelude-31", b"\x31", b"C", 5.0), Step("soh-block0", b"\x01", b"C", 5.0)]
    b0 = block0(name, len(body))
    steps.append(Step("block0+erase", b"\x00\xFF" + b0 + crc16_xmodem(b0).to_bytes(2, "big"), b"\x06C", erase_timeout, "erase"))
    off, seq, n = 0, 1, 0
    while off < len(body):
        rem = len(body) - off; size = 0x400 if rem >= 0x400 else 0x80; typ = STX if size == 0x400 else SOH
        take = min(size, rem); blk = body[off:off+take] + bytes([PAD]) * (size - take)
        if seq > 0xFF: seq = 0
        steps.append(Step(f"type#{n}", bytes([typ]), b"C", 10.0))
        steps.append(Step(f"block#{n}", bytes([seq, 0xFF - seq]) + blk + crc16_xmodem(blk).to_bytes(2, "big"), b"\x06", 10.0))
        off += take; seq += 1; n += 1
    steps.append(Step("eot", b"\x04", b"", 5.0, "eot", ignore_rx=True))   # read 1 byte, ignore it
# CRC16-XMODEM: poly 0x1021, init 0, MSB first, no xorout. crc16("123456789") == 0x31C3.
# Session._send: guard.check(frame); pipe.flush_input(); sleep(0.010); pipe.write(frame)   # the CPS's ComWrite
# Session.run: for each step: send; if ignore_rx: read 1 byte (ignore), stop; rx = read_exact(len(step.rx), timeout);
#              if rx != step.rx: abort (no NAK, no resend, no resume)
```

    - the CPS header check: `bin[0xFD] === 0x45 || bin[0xFE] === 0x4E || bin[0xFF] === 0x44` (any one of E, N, D;
      the CPS's own check at `0x42320B`).
  - `createDm32TxGuard(plan)`: `check(frame)` accepts **exactly** `plan[index].tx` (byte-equal) and nothing else;
    `advance()` moves on. It is a port of `TxGuard`.
- Tests (`plan.test.ts`, `interlocks.test.ts`), using a synthetic stock-length image (`BFUV32-V2` header, `END` at
  `0xFD`, seeded body):
  - CRC matches an independent bitwise implementation, and `crc16Xmodem("123456789") === 0x31C3`;
  - prelude TX equals `[52] [4D 00 00 00 01] [06] [45 00 00 00 00] [31] [01]`, and RX equals
    `[06] [4D 01 09] image[0..9) [06] [43] [43]`;
  - **golden block 0:** meta `DM32_L01_048_20250821.bin\0` + `860160`, zero-padded to 128. The frame is 0x84 bytes
    and **its CRC is `0x4227`** (the value the firmware repo's tests assert for stock 048). It depends only on the
    name and length, so it needs no vendor bytes;
  - a stock-length image gives **840 STX blocks**, 1,688 frames in total, all type bytes `02`, and the last seq
    `0x48`;
  - each block equals `seq, 0xFF-seq, chunk, CRC` (an independent derivation in the test);
  - EOT is last; the header bytes `image[0..0x100)` never appear in the concatenated TX stream;
  - a short-tail image (`0x100 + 300*1024 + 200`) gives 302 blocks: 300 STX then two SOH tails. `blocks[255]` starts
    `00 FF` (the seq wraps), and the last block is padded with 56 bytes of `0x1A`;
  - the guard accepts only the next frame; any other frame throws `RadioInterlockError`;
  - `checkDm32FirmwareImage` refuses: the wrong length, the wrong model ID, no E/N/D at all, `radioId` of the other
    radio, and an extra role.

### Slice 4: DM-32UV updater, mock bootloader, descriptor

`updater.ts`: `createDm32FirmwareUpdater(opts?: { preSendDelayMs?: number; eraseTimeoutMs?: number }): FirmwareUpdater`.
Tests pass `preSendDelayMs: 0`.

- **`identify(pipe)`:**
  - bind the pipe and a guarded send;
  - build the 3 prelude steps from constants (step 3's expected RX is ASCII `BFUV32-V2`);
  - for each step: `throwIfAborted`, `await pipe.flush?.()`, wait `preSendDelayMs`, guarded send, `readExact` with
    the step's timeout, then an exact compare;
  - step 2's reply must be `4D 01 09`. A mismatch is a `RadioWrongIdentError` ("Bootloader model reply …") or a
    `RadioProtocolError`;
  - return `{ radioId: 'baofeng-dm32uv', model: 'BFUV32-V2', raw }`.

  All of this precedes anything destructive by construction.
- **`flash(image, opts)`:**
  1. If `identify` hasn't completed on this instance, throw (wrapped, `radioTouched: false`).
  2. `bin = checkDm32FirmwareImage(image)`.
  3. Require `bin[0..9)` to equal the ident's `raw`, or throw `RadioInterlockError`. **The model check is enforced
     before the erase.**
  4. `plan = buildDm32FirmwarePlan(bin, DM32UV_FIRMWARE_BLOCK0_FILE_NAME, eraseTimeoutMs)`.
  5. Assert that `plan[0..3)` TX equals the prelude already sent.
  6. Run `plan[3..]` with a guard starting at index 3. For each step:
     - abort checks between frames only, never mid-frame;
     - flush, then the delay, then the guarded send;
     - set `radioTouched = true` **immediately before** sending the `block0+erase` frame;
     - EOT: read 1 byte with its timeout, ignore the value, and treat a timeout as fine; `end: 'eot-sent'`.
  7. Progress: emit a `FirmwareFlashProgress` on each phase change and every 8 data blocks. `cur`/`max` are the step
     index and plan length; `msg` is like "Transfer 120/840".
  8. Any error: stop sending, close nothing (the caller owns the pipe), and throw `FirmwareFlashError` with `cause`,
     `radioTouched` and `position` (the step name, e.g. `block#57`).
  9. Return `{ framesSent, dataFrames: 840, elapsedMs, end: 'eot-sent' }`.

`__fixtures__/dm32BootloaderMock.ts`: a `BytePipe` port of `tools/flash/bootloader_mock.py`.

- It is a state machine: `idle` → `want4d` → `want06` → `want45` → `want31` → `wantsoh` → `block0` → (`type` ↔
  `data`) → `done`.
- It checks CRC and seq, and reassembles `body`. It records `violations[]`, `frames[]`, `erased` and `eotSeen`.
- Faults: `silentAt` (a reply index from which it goes silent) and `wrongReplyAt: Map<replyIndex, Uint8Array>`.
- `readExact(n)` returns `n` bytes if they're buffered, otherwise throws `RadioTimeoutError` at once (simulated
  timeout).
- It replies `06` to EOT.

## Part B: wizard, DM-32UV stock path and prod gate resolver (#1365)

### Background

This is the first operator-facing slice: a wizard at **`/firmware`** that flashes **stock firmware only**, to a
**DM-32UV**. It needs no release catalog (Part C). It proves the risky app pieces on the shorter protocol:

- re-picking the port with USB filters after the radio enters update mode;
- the wake lock;
- the navigation block;
- the cancel confirmation;
- the recovery screen.

It also adds the **per-radio prod gate resolver**. Both radios' updaters start with `prodFlashDisabled: true`, so on

Firmware belongs to the physical radio, not to a project or build. The route sits **outside**
`RequireActiveProject`, and nothing is persisted.

**Vendor firmware rule:** the app holds the user's stock bytes in memory only, and drops them when the user leaves
the page. Tests use synthetic bytes. Nothing is committed.

### Slice 13: `prepareFirmwareImage` patch target

Widen the target union, and implement the patch target:

```ts
export type FirmwareTarget =
  | { readonly kind: 'stock' }
  | { readonly kind: 'patch'; readonly patch: LoadedFirmwarePatch };
```

For `kind: 'patch'`:

1. `description.stock` must equal the descriptor's pinned members, by role (sha256 and size), or
   `patch-wrong-stock` ("This patch was made for different stock firmware"). This is the pinned check; apply only
   checks the stock it is handed.
2. `applyFirmwarePatch(stock.package, parsed)`.
3. Recompute every role's hash, and assert equality with `description.result`, or `patch-result-mismatch`.
4. Set:
   - `provenance = patch.provenance`;
   - `releaseTag = patch.release?.tag`;
   - `patchVersion = description.version`;
   - `patchSha256 = patch.sha256`;
   - `versionStamp = readFirmwarePatchVersionStamp(...)`;
   - `verifyHint = patch.release?.verifyHint ?? 'Check the radio boots and shows the expected version.'`.
