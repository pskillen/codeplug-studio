## Series rules (apply to every change in this phase)

- **Read `AGENTS.md` and `DESIGN.md`** before the first edit. From phase 2 on, read DESIGN.md's "Firmware flashing"
  section, and `.claude/rules/firmware-flashing.md` if present.
- **No vendor firmware, ever, in any committed path.** That means no stock `.bin`, `.CDD`, `.CDI` or `.spi`, no
  vendor zip, and no slice of one: not in `src/`, test fixtures, docs, scripts or the planning branch. Tests build
  **synthetic** images in memory, and compute hashes on the fly. Studio's own release patch files are allowed, and
  only phase 7 adds them.
- **Hard interlocks are code.** No setting, flag, env value, query parameter or patch field may disable one.
- **Layers:**
  - `src/core/` has no React, DOM, `@app` or `@integrations` imports;
  - `src/integrations/` has no React and no `@app` imports;

    USB IDs, model IDs, entry steps or verify hints. Those come from descriptors.
- **Docs ship in the same PR** as the behaviour they describe.
- **Never touch hardware**, and never ask anyone to except through the "Hardware gate" section, which the
  orchestrator handles. Do not start the next phase.

## Context

Firmware releases reach Studio **by hand**. A maintainer copies a release's `.patch.json` byte for byte from the
firmware project's GitHub release, copies its release notes into Studio, and adds an index row. This phase adds:

- the first two **bundled releases**: DM-32UV `1.0.0` and AT-D890UV `1.0.0`, both finals. The owner supplied the
  files, and they're already verified;
- the **repo hygiene** that keeps those bytes exact: `.prettierignore` and `.gitattributes`;
- the **release catalog**: types, the index, and a `FirmwareReleaseSource` for bundled releases and for a
  user-supplied patch file;
- `prepareFirmwareImage`'s **patch target**;
- a **catalog unit test** that re-verifies every bundled patch, plus a local-only stock check that is skipped in CI;
- a **maintainer doc**: how to add a release.

No UI in this phase. Phase 8 wires the catalog into the wizard.

## Slice 2: catalog types, index and sources

`src/core/firmware/releases/types.ts`:

```ts
export type FirmwareReleaseChannel = 'final' | 'rc';
export interface BundledFirmwareRelease {
  readonly radioId: FirmwareRadioId;
  readonly tag: string;                 // firmware-repo tag, no 'v' ('1.0.0', '1.0.0-rc.3')
  readonly channel: FirmwareReleaseChannel;
  readonly patchFile: string;           // published asset name, e.g. 'dm32-fw-1.0.0.patch.json'
  readonly patchSha256: string;         // from the release's SHA256SUMS
  readonly stockVersion: string;        // must equal the radio's StockFirmwareDescriptor.version
  readonly publishedOn: string;         // ISO date
  readonly summary: string;             // one or two sentences for the release list
  readonly radioStatus: 'radio-checked' | 'emulator-checked' | 'not-checked';
  readonly verifyHint: string;          // how the operator confirms this release is running
  /** Result hashes by role, duplicated from the patch so stock resolution can spot already-patched input. */
  readonly resultSha256: Readonly<Record<string, string>>;
  readonly loadBytes: () => Promise<Uint8Array>;  // exact published bytes
  readonly loadNotes: () => Promise<string>;      // Studio copy of the release notes (markdown text)
}
export interface FirmwareReleaseSummary {
  readonly radioId: FirmwareRadioId;
  readonly key: string;                 // tag for bundled; 'user:<sha256>' for a user file
  readonly label: string;               // e.g. '1.0.0'
  readonly channel: FirmwareReleaseChannel | 'unknown';
  readonly provenance: 'bundled' | 'unreviewed';
  readonly release?: BundledFirmwareRelease;
}
export interface LoadedFirmwarePatch {
  readonly bytes: Uint8Array;
  readonly sha256: string;
  readonly parsed: ParsedFirmwarePatch;
  readonly provenance: 'bundled' | 'unreviewed';
  readonly release?: BundledFirmwareRelease; // set when bundled, or a user file matching a bundled one
}
export interface FirmwareReleaseSource {
  readonly kind: 'bundled' | 'user-file' | 'remote';
  listReleases(radioId: FirmwareRadioId, opts: { includeRc: boolean }): Promise<readonly FirmwareReleaseSummary[]>;
  loadPatch(radioId: FirmwareRadioId, key: string): Promise<LoadedFirmwarePatch>;
}
```

`src/core/firmware/releases/bundledSource.ts`: `export const bundledFirmwareReleaseSource: FirmwareReleaseSource`.

- `listReleases`: this radio's rows, finals only unless `includeRc`, sorted newest first by `publishedOn` then tag.
- `loadPatch(radioId, tag)`:
  - `loadBytes()`, then `sha256Hex`, which **must** equal `patchSha256`, or throw
    `FirmwareError('patch-unreadable', 'Bundled patch bytes do not match the published hash')`;
  - then `parseFirmwarePatch`;
  - return provenance `bundled` with `release`.

`src/core/firmware/releases/userPatchSource.ts`:
`export function createUserPatchSource(file: NamedBytes): FirmwareReleaseSource`. It lists exactly one entry, with
key `user:<sha256>`.

- If the sha256 equals a bundled `patchSha256` **for the same radio**, return that release with provenance
  `bundled`.
- Otherwise `parseFirmwarePatch`. `description.name` must be in the radio's `descriptor.patchNames`, or
  `FirmwareError('patch-wrong-radio')`. Return provenance `unreviewed`, label `description.version`.

## Slice 3: `prepareFirmwareImage` patch target

Widen the target union, and implement the patch target:

```ts
export type FirmwareTarget =
  | { readonly kind: 'stock' }
  | { readonly kind: 'patch'; readonly patch: LoadedFirmwarePatch };
```

For `kind: 'patch'`:

1. `description.stock` must equal the descriptor's pinned members, by role (sha256 and size), or
   `patch-wrong-stock` ("This patch was made for different stock firmware"). This is the pinned check; apply only
   checks the stock it is handed.
2. `applyFirmwarePatch(stock.package, parsed)`.
3. Recompute every role's hash, and assert equality with `description.result`, or `patch-result-mismatch`.
4. Set:
   - `provenance = patch.provenance`;
   - `releaseTag = patch.release?.tag`;
   - `patchVersion = description.version`;
   - `patchSha256 = patch.sha256`;
   - `versionStamp = readFirmwarePatchVersionStamp(...)`;
   - `verifyHint = patch.release?.verifyHint ?? 'Check the radio boots and shows the expected version.'`.

Tests (synthetic, using phase 4's `__fixtures__/makeSyntheticPatch.ts` and synthetic descriptors):

- patch target success: the provenance carries through, the stamp is read for DM-32 synthetic patches;
- a stock mismatch against the pins → `patch-wrong-stock`, before apply;
- the user source:
  - a file byte-identical to a (synthetic) bundled row → `bundled` with `release` set;
  - a different valid patch → `unreviewed`;
  - the other radio's patch name → `patch-wrong-radio`;
- the bundled source: a row whose `loadBytes` returns altered bytes → the hash refusal. Test with an injected row
  list (make the source factory take rows: `createBundledFirmwareReleaseSource(rows)`, and export the default);
- `includeRc` filtering and sort order (synthetic rows).

## Slice 4: catalog test and local stock check

`src/core/firmware/releases/catalog.test.ts` reads the raw files with `node:fs` (path from `import.meta.url`). For
every row in `BUNDLED_FIRMWARE_RELEASES`:

- the patch file exists, and `sha256(file bytes) === patchSha256`;
- `loadBytes()` returns the same bytes (proves `?raw` is byte-exact);
- `parseFirmwarePatch` succeeds, `description.name` is in the radio's `patchNames`, and `description.version === tag`;
- every `description.stock` role and hash equals the radio's `StockFirmwareDescriptor.members`, and
  `stockVersion === descriptor.version`;
- `resultSha256` equals `description.result` hashes by role;
- **DM-32UV:** `result.bin.size === DM32UV_FIRMWARE_IMAGE_SIZE`, so a bundled release can never be refused by the
  updater's length interlock;
- **D890:** every hook has equal `original` and `hex` lengths and lies within the stock `.CDD` size; `append.offset`
  equals the stock `.CDD` size. Read the parsed patch's structure; the format module's types are available;
- the notes file exists and is non-empty;
- at least one `final` per radio; no duplicate `(radioId, tag)`; a `-rc.N` tag ⇔ `channel: 'rc'`.
