## Context

The `/firmware` wizard currently flashes **stock only** (phase 6). The release catalog exists in core (phase 7),
with DM-32UV `1.0.0` and AT-D890UV `1.0.0` bundled. This phase lets the operator:

- pick a **bundled release**. Finals are shown; a "Show release candidates" toggle adds RCs, labelled pre-release.
  Each row shows its summary, its radio-check status and **its release notes (the Studio copy)**;
- or, under **Advanced**, **use a patch file from disk**. That requires accepting a risk statement, unless the file is
  byte-identical to a bundled release, in which case it's treated as that release.

The flash then uses `prepareFirmwareImage` with a patch target. The summary records provenance, and the Done step
shows the release's verify hint.

On DM-32UV `1.0.0`, Device Info still reads Baofeng's `DM32.01.L01.048`. The verify hint says to check that Scan on a
channel with no scan list starts a zone scan.

The AT-D890UV isn't registered yet (phase 10), so only the DM-32UV appears. The code must stay radio-generic.

**Vendor firmware rule:** user files stay in memory. Nothing is committed except code, tests and docs. Tests use
synthetic patches.

## Slice 3: wizard changes

**Firmware step:**

- For the chosen radio, `listBundledReleases(radioId, includeRc)`. A `ToggleSwitch` "Show release candidates"
  defaults off. RC rows carry a `Pill` "Pre-release, for testing".
- Each row: tag, date, `summary`, a radio-status pill (`radio-checked` → "Checked on a radio"; `emulator-checked` →
  "Emulator-checked only"; `not-checked` → "Not checked"), and a **"Release notes"** disclosure that lazy-loads
  `release.loadNotes()` into `ReleaseNotes`.
- The **"Stock firmware (v…)"** entry stays, always present (recovery), with the phase 6 "not yet hardware-proven"
  label when `stockFlashHardwareProven` is false.
- An **Advanced** disclosure, **"Use a patch file from disk"**:
  - `FileDropzone accept=".json"`, then `filesToNamedBytes`, then `loadChosenPatch(radioId, {kind:'user-patch', file})`.
  - If the result is `bundled`: show "This is release <tag> (bundled)", and select it like the bundled row, with no
    warning.
  - Otherwise show the **risk statement**, verbatim:

    > This patch has not been reviewed or bundled by Codeplug Studio. Studio checks that it matches your stock
    > firmware and that the result matches the hash inside the patch, but it **cannot tell whether the firmware it
    > produces is safe**. A bad patch can leave your radio unable to boot. Only use patch files you built yourself or
    > got from the firmware project's own release page.

    Plus a `Checkbox` "I understand", which **must** be ticked to continue. Show the patch version and a short
    sha256.
  - A `FirmwareError` shows its message, for example "This patch is for the AT-D890UV".

**Prepare step:** use `prepareFlash` with the choice. Show provenance ("Bundled release 1.0.0" / "Unreviewed
user-supplied patch"), the result hashes and the version stamp. A `patch-wrong-stock` or `patch-result-mismatch`
stops here with its message: "Nothing was sent to the radio."

**Done step:** "Check: <image.verifyHint>". For bundled releases this comes from the release row. Show the summary
(phase 6 already provides copy and download).

**Reducer:** add `choice` (`FirmwareChoice`), `loadedPatch`, `includeRc` and `riskAccepted`.

- Changing the radio clears the choice, the loaded patch, the stock and the acceptance.
- Changing the choice clears the prepared image and the acceptance, but keeps the verified stock.
- The flow can't continue while an `unreviewed` patch has `riskAccepted === false`.

**Tests** (extend `firmwareWizardState.test.ts` and `FirmwareFlasherPage.test.tsx`, with mocked services):

- the release list renders finals; the RC toggle adds an RC row (mock a synthetic RC);
- release notes expand;
- a bundled-match user file shows "This is release 1.0.0 (bundled)" and no risk statement;
- an unreviewed file shows the risk statement, and continue is disabled until "I understand" is ticked;
- a wrong-radio patch shows its error;
- Done shows the release verify hint.
