### The protocol (spec, from `d890update.py`)

```python
ENTRY = 278; BLOCK = 32; FRAME = 40
FW_BASE = 0x0800C000; FW_LIMIT = 0x081E4000; ACTIVATION = (0x0800A000, 0x0800C000)
FIRST_BLOCK_TIMEOUT = 30.0  # the first frame's reply may follow a flash erase; later frames: 2.0 s

class Package:  # (spi, cdi, cdd)
    if len(spi) not in (50, 51, 14) or u32(spi, 0) != 0x20: error   # 14 = resource mode: Studio REFUSES it
    count = u16(spi, 4); total = u32(spi, 6)
    len(cdi) must == ENTRY * count; total must == len(cdd)
    entry i = cdi[i*278:(i+1)*278]: name = e[:0x100] up to NUL; addr,len,off,flag = u32x4 LE at 0x100; off+len <= len(cdd)
    model = spi[0x0E:0x14] ascii strip   ('D890UV');   version = spi[0x16:0x1A] ascii strip  ('V100')
    blocks(): for e in entries: for k in range(0, e.len, 32): (e.addr + k, cdd[e.off+k : e.off+min(k+32, e.len)] zero-padded to 32)
def frame(addr, data32): body = u32le(addr) + data32; return 01 + body + u16le(sum(body) & 0xFFFF) + 06     # 40 bytes
def addr_problem(addr):  # firmware mode
    end = addr + 32
    if addr < FW_BASE or end > FW_LIMIT: "outside the firmware window"
    if addr < ACTIVATION[1] and end > ACTIVATION[0]: "touches the activation page"
def check_outgoing(data):  # the single gate for everything sent (firmware mode)
    if data in (b"UPDATE", b"\x02", b"\x18"): ok
    elif len(data) == 40 and data[0] == 1 and data[-1] == 6: checksum must match; addr_problem must be None
    else: refuse
def check_package(pkg):
    every block: addr_problem None; first entry addr == FW_BASE
    sp, reset = u32le(cdd,0), u32le(cdd,4); end = FW_BASE + entries[0].len
    require 0x20000000 <= sp <= 0x20040000 and FW_BASE <= reset < end and reset odd
handshake():
    drain input; send "UPDATE"; read 1 byte at a time until the last byte is 06 (max 16 bytes) within 2 s, else error
    send 02; ident = read 16 bytes; require ident[0] == 'I' and ident[15] == 06
    model = ident[1:8] up to NUL; version = ident[9:13]; require (model, version) == (pkg.model, pkg.version) ("Model Error")
send_block(addr, data, timeout):
    f = frame(addr, data)
    for attempt in (1, 2): send f; r = read 1 byte (timeout); if r == 06: return; drain input
    raise "no 06 after 2 attempts"            # NAK 15, timeout, or any wrong byte → one resend, then abort
run(): check_package; handshake; for each block: send_block(timeout = 30 s for the first frame, else 2 s); send 18; end reply
end reply: read 1 byte: 06 → ok; port closed (OSError ENXIO/EIO/ENODEV) → ok "port closed by the radio"; else error
```

**Studio-specific decisions (from the design; follow them):**

- **Band-byte interlock (stricter than the Python):** require `ident[8] === 0x00` (bootloader). `0x03` is app mode.
  Refuse otherwise, before any data frame.
- **End handling:**
  - `06` → `end: 'acknowledged'`;
  - `RadioClosedError` **after** `18` → `'port-closed-by-radio'` (success);
  - `RadioTimeoutError` after `18` → `'no-reply'`. Every frame was ACKed, so this is **not** an error; the UI says
    "check Device Info";
  - any other byte → error;
  - `RadioClosedError` **before** `18` → error (`radioTouched: true` once any data frame was sent).
- **`radioTouched`** becomes true immediately before the **first data frame** is sent. `UPDATE` plus ident erases
  nothing (hardware stage S2: the radio booted normally afterwards).
- The ident model is `D890UV` in the bootloader. The app-mode ident `ID890UV` handled by `connection.ts` is a
  different dialect; don't reuse `parseAtD890Ident`.

  - `ENTRY = 278`, `BLOCK = 32`, `FRAME = 40`;
  - timeouts in ms: `HANDSHAKE 2000`, `FIRST_FRAME 30_000`, `FRAME 2000`, `END 2000`;
  - the `UPDATE`, `IDENT_REQ = 0x02`, `END = 0x18`, `ACK = 0x06` and `NAK = 0x15` bytes;
  - the SRAM bounds `0x20000000..0x20040000`.
- `package.ts`:
  - `parseD890FirmwarePackage(files: { cdd; cdi; spi }): D890FirmwarePackage`, where `D890FirmwarePackage` is
    `{ model, version, entries: {name, addr, len, off, flag}[], cdd }`;

  - `d890BlockCount(pkg)`, which is `Σ ceil(len / 32)`.
  - Structural errors throw `RadioInterlockError` (an unsafe package must never send). A 14-byte `.spi` (resource
    mode) is refused with "ICON pack / resource mode is not supported".
- `frames.ts`: `makeD890UpdateFrame(addr, data32): Uint8Array` (40 bytes; sum16 LE over bytes `[1, 37)`).
- `interlocks.ts`:
  - `d890AddrProblem(addr): string | undefined`;
  - `checkD890Package(pkg)`: every block address is safe, entry 0 loads at `FW_BASE`, and the vector table is sane;
  - `checkD890FirmwareImage(image: PreparedFirmwareImage): D890FirmwarePackage`:
    - `radioId === 'anytone-at-d890uv'`;
    - the roles are exactly `cdd`, `cdi` and `spi`;
    - then parse and `checkD890Package`;
  - `checkD890Outgoing(frame: Uint8Array)`: the port of `check_outgoing`, firmware mode only. It throws
    `RadioInterlockError`.
- Tests (`package.test.ts`, `interlocks.test.ts`), with a helper `synthD890Package(addr = 0x0800C000, length = 100)`
  ported from `test_d890update.py` `synth()`:
  - `.CDD` bytes `(i*7) & 0xFF`, with `cdd[0..8) = u32le(0x20025FA0) + u32le(0x0800C041)`;
  - the `.CDI` entry is the name padded with spaces to `0x100`, then `addr`, `len`, `0`, `0x10000` as u32 LE, plus 6
    zero bytes (278 in total);
  - the `.spi` is `u32 0x20, u16 1, u32 len`, 4 zero bytes, `"D890UV  V100"`, `"D890UV".ljust(16)`, `"V100"`, padded

  Cases:
  - **frame layout**: `makeD890UpdateFrame(0x0800C020, 0..31)` has byte 0 = 1, bytes `[1..5)` = `20 C0 00 08`, the

    - allowed: `0x0800C000` and `0x081E3FE0`;
  - **package checks**: synth passes; addr `0x08008000` refused; addr `0x0800A000` refused; `0x081E3F80` with length
    `0x100` refused; an all-zero `.CDD` (no vector table) refused; a 14-byte `.spi` refused; a `.CDI` length mismatch
    and a total mismatch refused.

### Slice 2: mock bootloader

`src/integrations/radio-io/radios/at-d890uv/__fixtures__/d890BootloaderMock.ts` is a `BytePipe` port of
`MockBootloader`, firmware mode only:

- `model = 'D890UV'`, `version = 'V100'`, `bandByte = 0x00` (configurable, to test the interlock);
- `UPDATE` → `06`;
- `02` → `I` + model padded with NUL to 7 + band + version + `00 00` + `06` (16 bytes);
- `18` → `ended = true`. With `dropAfterEnd`, the next `readExact` throws `RadioClosedError`; otherwise the reply is
  `06`;
- 40-byte frame: a bad checksum or trailer gives `15` and is logged as `badframe`. Otherwise store `mem[addr]` and
  reply `06`;
- faults: `nakAt`, `corruptReplyAt` (reply `07`) and `silentAt` (no reply), each a set of 1-based frame numbers that
  fires once;
- `readExact(n)` returns the buffered bytes, or throws `RadioTimeoutError` at once when fewer than `n` are available;
- `log[]` records `UPDATE` / `ident` / `data 0x…` / `end` / `unknown …`;
- `image(base, length)` returns memory filled with `0xFF`, overlaid with the stored blocks.

### Slice 3: updater, descriptor and registration

`updater.ts`: `createD890FirmwareUpdater(): FirmwareUpdater` (`radioId: 'anytone-at-d890uv'`, `link: AT_D890_FW_LINK`).

- `checkImage(image)` calls `checkD890FirmwareImage`.
- **`identify(pipe)`:**
  - bind the pipe, with a guarded send using `checkD890Outgoing`;
  - `await pipe.flush?.()`;
  - send `UPDATE`;
  - read 1 byte at a time until the last byte is `06`, at most 16 bytes, within 2 s overall;
  - send `02` and read 16 bytes;
  - validate `I…06`;
  - parse the model (`[1..8)`, NUL-trimmed), the band (`[8]`) and the version (`[9..13)`);
  - return `{ radioId, model, version, raw }`.

  Don't check against an image here; `flash` does that.
- **`flash(image, opts)`:**
  1. If `identify` hasn't completed on this instance, throw.
  2. `pkg = checkD890FirmwareImage(image)`.
  3. Require `ident.model === pkg.model && ident.version === pkg.version` ("Model Error. Radio: … package: …"), and
     `raw[8] === 0x00`. Both throw `RadioInterlockError`, before any data frame.
  4. Precompute nothing large. Iterate `d890Blocks(pkg)`; there are 52k frames, so build each frame lazily.
  5. For each block:
     - `throwIfAborted(signal)`;
     - set `radioTouched = true` before the first;
     - send the frame through the guard and read 1 byte, with a timeout of 30 s for the first frame and 2 s after;
     - on `06`, continue;
     - on `15`, a wrong byte, or a timeout: `pipe.flush()`, then resend **once**. A second failure aborts.
     - `RadioClosedError` mid-transfer aborts.
  6. Send `18`, then do the end handling above.
  7. Report progress on phase changes and every 256 frames, as `Transfer n/N`. Keep the per-frame overhead minimal:
     no array growth, no per-frame closures if you can avoid them.
  8. Wrap every failure in `FirmwareFlashError` with `radioTouched` and `position` (`frame n/N @ 0x0800C020`). Never
     send anything after a failure; in particular, never send `18` after a failed block.
  9. Return `{ framesSent, dataFrames: N, elapsedMs, end }`.

## Part B: AT-D890UV in the wizard (#1365)

### Background

The AT-D890UV updater is registered (earlier in this part), so the radio-generic wizard already lists it on pre-prod. The
AT-D890UV still differs from the DM-32UV in ways the wizard must handle:

- **About 52,515 frames** for release `1.0.0`, against 1,688 for the DM-32UV. Progress updates must be throttled,
  or React re-renders tens of thousands of times.
- **How the session ends.** After the end byte, the bootloader usually reboots at once and its USB port disappears:
  `end: 'port-closed-by-radio'`, which is success. It may instead reply `06` (`'acknowledged'`), or say nothing
  (`'no-reply'`). With `no-reply`, every frame was ACKed, so it is **not** a failure, but the operator should check
  Device Info.
- **Same USB ID in both modes.** The radio enumerates the same in normal and update mode. The descriptor's
  `bootloaderEntry.warnings` already says so; make sure warnings are shown prominently next to the
  "Connect and flash" button, not only in the update-mode step.

All of this stays radio-generic: no radio literals in `src/app/`. The code branches on `FirmwareFlashEnd` values and
descriptor fields, never on `radioId`.

The AT-D890UV stays **prod-hidden** (`prodFlashDisabled: true`) until this part's final commit.

### Slice 6: progress throttling and phase mapping

- In the page's progress handler, coalesce updates. Store the latest `FirmwareFlashProgress` in a ref, and flush it
  to state at most every ~100 ms (or per animation frame). Always flush immediately on a `phase` change and on
  `radioTouched` flipping to true.
- Map phases generically. When the updater never reports `erase` (the D890), render the ProgressModal steps from the
  phases actually seen, or mark Erase as "skipped / part of transfer". Don't key this on `radioId`.
- While the first data frame waits (up to 30 s), show "Waiting for the radio (it may be erasing)…". Derive it from
  `phase === 'transfer' && cur` at its first transfer value.
- Tests: a burst of 10,000 progress events causes fewer than ~100 state updates (fake timers). A phase change
  flushes immediately.
