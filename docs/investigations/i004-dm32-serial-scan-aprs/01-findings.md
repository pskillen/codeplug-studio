## Scan lists (serial)

| #   | Finding                                                                                                                                                                                                                                                                                                                                     | Evidence                                                   |

| S1  | NeonPlug and Studio use the same 57-byte entry geometry: count at byte `0`, entry `N` at `(57×N)−56`, members as u16 LE channel numbers at `+0x1A`, designated TX at `+0x11` stored as `ch−2` when `ch≥2`.                                                                                                                                  | `S/2026-08-15-neonplug`; `S/2026-08-15-studio-scan`        |
| S2  | **Unused-slot fill differs.** NeonPlug `writeAllData` `0xFF`-fills the concatenated scan-list bank, then writes entries and count. Studio `encodeScanListsIntoDm32Image` `0x00`-fills the bank (and tests assert shrink leftover names become `0x00`).                                                                                      | `S/2026-08-15-neonplug`; `S/2026-08-15-studio-scan`        |
| S3  | Firmware treats `0x00` names as occupied empty-named lists. Both dumps: named lists then slots through 32 are `<00-empty>` (zero `0xFF` vacant). Count byte matches named count. Matches NeonPlug `0xFF` fill vs Studio `0x00` fill.                                                                                                        | `D/2026-08-15-before`; `D/2026-08-15-after`; S2            |
| S4  | Studio serial projection sets `scanListId` + `scanAdd` on **carriers only**. Shared / ordinary members stay `scanListId` undefined → encode as `0` (none). NeonPlug `deriveNeonplugZoneDerivedScanLists` also stamps **member** channel ids (first zone wins). ## APRS upload ID

| #   | Finding                                                                                                                                                                                                                                                                                                                 | Evidence                                            |
| --- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------- |
| A1  | Studio and NeonPlug both encode upload ID at settings `0x332–0x334` as **24-bit big-endian**; call type is `0x331` bit 0 (`0`=private, `1`=group). Same clamp `16776415`.                                                                                                                                               | `S/2026-08-15-studio-aprs`; `S/2026-08-15-neonplug` |
| A2  | **Retracted hex:** an earlier source-read used `234999 = 0x039477`. That arithmetic was wrong. See A6.                                                                                                                                                                                                                  | `D/2026-08-15-after` (kills `S/2026-08-15-ids`)     |
| A3  | Serial APRS DTO comes from `buildNeonplugAprsRadioSettingsPatch`: upload ID = first **contributing** slot’s `targetDmrId` (`channelRef` **or** `targetDmrId` **or** `timeslot` set). Empty-looking slot 1 with a leftover ID would win over later slots that hold `234999`.                                             | `S/2026-08-15-studio-aprs`                          |
| A4  | If `assembled.aprsConfiguration` is null, `organisation.aprs` is null and `encodeAprsIntoDm32Image` is a no-op — donor `0x04` bytes stay. `dm32WriteRole` labels the whole `0x04` block **kept**; that is verify/UI grouping. Upload still sends every cached sparse block, including settings, from the encoded image. | `S/2026-08-15-studio-aprs`; `S/2026-08-15-upload`   |
| A5  | Before and after today’s Write, `0x332–0x334` are **`03 95 f7`** (unchanged). Report-channel numbers _did_ change (before `[0,44,28,81,60,…]`, after `[0,30,21,64,43,…]`), so the APRS slice **was** patched — the ID bytes already were BE `234999`.                                                                   | `D/2026-08-15-before`; `D/2026-08-15-after`         |
| A6  | `234999 = 0x0395F7`. Stored BE as `03 95 f7`. 24-bit **LE** of those bytes is `0xF79503 = 16225539`. Radio UI matches LE. NeonPlug `encodeRadioSettings` writes the same BE as Studio.                                                                                                                                  | `D/2026-08-15-after`; `S/2026-08-15-neonplug`       |
