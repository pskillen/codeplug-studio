## Closed conclusion (2026-08-13)

| #   | Finding                                                                                                                                                                                              | Evidence                                                                                                                                        |
| --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| F1  | The brick was encode-onto-virgin-`0xff`. Codecs still “leave what’s already in the image”; sparse RMW only preserves bytes **outside** the modelled overlay. A radio-shaped stash had hidden that.   | C2; C3; `D/21-37`; `O/hw-pass-p2`                                                                                                               |
| F2  | Overlaying on this PROGRAM session’s download cache (`encodeAtD890WriteImageFromDownloadCache`), with no `0xff` fallback, is a writer this firmware boots.                                           | `O/hw-pass-p2`; [PR #1118](https://github.com/pskillen/codeplug-studio/pull/1118) `1920341f`                                                    |
| F3  | Zero **visible** zones (W6) is a firmware reject and was present on the first brick (`ZoneHide` all-`0xff`). Clearing ZoneHide (#1125 / #1126) reached flash and was **not** enough.                 | W6; W7; E1; `O/1126-still-bricks`                                                                                                               |
| F4  | Occupancy-all-set / AES-`0xff` / ChannelSet tail `ff` were **symptoms** of the `0xff` prior, not independent product fixes.                                                                          | E1–E6; parked [#1129](https://github.com/pskillen/codeplug-studio/issues/1129)–[#1132](https://github.com/pskillen/codeplug-studio/issues/1132) |
| F5  | Dropping a hydration stash is not the same as encoding onto a blank map. The same W3 miss showed up on OpenGD77 as 0 dirty FLASH sectors (1701 stays in zone) until contact name mode reached Write. | `O/opengd77-zero-sectors`; [PR #1133](https://github.com/pskillen/codeplug-studio/pull/1133)                                                    |
