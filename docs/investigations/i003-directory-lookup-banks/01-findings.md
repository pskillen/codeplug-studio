## DM-32

| #   | Finding                                                                                                                                                                                                 | Evidence                                                                                                       |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| D1  | Library digital contacts encode to V-frame `0x0F` address book (92-byte records: name, ID, callsign, city, province, country, remark).                                                                  | `S/2026-08-15-code`; [contacts-zones-lists.md](../../reference/radios/baofeng/dm-32uv/contacts-zones-lists.md) |
| D4  | Firmware contact-bank max is V-frame `0x10` or L01 fallback **50 000 / 150 000**. CPS / `DM32UV_LIMITS.CONTACTS_MAX` **250** is the profile/export ceiling Studio uses for library contacts.            | `S/2026-08-15-code`                                                                                            |
| D5  | Clone download **skips** V-frame `0x0F` and **includes** `0x67`. Backup/Restore cannot show address-book occupancy; Write now allocates `0x0F` blocks without a Read of that bank.                      | `S/2026-08-15-code`; D7                                                                                        |
| D6  | **Inference:** there is no named OpenGD77-style User Database on the DM-32 serial map. The lookup-shaped store is the large `0x0F` book. Incoming-call display using `0x0F` is not hardware-proven.     | inference; no fourth bank named in-repo                                                                        |
| D7  | Directory Write/CPS **no longer** merge into `0x67` / `DMR-ID.csv`. Operator radio IDs are channel `dmrId` only. Directory Web Serial targets `0x0F` (allocate-on-write; serial cap 11 264). CPS warns. | `S/2026-08-15-impl`; #1220                                                                                     |
| D8  | Shared `0x0F` bank: **Both** skips overlapping `digitalId` (library wins). RadioID-only **replaces** the book and keeps overlapping directory IDs. LCD still H4.                                        | `S/2026-08-15-impl`; P2                                                                                        |
| D9  | Operator radio IDs remain metadata `0x67` (250 × 16 bytes). Channel `0x2B` is a 0-based index into that bank (`0xFF` = none). Not a lookup store.                                                       | `S/2026-08-15-code`                                                                                            |
