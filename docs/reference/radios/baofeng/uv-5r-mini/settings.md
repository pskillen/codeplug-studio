# UV-5R Mini — settings and upload scope

High-level VFO / settings / ANI / PTT offsets and how NeonPlug vs CHIRP vs Studio upload differently.

**Hub:** [README.md](README.md) · **Regions:** [memory-layout.md](memory-layout.md) · **Calibration:** [calibration.md](calibration.md)

Cite: NeonPlug `settingsFormat.ts`, `protocol.ts`; CHIRP `UV5RMini` / `_mem_params`; Studio `writeStrategy: 'full-image'`.

## Packed-image layout (high half of first region + tail)

NeonPlug documents (CHIRP-aligned):

| Packed offset | Role                |
| ------------- | ------------------- |
| `0x8000`      | VFO A (32 bytes)    |
| `0x8020`      | VFO B (32 bytes)    |
| `0x8040`      | Settings (64 bytes) |
| `0x8080`      | ANI                 |
| `0x80A0`      | PTT ID              |
| `0x81E0`      | Upcode              |
| `0x8210`      | Downcode            |

CHIRP `_mem_params` places `ani=0x8080`, `pttid=0x80A0` on the same packed map. Modes / end-format seek around `0x8220`.

## Settings block (64 bytes @ packed `0x8040`)

NeonPlug parses squelch, save mode, VOX, backlight, dual watch, TOT, beep, voice, side tone, scan mode, PTT ID mode/delay, display types, BCL, autolock, alarm, roger, A/B, work modes, key lock, power-on display, and related indices from this block (`parseUv5rMiniSettings`). The firmware's own reading of every byte is below.

## Settings frame decode (radio `0x9000-0x903F`)

Read-only view on `/debug/uv5r-mini` (`debugRead/settingsFrame.ts`). Source: static trace of the v0.04 `app.bin` (radio repo PR #219, ledger F302-F309; v0.27 runs the same code relocated, same defaults). **45 bytes are named** (41 traced, 4 partly traced with the name inferred) and **19 have no reader** in either build. "No reader" means no reference in either build's refs, decompile or immediates; a computed pointer access is not ruled out. Studio shows these bytes and never writes them: Write keeps the frame from the Read (full-image retain). Nothing in the frame is sensitive.

**Confidence:** _traced_ (code address and meaning), _partly traced_ (traced use, inferred name, marked "inferred"), and **unused (no reader)** for bytes nothing reads. Storage: the log slot is 0x60 bytes, the 64 bytes then 30 zero bytes and a CRC-16/XMODEM at `0x5E` (LE); a bad CRC loads the defaults.

**CHIRP names differ from the firmware.** The second programmable key is read from `0x33` (CHIRP `unknown7`); CHIRP's `key2short` at `0x34` is never read (inferred statically; a bench check is open). `0x36` is the NOAA channel; `0x39` (CHIRP `hangup`) is the DTMF call hang time.

## VFO frame decode (radio `0x8000-0x803F`)

Two 32-byte records, A then B (`0x8000`, `0x8020`). Per record: **24 bytes named** (22 traced, 2 inferred: the RX tone) and **8 with no reader** (`0C`, `0D`, `0F`, `12`, `1C-1F`). Busy lockout in VFO mode is settings byte `0F`, not here. CHIRP has 6 offset digits and `sqmode` at `+0x1C`; the firmware writes 7 digits and SP-Mute at `+0x1B`. The power index at `10` is also the PA bias frame index ([calibration.md](calibration.md)). Tones are shown raw (the channel record's tone encoding, [channel-record.md](channel-record.md)).

## Upload behaviours (document all three)

| Behaviour             | NeonPlug                                                                  | CHIRP                                     | Studio Web Serial                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Full clone **read**   | All three `MEM_*` regions → packed `0x8240`                               | Same                                      | Same (`radio-clone` hydration)                                                                                                                                                  |
| Full clone **upload** | Not the default path                                                      | Writes **all** `MEM_STARTS` / `MEM_SIZES` | **Yes** — `writeStrategy: 'full-image'`                                                                                                                                         |
| Channel write         | After upload handshake, writes radio addrs `0 … 0x7CE0` only (`999 × 32`) | Full multi-region                         | Encodes the build's channels over the Read (an unchanged channel kept as read, any other encoded fresh; slots not in the build emptied); **all three** `MEM_*` regions uploaded |
| Settings write        | Read-modify-write one 64-byte block                                       | Part of full upload                       | Retained from Read via full-image upload (no separate settings RMW)                                                                                                             |

**Studio intentional path:** Prefer NeonPlug’s **outcome** (VFO / settings / ANI survive a channel Write) via **full-image upload of the hydrated retain**, not NeonPlug’s channel-span-only traffic. That also avoids NeonPlug’s settings-address debt (below). Channel-span-only upload is **out of scope** for the shipped adapter.

**Channel encode contract:** Write encodes the build's slots over the Read (an unchanged channel's record kept as read, any other encoded fresh) and empties the rest of the span. Orphan memories from a prior Read are not kept. See [channel-record.md — What Write keeps](channel-record.md#what-write-keeps).

## Packed `0x8040` vs radio address caveat

| Context                       | Address used                                                    |
| ----------------------------- | --------------------------------------------------------------- |
| Packed image parse            | Image offset `0x8040` (= radio **`0x9000`** via region map)     |
| NeonPlug `writeRadioSettings` | `readBlock` / `writeBlock` with addr **`0x8040`** (radio space) |

Those are **not** the same physical region under the `MEM_*` map. NeonPlug’s settings RMW address is **verify-on-hardware** debt. Studio does not use that path — full-image upload uses the correct packed ↔ radio map.
