# RT95 calibration debug capture

The debug capture reads 16-byte blocks at `0x3B00` through `0x3FB0` using the existing PROGRAM/END session. The resulting `0x4C0` bytes cover main-body EEPROM `0x3B00–0x3FBF`, relayed via the head, and are inspect-only. The clone programming image covers offsets `0x0000–0x329F`; `0x32A0–0x3AFF` is not captured. These representations do not establish a physical memory map. The signature at `0x3FF8–0x3FFF` is outside this capture. Old archives may have no calibration region.

The decoder follows a static MAIN V1.61 / head V1.41 trace; applicability to any individual radio is unknown and the decoding has not been validated on hardware. Stored production text is evidence of stored bytes, not running firmware or a modification. Captured zeros and FF are values; missing bytes are not. The 16-bit display assumes little-endian, supported by the traced ARM consumer; signedness and physical units remain unresolved. The decoder is the radio-repo decode research (F153-F161, static MAIN V1.61, head V1.41, CPS 2.01): every byte of `0x3B00–0x3FBF` belongs to one field, either with a meaning and a confidence (**traced** = read in code, **partly** = inferred or incomplete, noted per row) or **unused (no reader)**: nothing in MAIN, the head or the CPS reads it. Squelch and S-meter dB scales are inferred, not measured. The twelve test-channel slices are factory test-mode frequencies and offsets, not calibration steps. Raw hex stays available for every field. Stable reads and plausible values do not establish calibration health.

The head relays each block and can answer without a main-board reply, returning stale or zero bytes; captured bytes are what the head returned, not proof of EEPROM contents.

**Relay caveat (RT95 F157).** The head's `R` relay never checks that the main board answered. A timeout returns the _previous_ block under the new address, and a late reply can shift the next block; both carry a valid checksum. A debug capture can therefore hold a wrong block, so two captures taken back to back should be compared block by block, and a differing block is suspect. The capture itself still reads each block once; reading twice is an open owner decision.

The archive region contract is ID `rt95-calibration`, path `regions/rt95-calibration.bin`, start `0x3B00`, inspect-only, and at most `0x4C0` bytes. Opening refuses the region on a wrong model, address, role, path or excess length, and refuses that path under another ID. Manifest lengths must match their data.

Corrections shown as base + entry − reference are unmasked; firmware masks the result to 16 bits.

## Calibration and production record, `0x3B00–0x3FBF`

V row = `0x3F80` (19 bytes), U row = `0x3FA0` (20 bytes). Power code = channel byte 9 bits 3:2 (0 Low, 1 Mid, 2 High); width code = byte 10 bits 3:2 (0 = 12.5, 1 = 20, 2 = 25 kHz).
