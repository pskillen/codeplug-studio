# AT-D890UV — memory layout

Sparse multi‑MB codeplug regions for Anytone AT-D890UV (`D890_MAP`). There is **no** single contiguous clone image like RT95 (`0x32A0`) or UV-5R Mini (`0x8240`).

**Hub:** [README.md](README.md) · **Protocol:** [protocol.md](protocol.md) · **Records:** [channel-record.md](channel-record.md) · [talkgroup-record.md](talkgroup-record.md) · [receive-group-record.md](receive-group-record.md) · [zone-record.md](zone-record.md) · [scan-list-record.md](scan-list-record.md)

> Bases below are **D890 only**. D878UVII uses a different map (`D878II_MAP`) — see [#648](https://github.com/pskillen/codeplug-studio/issues/648). Do not mix.

Cite: anytone-cps `D890_MAP` + `Device` read/write helpers — facts only; do not paste GPL sources.

### Optional settings and alarm (preserved through erase on Write)

anytone-cps community RE — verify on hardware before relying on offsets. Studio **Reads** these regions on Connect/Read ([#760](https://github.com/pskillen/codeplug-studio/issues/760)) for Radio image forensics. They live in the session download cache only; Studio persists no settings bytes in the project or a hydration bag.

On **Write**, Studio encodes the modelled overlay onto `cacheToMemoryMap` of this PROGRAM session download cache ([#875](https://github.com/pskillen/codeplug-studio/issues/875)) — not a persisted hydration bag and not a virgin `0xff` `MemoryMap`. Sparse erase-unit RMW ([#768](https://github.com/pskillen/codeplug-studio/issues/768)) then **fresh-reads** each touched `0x40000` unit from the connected radio and re-stages non-`0xff` bytes unchanged **outside** that modelled overlay — including optional settings and alarm spans that share units with modelled banks. Studio does **not** re-derive those kept bytes from the library build. Identity is the radio on the cable this session ([#1276](https://github.com/pskillen/codeplug-studio/issues/1276)); Restore still refuses zip vs live serial mismatch.

The Radio image retain preview reads startup enable at main `+0xD6` bit 0, zones A/B at `+0xD7`/`+0xD8`, channels A/B at `+0xD9`/`+0xDA` (`0xFF` = none), UTF-16LE display lines of `0x20` bytes at `0x3500900` and `0x3500920`, and an 8-byte ASCII password at `0x3500940`.

**Settings patches** ([#1393](https://github.com/pskillen/codeplug-studio/issues/1393)). A codeplug Write leaves these bytes as the radio holds them, except for registered fields. A registered field (address, length, optional bit mask, targets) is applied as a **field patch on the fresh read** of unit `0x3500000`: `new = (fresh & ~mask) | (value & mask)`. Only addresses in the main record `+0x000`…`+0x15F` and the power-on block `+0x900`…`+0x947` may be registered, and these main-record offsets never may (radio state): `+0x15 +0x16 +0x1D…+0x21 +0x2C +0x4E +0x6F +0x70 +0xDB +0x13E…+0x140 +0x14E…+0x150`. LocalInfo, alarm, Zone A/B, the safe-skip address, the flash markers and (until the MM9PDY store is modelled) `+0x200` are refused for every target. The preserved-byte check allows a staged block outside the modelled set to differ from the fresh read only in the patched bits. After patching, main `0x200` and ext `0x60` must not read all `0xFF`. The registry holds the v1 fields listed in [optional-settings.md](optional-settings.md) (each with its encoding and the firmware's clamp); the MM9PDY TG step keys are the short-press P1 (`+0x13`) and P2 (`+0x14`) fields set to 14 and 13. Empty power-on lines are encoded as `0x20` NUL bytes, which is how the CPS and the radio itself store them.

**Language.** `+0x05` is the menu language (0 English, 1 Chinese, 2 Russian) and the firmware does not range-check it. LocalInfo `+0x04` **forces** the language at every settings load: 1 sets English, 2 sets Chinese; 0 leaves `+0x05` as stored. Studio writes LocalInfo only through the Danger zone's range change, never on Write. A Chinese menu after an erase therefore comes from `+0x05` (an erased `0xFF` is out of range) on a radio whose LocalInfo does not force a language, not from LocalInfo being replayed. Bag diffs on a faulted radio showed LocalInfo byte-identical between healthy and faulted reads ([#768](https://github.com/pskillen/codeplug-studio/issues/768)); the brick came from erase collateral in shared flash units.

**Backup / Restore** ([backup-restore.md](backup-restore.md)): optional settings and APRS **are** restorable from a zip; LocalInfo and alarm are inspect-only and are never taken from the archive.

#### Settings-unit map (`0x3500000`, both halves)

A settings **save** in stock V1.05 erases the other half of the unit and writes back only the extents below; anything else in the unit does not survive a save. A frequency-range change (LocalInfo `+0x03`) erases and re-defaults the whole unit on the next boot, so every extent here has a Studio backup span and is restorable. The firmware's settings save copies the old half, overlays the settings it holds in RAM and writes only these extents; the settings loaders read the same ones. Offsets are from `0x3500000`.

The range change also re-defaults VFO A/B, which are channel slots 4000/4001 at `0x1F81000` and `0x1F81080` (`0x80` each). On a real radio the channel bitmap normally has bits 4000/4001 set, so Read already pulls VFO A/B in with the channels (and older zips carry them inside `channel-data` regions). Studio also reads this `0x100` block explicitly, so it is captured when the bits are clear, and names it `vfo-channels`. Write never stages it, even when the bitmap bits are set.

The flash sector-management markers at `+0x3FBF0` / `+0x3FFF0` of each half (including the bytes at `+0x3FFFC..+0x3FFFF`) are radio-managed. They are deliberately uncovered: never backed up, never restored (see [flash-sectors.md](flash-sectors.md)).

#### What depends on the range code, and what a restore does with it

Firmware facts (the firmware repo's `docs/reference/firmware/codeplug-and-settings.md` sections 4.3, 4.5 and 4.10; findings F280 to F283):

- **Only 49 bytes of the settings unit depend on the code:** `+0x34` (the professional-mode flag: 1 by default for codes 0, 1, 8, 13 and 14, else 0; a non-zero value hides menu rows and blocks the VFO) and the three limit blocks `+0x58..+0x67` (VFO scan), `+0xC4..+0xD3` and `+0xF4..+0x103` (auto-repeater 1 and 2), filled from the code's receive table. For codes 0, 3, 7 and 10 the limits are identical (receive 400-480 / 136-174), so between those codes only `+0x34` differs, and only for code 0. Everything else the reset writes is constant. The language byte follows LocalInfo `+0x04`, not the range.
- **Outside the unit,** the default channels 1 to 8 and VFO A/B depend on the code (VFO A is 435.125, 446.125 and 430.125 MHz on codes 0, 7 and 10). A restore replaces them.
- **Replay is safe for the common codes.** Putting a code-3 backup back onto a radio on code 7 or 10, after the zones and channels, boots without a second reset and leaves the settings byte-identical to the radio before the change. A restored `+0x34` of 0 is legal on code 0 too: the radio keeps amateur-style menus.
- **Narrower codes.** At every load the firmware clamps the auto-repeater ranges (`+0xC4..` and `+0xF4..`) to the code's receive table, in RAM only; the flash keeps the restored bytes until the next settings save. The VFO-scan limits `+0x58..+0x67` are **not** clamped. What a scan does outside the receive table is unconfirmed. Studio does not rewrite either set on Restore.
- **The order rule.** The settings must not go back before the zones and channels, or in a session of their own while the codeplug is still the default: the boot then stops at "Program Error / Please Initialize The Radio!", because the restored zone A/B numbers point at empty zones. The same stop is expected for a build with fewer zones than those numbers, or without the start-up zone or channel (`+0xD6..+0xDA`); that is inferred, not tested. Whether a radio in that state still accepts a PC session is not known (RT-8). Studio therefore restores settings and codeplug together, after the restart ([backup-restore.md](backup-restore.md#after-a-range-change)).
- **The DTMF settings, 2-tone, 5-tone, alarm, auto-repeater offset list and the channel, zone and scan-list bitmaps live in unit `0x3480000`, which the reset does not touch.** Until a Write, the bitmaps there keep the old bits while the data units hold defaults. Studio's restore rewrites both, so this only matters to a radio left between the change and the Restore.
- **What Studio cannot put back:** calibration and LocalInfo (never written by Restore; the wizard checks them against the vital backup), and anything in a unit outside the backup's regions (MDC, one-touch, broadcast FM and the like are not wiped, so they are not lost).

Every stock-CPS Optional Settings input, with its address and whether a range change wipes it: [optional-settings-cps-coverage.md](optional-settings-cps-coverage.md).

### Usage-volatile bytes

Bytes the radio rewrites in normal use (changing channel or zone, tuning a VFO). A difference from a backup at these
bytes is expected after a Restore and is not a failed restore. The list is in code in
`src/integrations/radio-io/radios/at-d890uv/usageVolatileBytes.ts` (one place); the range change's final Check reads
it and reports them as "Changed since the restore, which is normal if you've used the radio", not as a failure.
Everything else that differs still fails the Check.

| Bytes                                                                 | What                                       |
| --------------------------------------------------------------------- | ------------------------------------------ |
| Optional settings (main) `+0xD7`, `+0xD8`                             | Zone A / zone B                            |
| Optional settings (main) `+0xD9`, `+0xDA`                             | Channel A / channel B                      |
| `ZoneAChannel` `0x3500400`, `ZoneBChannel` `0x3500600` (`0x200` each) | Current channel of each zone, u16 per zone |
| `VfoChannels` `0x1F81000` (`0x100`)                                   | VFO A/B, channel slots 4000/4001           |

Only offsets this page names are listed. `+0xD7..+0xDA` are named above as zone and channel A/B; the retain preview
reads them as the power-on selection, so they may be the startup choice rather than the live one. They are listed
anyway (a channel change on hardware showed a difference in Optional settings (main)); which of the four moved was
not recorded. `+0xD6` (startup enable) is a setting and is not volatile. Other radio-state offsets in the main record
(the list under Settings patches) are not included, because this page does not say they change in normal use.

Width and member-list indexing are verified: a sample with A-channels at member positions 0/1/2 reads `00 00 01 00 02 00` — u8 would give `00 01 02`, and a global-index scheme would give 18/9/1. **anytone-cps reads u16 (correct) but writes u8**, landing zone _n_'s value on byte _n_ instead of byte _2n_; its `0x10` read length also covers only 8 of the 16 zones. Zones 8–15 not yet sampled. |
| `AmZoneScan`     | `0x3884800` | **`0x4` per zone** (`0x40` total) | One bit per **member-list position**, LSB-first — 32 bits matching the 32 member slots. Verified: `ff 03`/`ff 01`/`1f 00` ↔ 10/9/5 all-scanned members. Bit index is a member position, _not_ a global channel index (zone 0's members are globals 18,16,15,17,7,23,22,19,21,20 yet its bits are 0–9). **anytone-cps reads this at a `0x10` stride and so reads outside the zone's slice for every zone after the first.**                                                                        |

#### `AmZoneData` record (`0x80`)

| Offset        | Len    | Field     | Notes                                                                                                                                                                                                                                                                                 |
| ------------- | ------ | --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `0x00`        | `0x22` | Zone name | UTF-16LE, max 16 chars, NUL-terminated — the terminator occupies `0x20`–`0x21` for a full-length name. `LocalInfo` @ `0x4f80000` (`0x100` bytes) is **Read** on download for Radio image retain preview and future band validation. **Bytes `+0x00..+0x0F` and what each does when changed.** The range change sends this whole 16-byte block with only `+0x03` altered, so every other byte must already be in a safe state:

| Offset            | If changed                                                                                                                                                                                        |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `+0x00` stun      | Non-zero stuns the radio. `END` with it set rewrites LocalInfo from stale RAM.                                                                                                                    |
| `+0x01` kill      | Non-zero kills the radio. Same `END` behaviour.                                                                                                                                                   |
| `+0x03` range     | The change itself. At the next boot the firmware compares it with the tune bank's copy at tune `+0x28` and, on a difference, wipes the codeplug and settings and writes the new range's defaults. |
| `+0x04` / `+0x05` | Market / language-lock pair. The `W` handler forces `+0x05`; if they differ at boot the radio runs full factory defaults.                                                                         |
| `+0x06..+0x0A`    | Unknown. Carried unchanged.                                                                                                                                                                       |
| `+0x0B..+0x0E`    | `890#` unlocks range code 14. Without it the loader maps 14 to 0.                                                                                                                                 |

The table above is the anytone-cps `ExpertOptions::decode` layout. The official CPS encoder we read does not write `+0x00`–`+0x0F`. That encoder has a 2-character field at `+0x24`.

`writeRole` labels LocalInfo **kept** — meaning **not re-derived from the library build** and **not serial-written** on Upload.

## Write upload contract (WATCH-08 allow-list + sparse erase-unit RMW)

Studio upload uses a **positive allow-list** (`AT_D890_WRITABLE_EXTENTS` in `writableExtents.ts`) to define what Studio may **change** from the library build. `listWriteChunks` still emits only modelled banks; **sparse erase-unit RMW** ([#768](https://github.com/pskillen/codeplug-studio/issues/768)) may **transmit** unchanged bytes inside touched `0x40000` units so co-resident optional settings and alarms survive flash erase. `atD890WriteMemory` uses a touched-unit transmit fence during upload; LocalInfo’s unit is never touched so LocalInfo is never serial-written.

**Hard deny (non-overridable):** `isAtD890HardDeniedWriteAddress` / `assertAtD890NotHardDenied` in `writableExtents.ts` refuse, for every generic write, the vital units `0x04F00000..0x04FFFFFF` (tune pair `0x04F00000` / `0x04F40000` and LocalInfo pair `0x04F80000` / `0x04FC0000`), the erase-unit bookkeeping blocks at `+0x3fbf0` / `+0x3fff0`, and the family safe-skip address `0x2fa0010`. The check runs first in `isAtD890TransmitAddress` (before the touched-unit shortcut) and in `atD890WriteMemory` (the only `W` sender) for the start address, every 16-byte block and the last byte, before the caller's `transmitGuard` and before any frame is sent. A caller's `transmitGuard` can only narrow the fence, never widen it past the hard deny. No flag re-enables it. No LocalInfo writer exists today. The only one planned is the Danger zone frequency-range change ([#1369](https://github.com/pskillen/codeplug-studio/issues/1369), not yet merged): a one-shot, single-purpose sender that will build its own frames. It must opt in to the program-session latch (`noteAtD890WriteFrame`, `assertAtD890ReadAllowed`, `atD890ExitProgram`, [protocol.md](protocol.md#session-rule-no-r-after-the-first-w)) and ask whether a range change may run while units are pending ([#1424](https://github.com/pskillen/codeplug-studio/issues/1424)); `writeFrameCallers.test.ts` fails otherwise.

**Encode prior:** `encodeAtD890ProjectionOntoImage` runs on `cacheToMemoryMap(session download cache)` from this PROGRAM `download()`. Empty cache refuses Write (no `0xff` fallback). Occupied `ZoneHide` bits are cleared unless hide is modelled; zero visible zones are refused ([#1125](https://github.com/pskillen/codeplug-studio/issues/1125)). Channel `0x80` bodies overlay modelled fields and safety defaults from the projection ([channel-record.md](channel-record.md)). When the downloaded slot still holds a record, Write also copies the preserve list from that record; a vacant slot stays 0 ([#1302](https://github.com/pskillen/codeplug-studio/issues/1302), narrowing [#1273](https://github.com/pskillen/codeplug-studio/issues/1273)). The image prior still covers other regions and ChannelSet bits ≥ 4000.

**Sparse RMW flow (upload):** compute touched erase units from modelled write addresses → fresh-read each unit from the connected radio → overlay modelled chunks → stage only non-`0xff` 16-byte blocks **excluding** per-unit flash sector-management markers at `+0x3fbf0` / `+0x3fff0` → transmit filtered chunks → `END` (bare `0x06` ACK; no further wire command). There is **no** separate commit command — see [flash-sectors.md](flash-sectors.md). RMW preserves co-residents **outside** the modelled overlay; it is not a substitute for the in-session encode prior.

**ChannelData** is modelled as **32 per-block low halves** (`0x40000` each, `0x80000` pitch). Studio refuses upper-half addresses ([#791](https://github.com/pskillen/codeplug-studio/issues/791)). That refusal is the write fence, separate from how firmware selects the live half.

**Pre-Write sentinel plausibility:** before any write frames, Studio Reads six never-write spans and **refuses** the Write when any region reads entirely `0xff` (already-erased / faulted radio). Regions: `LocalInfo`; optional-settings main (`0x3500000`/`0x200`), ext (`0x3500900`/`0x60`), APRS (`0x3501280`/`0x30`); alarm settings (`0x3482e00`/`0x10`) and data (`0x3483000`/`0x30`). In-session pre/post compare was removed ([#769](https://github.com/pskillen/codeplug-studio/issues/769)) — reads in the same PROGRAM session return flash, not the RAM shadow. **Cross-session verify** after `END` is optional in the build **Direct radio** UI: wait for the radio to finish its automatic restart, reconnect, and diff those spans against the pre-Write snapshot ([#769](https://github.com/pskillen/codeplug-studio/issues/769) slice 5b).

**Encode guards:** MR channel encode rejects AM airband frequencies (108–137 MHz) and non-BCD-encodable Hz before bytes are packed (`channelEncodeGuards.ts`).

| Category                                                   | `writeRole`     | Re-derived from build? | On Upload                                                                                                                                  |
| ---------------------------------------------------------- | --------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Channels, zones, scan, TG, RX, radio IDs, master, TG order | `replaced`      | Yes                    | Written from build (allow-listed); radio IDs and master only with a default DMR Digital ID, else left as read                              |
| APRS global config + channel APRS bits                     | `replaced`      | Partial                | Modelled digital fields from library; unmodelled bytes RMW-preserved ([#758](https://github.com/pskillen/codeplug-studio/issues/758))      |
| AM airband channels + AM zones                             | `replaced`      | When projected         | Written together when build has airband zones; else radio bank left alone ([#756](https://github.com/pskillen/codeplug-studio/issues/756)) |
| LocalInfo                                                  | `kept`          | No                     | **Not transmitted** — identity check only; unit not touched                                                                                |
| Optional settings, alarm                                   | `kept`          | No                     | **Preserved** — fresh-read + unchanged re-stage inside touched units                                                                       |
| DigitalContact\*                                           | `replaced`      | Yes (contacts)         | Written from Studio-owned erase units, never read ([digital-contacts.md](digital-contacts.md))                                             |
| Boot images, crypto, broadcast FM, …                       | `kept` / unread | No                     | Untouched — absent from cache unless future Read tickets                                                                                   |

**Serial Write projection:** `RadioWriteProjection` for `radio-io-at-d890uv` partitions receive-only AM airband and broadcast FM out of MR channels, zones, and scan — same bank split as Anytone CSV egress ([#755](https://github.com/pskillen/codeplug-studio/issues/755)). **AM airband** then projects into the parallel `AmAir*` / `AmZone*` banks when the build has airband channels **and** AM zone membership (zones ship with channels). Empty airband content retains the radio bank (DigitalContacts-style). Broadcast FM stays CSV-only until a later ticket — see [am-air.md](../../../export-formats/anytone/am-air.md). Export **Web Serial** shows an operator-facing **What Write updates** table (written vs deferred vs left alone).

**AmAir erase unit:** `AmAirData` (`0x3880000`) and `AmZoneData` (`0x3888000`) share erase unit `0x3880000`. Sparse RMW fresh-reads the unit when airband is written.

The `0x2fa0010` skip is anytone-cps lore. The official CPS encoder we read does not skip that address. Studio still skips it as a family precaution. D890 `LocalInfo+0x10` (`0x4f80010`) is excluded because LocalInfo is not on the upload allow-list.

**Operator note:** after CPS recovery or band changes, perform a **fresh Read** of the live radio before Write. Do not Write from a stale hydration YAML export — the build projection must match the radio you are connected to.

Web Serial Write is available on production deploys ([#800](https://github.com/pskillen/codeplug-studio/issues/800)).

Zone record detail: [zone-record.md](zone-record.md). Channel geometry: [channel-record.md](channel-record.md).

## Alternate half of a `0x40000` unit

Flash address space is **not** uniformly flat. Measured on hardware 2026-07-27 (`/debug/d890-erase-probe`, `ID890UV`, 240-byte reads). The upper half of a `0x40000` unit is an alternate unit, not a mirror of the lower half.

### ChannelData

| Property                     | Value                                                       |
| ---------------------------- | ----------------------------------------------------------- |
| Block pitch                  | `0x80000` (`ChannelDataBlockOffset`)                        |
| Bytes the write fence covers | `0x40000` (low half of each block)                          |
| Upper half                   | `+0x40000` — alternate unit, not a mirror of the lower half |
| Erase unit                   | `0x40000`, aligned                                          |

Firmware selects the live half at run time. `55 55 AA AA` at `+0x3FFFC` is the tail of the already-documented `+0x3fff0` marker block. `AA AA 55 55` at `+0x3FDF8` marks the lower half not live. Three firmware routines read those words. The PC-link address map is not settled. Never write the `+0x3fbf0` / `+0x3fff0` markers; see [flash-sectors.md](flash-sectors.md) and investigation [i001](../../../investigations/i001-d890-write-commit-failure/README.md).

Studio refuses upper-half ChannelData addresses ([#791](https://github.com/pskillen/codeplug-studio/issues/791)). That refusal is the write fence (`writableExtents.ts` per-block extents; `channelDataGeometry.ts`), separate from how firmware selects the live half.

### TalkgroupData ([#829](https://github.com/pskillen/codeplug-studio/issues/829))

The 2026-07-28 memory dump showed identical bytes at `0x3a40000` and `0x3a00000`. That window is the alternate half of the unit, not a mirror of the lower half. Studio still models a flat `TalkgroupData` bank. Slot `i` is `0x3a00000 + floor(i / 1000) * 0x80000 + (i % 1000) * 0xc8`. The writable window stays `[TalkgroupData, TalkgroupOrder)` and still includes `0x3a40000`. Do not raise `TALK_GROUPS_MAX` or change writable extents.

### Config regions

Regions that matter for erase-unit RMW ([#768](https://github.com/pskillen/codeplug-studio/issues/768)) are **flat** across `+0x40000` — the base and the upper half hold distinct cells ([#792](https://github.com/pskillen/codeplug-studio/issues/792)):

| Region                   | Base        | Upper half (`+0x40000`) | Length  | Status | non-`0xff` (base / upper) |
| ------------------------ | ----------- | ----------------------- | ------- | ------ | ------------------------- |
| LocalInfo                | `0x4f80000` | `0x4fc0000`             | `0x100` | flat   | 233 / 0                   |
| Optional settings (main) | `0x3500000` | `0x3540000`             | `0x200` | flat   | 512 / 512                 |
| ChannelSet               | `0x3482a00` | `0x34c2a00`             | `0x200` | flat   | 490 / 0                   |

Sparse erase-unit RMW may treat `0x3480000` and `0x3500000` units as 1:1 address → cell. Dual all-`0xff` spans would be inconclusive (not “flat”); none of the measured pairs were.

## Flash erase unit

Measured in `ChannelData` 2026-07-27 (`/debug/d890-erase-probe`, `ID890UV`): **`0x40000` (256 kB), aligned**. A write into a unit has been observed to clear co-resident bytes; bytes re-staged in the same PROGRAM session are what Studio puts back. There is no separate erase/commit opcode — see [flash-sectors.md](flash-sectors.md).

| Erase unit base | Modelled writes (examples)                                       | Co-resident regions preserved by sparse RMW         |
| --------------- | ---------------------------------------------------------------- | --------------------------------------------------- |
| `0x3480000`     | `ChannelSet`, `ZoneSet`, `ZoneHide`, `RadioIdSet`, `ScanListSet` | Alarm settings `0x3482e00`, `AlarmData` `0x3483000` |
| `0x3500000`     | `ZoneAChannel`, `ZoneBChannel`                                   | Optional settings main/ext/APRS `0x3500000`…        |
| `0x3880000`     | `AmAir*` / `AmZone*` (when airband projected)                    | AmAir VFO + unmodelled co-residents in the unit     |
| `0x1000000`+    | `ChannelData` (per backed block)                                 | Unused slots in same unit                           |

**Sparse staging:** only non-`0xff` 16-byte blocks are re-transmitted (~37.5 kB across 14 touched units in a typical codeplug, vs 3.67 MB dense). Fresh-read source is the **connected radio**, not a stored bag. Identity is the radio on the cable ([#1276](https://github.com/pskillen/codeplug-studio/issues/1276)); an erased LocalInfo refuses Write.

`LocalInfo` (`0x4f80000`) sits in unit `0x4f80000` — outside the modelled write set — so it is never transmitted.

**Vital units `0x4f00000`–`0x4fc0000`:** the tune bank (`0x4f00000`, calibration tables) and LocalInfo sit in four 256 KiB units that the [vital-data backup](backup-restore.md#vital-data-backup) reads whole. `0x4f40000` is diverted to LocalInfo on hardware. They are read-only to Studio.

## Channel address formula

For 0-based channel index `idx`:

```text
blockIndex   = idx / 128          // ChannelDataBlockSize
indexInBlock = idx % 128
primaryAddr  = 0x1000000
             + (blockIndex * 0x80000)   // ChannelDataBlockOffset
             + (indexInBlock * 0x80)    // ChannelDataOffset
secondaryAddr = primaryAddr + 0x40      // ChannelDataSecondaryOffset
```

Read/write **64 + 64** bytes (primary then secondary) and concatenate to a **`0x80`** combined record before decode. On D890 the halves are contiguous; still treat them as two 16-aligned transfers of `0x40` (multiple of 16).

Only indices with a set bit in `ChannelSet` are present.

## Occupancy bitmaps (summary)

| Set             | Size    | Sense                                                                                                                                                                                                                         |
| --------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ChannelSet      | `0x200` | Bit **set** → channel slot occupied                                                                                                                                                                                           |
| ZoneSet         | `0x20`  | Bit **set** → zone occupied                                                                                                                                                                                                   |
| RadioIdSet      | `0x20`  | Bit **set** → radio ID occupied. Live-cache encode retains this when the projection has no IDs; assemble-from-`0xff` zeros are **not** the Write contract ([#1129](https://github.com/pskillen/codeplug-studio/issues/1129)). |

### DigitalContact (huge bank — written on Write from Studio-owned units, no read)

Cite: anytone-cps `D890_MAP`, `Device::readDigitalContacts` / `parseDigitalContact_D890UV` / `writeDigitalContacts` — facts only. Studio writes this bank on Write, from erase units it owns outright and without reading them: [digital-contacts.md](digital-contacts.md) ([#992](https://github.com/pskillen/codeplug-studio/issues/992), [#1406](https://github.com/pskillen/codeplug-studio/issues/1406)). The layout is fully known upstream (unlike AmZone).

| Region                | Base        | Block length / stride             | Notes                                                                                                                                                                     |
| --------------------- | ----------- | --------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DigitalContactMeta`  | `0x7000000` | `0x10`                            | `u32` contact count @ `+0x0`, `u32` end address (post block-hop) @ `+0x4`, `0x8` padding                                                                                  |
| `DigitalContactData`  | `0x7900000` | Block `0x30d40`; stride `0x80000` | Variable-length records: call type, call-alert flag, BCD radio ID, then name/city/callsign/state/country/remarks as wide-char strings each terminated by `\0\0`           |
| `DigitalContactOrder` | `0x7080000` | Block `0x3e800`; stride `0x80000` | Sort/lookup, `0x8` bytes/contact (u32 LE BCD key, private so the added bit is 0, plus u32 LE linear data offset), rebuilt on every Write; odd entry count gets one `FF×8` |

Both `DigitalContactData` and `DigitalContactOrder` are **block-hopped**: logical byte `i` maps to `base + floor(i / blockLength) * stride + (i % blockLength)` — a linear record stream de-interleaved across `0x80000`-spaced physical blocks. The debug memory-export tool below reconstructs this linear stream (using the count from `DigitalContactMeta`) rather than dumping the raw sparse address range, which is mostly unused space between blocks.

## Debug memory-region export (`/debug/d890-erase-probe`)

Read-only raw-binary export of every region documented on this page, for offline diffing against codeplugs written by the official Anytone CPS — this is the read-only differential RE workflow for AmZone encode and any other undocumented byte ranges, not a modelled Read/Write path. Regions are grouped into higher-level areas (Device, Optional settings & alarm, APRS, Channels, Zones, Scan lists, Talkgroups, RX groups, Radio IDs, Airband) — each region's address/size is still listed individually, but export happens at group granularity:

- One button per group — zips every region in that group into a single download.
- **Export all (excl. Digital Contacts)** — every region above regardless of group, except `DigitalContact*`, zipped together (contacts are excluded because the block-hopped bank is large and slow relative to everything else).
- **Export Digital Contacts** — meta + de-interleaved order table + de-interleaved contact data, zipped separately.

Filenames are stamped with the export time in ISO 8601 (colons/periods replaced with `-` for filesystem safety). Nothing here is on the write allow-list; the tool only issues `R` frames.

Dump / write-verify region sizes for `ReceiveGroupSet` and `ReceiveGroupData` derive from `AT_D890UV_LIMITS` / `AT_D890_LIMITS` — same source as encode ([#845](https://github.com/pskillen/codeplug-studio/issues/845)). `ScanListData` debug export is 256 banked slots (`AT_D890_DUMP_SCAN_LISTS`), not a flat `SCAN_LISTS_MAX × 0x200` span; the product encode cap is 250 ([#1295](https://github.com/pskillen/codeplug-studio/issues/1295)).
