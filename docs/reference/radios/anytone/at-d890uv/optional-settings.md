# AT-D890UV — optional settings (the general settings block)

The optional-settings record is the radio's general settings: erase unit `0x3500000`, main record `+0x000..+0x15F` (RAM copy `0x200148E4`) and the power-on block `+0x900..+0x947` (RAM copy `0x20013226`). This page lists every field Studio's radio-settings feature offers, how it is encoded, what the firmware does with out-of-range bytes, and the fields Studio does not offer and why ([#1393](https://github.com/pskillen/codeplug-studio/issues/1393)).

- Layout of the unit and the patch rules (allow-list, never-patch offsets, erase-unit RMW): [memory-layout.md](memory-layout.md).
- Value lists and labels in code: `src/core/radios/anytone/at-d890uv/radioSettings.ts`. Offsets, masks and encodings: `src/integrations/radio-io/radios/at-d890uv/settingsFields.ts`.
- Firmware-side reference (offset to CPS identifier, load clamps, menu lists, who writes each byte): the firmware repo's `docs/reference/cps/records/optional-settings.md` and `docs/reference/firmware/codeplug-and-settings.md` (not copied here).

**Rule for what is offered.** The firmware is the arbiter. A value is offered when its meaning is settled by the firmware (its load clamp at `0x080DDEE0`, a radio menu list, or the reader of the byte), except the items under "Open items" below, each of which names its evidence and carries a radio check. Where the official CPS offers more than the firmware honours, Studio follows the firmware. "Wire = index" below means the stored byte equals the position in the list. Offsets are from the main record unless marked ext. **Targets:** every field is available on the stock and the MM9PDY target; MM9PDY only changes key-function labels.

**Exposure:** _menu_ = the radio's own menu has a row; _CPS_ = only the official CPS changes it; _hidden_ = the firmware honours it but neither shows it.

| `keyLongPF1`, `keyLongPF2`, `keyLongPF3`, `keyLongP1`, `keyLongP2`      | `+0x41..+0x45` | ff   | as short                                           | **none**       | menu     | as above                                                  |

The firmware does not range-check the key bytes: it calls through a table indexed by the stored value (`0x08016978`), so 65 and above reach the release table and 130 and above jump through arbitrary RAM. MM9PDY renames four functions: 13 TG Previous, 14 TG Next, 30 Quick Filters, 55 S-Meter; Studio shows those names on the MM9PDY target and writes the same numbers. The radio's own Key Func menu hides some functions per key (for example 62 Digital Protocol never, 6 Call on P keys, 9 Sub PTT on short P and all long, 12 Alarm, 18 Monitor and 46 TBST Send on long presses); Studio offers all 65, as the CPS does.

## Open items settled in this PR

Evidence is the firmware decompile of V1.05 (stock) and the emulator, never a radio.

1. **`+0xAF` "Name based".** Emulator: the live unit with `+0xAF` = 2 booted; RAM `0x20014993` reads 0 after load. The clamp at `0x080DDEE0` (`1 < byte` becomes 0) is confirmed. Studio offers 0 and 1, and decodes 2 as "Name based (the radio resets this at power-on)". Radio check RS8.
2. **Empty power-on line padding.** The owner's live settings half (byte classes only, no characters) shows each line as characters at even offsets with `00` between and `00` padding to the end of its `0x20` bytes, and `00` through ext `+0x5F` after the password. Studio encodes an empty line as `0x20` x `00`. A test shows the "settings block all 0xFF" guard does not fire for a valid encode.
   Length: the start-up screen (`0x0807652C`) draws each line through `0x0808DC10`, `0x08090610` and `0x0808D894`, which stop only at a `0x0000` unit, the screen width or a count of `0xFF`, never at 16. A 16 character line would have no terminator, so line 1 would run into line 2 and line 2 into the password block at ext `+0x40`. Studio caps lines at 14 characters (the CPS limit), which always leaves two NUL units. Static finding; radio check: 14 characters on both lines show no spill.
3. **Bounds.**
   - `txTimeout` 0..8: the radio's list has 9 entries (Off, 30 s ... 240 s); there is no load clamp.
   - `backlightTimeout` 0..15 in the order shown above, equal to the radio's 16-entry list. The radio's timeout table (`0x0814BA86`, read by `0x0811A544`, 100 ms ticks) holds 1800 and 2700 for entries 13 and 14, which the menu calls 30 and 45 min but are 3 and 4.5 min (entry 9 is also 1800). Studio labels them "3 min (radio menu says 30 min)" and "4.5 min (radio menu says 45 min)". Radio check: time them.
   - `txPreamble`: no load clamp and the menu lists 0..40, but the reader `0x08118AA8` uses 5 when the value is below 5 (DMR: `+0x152` is forced to 0 at load). Studio offers 5..40.
   - `powerOnVolumeLevel`: the start-up code (a level above 14 is 15) indexes a table `0x0815153E` whose entry 0 is 0 (silent). Studio offers 1..15.
   - Hang times: reader `0x081134F8` gives `n * 100` ticks below 31, 180000 at 31 (30 min, at 100 ticks per second) and 200000 for 32 and above (about 33 min, which the CPS calls "Infinite"). Studio offers 1..31; 0 and 32+ are not offered. Manual dial 0 is clamped to 1 at load.
   - `analogueCallHold`: no clamp, no menu row; the reader scales by 10 ticks and tests non-zero. 1..30 per the CPS. Units: the counter is decremented in the same 100 ms block as the auto power-off counter (which scales by 600 for minutes), so n is seconds; no on-air timing yet.
   - `voiceHeaderRepeats`: clamp `>10` becomes 2; the radio's list is 2..10 and the stored byte is the value. Studio writes the value. (The CPS encoder's adjustment is not Studio's concern: Studio writes the wire byte.)
4. **`+0x110` bits and `+0x4D` order.** Emulator, analogue demo channel on the standby screen, `+0x110` = `01`: the channel-type badge ("ANA") appears; `02` and `04`: nothing appears on an analogue channel (time slot and colour code are DMR-only). So bit 0 is the channel type. Bit 1 is the time slot: its drawer (`0x080737B0`) picks one of two strings by the channel's slot bit. Bit 2 is the colour code, from the code: the drawers in `0x08072654` and `0x08087518` are gated by bit 2 and write `'C'` and the digit of channel byte `+0x20` (the colour code); bit 0 gates `0x08072400` (channel type) and bit 1 gates `0x080737B0` in `0x080713B4` (time slot). A DMR-channel screenshot was not taken (it needs key presses to change channel); radio check RS8c. `+0x4D`: the firmware clamps to 0..3 and bit 0 gates the ID view (`0x080921B0`), but which value shows which line needs a received call; no fake call was run. Studio offers the CPS order (0 Off, 1 ID, 2 callsign, 3 both) and says so; radio check RS8b.
5. **`+0xBE` key-lock bits.** Read `0x08016978` and `0x08020860` (consumers at the tests of bits 0, 1, 3, 4 of `0x200149A2`); which key group each bit locks was not established. Not offered.
6. **Time-zone labels.** The 34 strings of `0x0818E2E0` are the labels above (UTC-12:00 ... UTC+13:00), taken from the firmware list.

Vectors (not committed): Studio's real `uploadSettingsPatches` frames for every v1 field at its highest offered value, then at its lowest, boot the stock image in the emulator and the settings RAM equals the encode, with no other settings RAM difference from a control boot and no settings-unit erase at boot.
