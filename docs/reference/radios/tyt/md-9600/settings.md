# MD-9600 / RT-90 firmware settings

Tier-3 reference for the OpenGD77 firmware's own settings struct (`settingsStruct_t`: menus, last mode, APRS beaconing, and so on) on the MD-9600 / RT-90, distinct from the codeplug "general settings" (below). Code: `src/core/radios/opengd77/settings.ts` (layout and decode), `src/integrations/radio-io/radios/opengd77/debugSettings.ts` (selection). Sibling model: [DM-1701 settings.md](../../baofeng/dm-1701/settings.md). Shared memory map: [OpenGD77 memory-layout.md](../../opengd77/memory-layout.md).

> Read from the OpenGD77 source (MD-9600 tree, snapshot 2026-01-31, `include/functions/settings.h:184-267`), static reading only; not validated on hardware. The size depends on an inferred toolchain fact (see below).

## Where it lives

|               |                                                                                                                                                                                                                                     |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Address       | SPI flash `0x604B` (`STORAGE_BASE_ADDRESS` = `0x6000 + 0x4B`, after the Last-Used-Channel-In-Zone block; `interfaces/settingsStorage.c:31-52`)                                                                                      |
| Primary store | The live copy is in STM32 backup SRAM (`BKPSRAM_BASE + 2`; offsets 0-1 hold the power-state flag); SPI flash `0x604B` holds a backup.                                                                                               |
| Size          | 0x70 (112 bytes), flash `0x604B-0x60BA`                                                                                                                                                                                             |
| Version       | `magicNumber`, a u32 little-endian at `+0x00`, must be `0x00004780` (`settings.c:44`). A different value makes the firmware restore defaults at boot (`settings.c:124-129`), so Studio refuses to name any field for another value. |
| Freshness     | The flash copy is rewritten after every boot load, on power-off, on a CPS save and on restore defaults or voice-prompt changes; menu changes go to backup SRAM, so the flash copy can lag until power-off.                          |

Studio labels the data **"Backup copy; the live copy is in backup SRAM."**

**Size is inferred.** `roaming` is an enum (values 0 to 5). arm-none-eabi GCC uses 1-byte enums by default and the project passes no `-fno-short-enums`, so the struct is 0x70. With 4-byte enums both models would be `0x78` and only the last three members would move. Everything before `+0x6D` is unaffected either way.

## What a capture holds today

Studio's first FLASH span ends at `0x6060`. A current capture holds the whole struct: span 0 gives `0x604B-0x605F` (21 bytes, `magicNumber` through `overrideTG` and the first byte of `vfoScanLow[0]`) and the debug-only `settings-gap` region gives `0x6060-0x60BF` (96 bytes, read in three 32-byte reads; it is not a flash span, so Write, Restore and Backup never touch it). An older archive has no `settings-gap` region and holds only the 21 bytes. Studio decodes whatever part of `0x6000-0x60FF` the archive holds and shows every other member as "not captured".

## Codeplug device info and general settings

Separate CPS-written blocks in the same flash span 0 (so already captured): device info at `0x80` (96 bytes) and general settings at `0xE0` (40 bytes), structs in `include/functions/codeplug.h`.

- **Device info:** only the four band limits (`minUHFFreq`, `maxUHFFreq`, `minVHFFreq`, `maxVHFFreq`, `0x80-0x87`, BCD in MHz) are read, and only if all four pass sanity checks against the hardware bands (`codeplug.c:190-201`, `settings.c:150-178`). `lastPrgTime`, `model`, `sn`, `cpsSwVer`, `hardwareVer`, `firmwareVer`, `dspFwVer` and the reserves are filled by `codeplugGetDeviceInfo` but never read: unused (no reader).
- **General settings:** the struct is never loaded (`codeplugGetGeneralSettings` has no caller). Two fields are read individually: the callsign `radioName` (`0xE0`, 8 characters, 0xFF or 0 padded, `codeplug.c:1297-1302`) and the DMR ID `radioId` (`0xE8`, BCD, big-endian byte order, `codeplug.c:1283-1294`). The rest (`0xEC-0x107`, stock CPS fields and the program password) are unused (no reader).
- **Boot password (display only):** enable flag at flash `0x7519` bit 0; PIN at `0x751C-0x751E`, packed BCD, high nibble first, up to 6 digits, a `0xF` nibble ends the PIN (`codeplug.c:1618-1647`, `CODEPLUG_ADDR_BOOT_PASSWORD_PIN` = `0x7518`). Confidence: firmware source, DM-1701 tree; this MD-9600 layout is unconfirmed (that tree was not read), so the row is shown with that caveat. Both are in captured span 1. The debug Settings tab shows the PIN, and `prgPwd` (`0x100`, 8 characters), only after **Show password**; Hex masks them. Studio never writes them.
- `0x108-0x10F` (inside Studio's 0x90-byte "settings" element) is not declared in this source.
- `0x6000` holds the Last-Used-Channel-In-Zone block: tag `"LUCZ"` then 70 bytes, ending `0x6049`; it is rewritten with the settings.

## Not claimed

Hardware validation; that a given OpenGD77 build matches this snapshot; the stock firmware's meaning of unused bytes; the MD-9600 / RT-90 live copy (it is in backup SRAM and is not reachable by a plain flash read).
