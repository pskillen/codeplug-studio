# AT-D890UV radio settings

**Tracking:** [#1393](https://github.com/pskillen/codeplug-studio/issues/1393) · fixes [#1394](https://github.com/pskillen/codeplug-studio/issues/1394)  
**Progress:** [at-d890uv-radio-settings-progress.md](at-d890uv-radio-settings-progress.md) · [outstanding](at-d890uv-radio-settings-outstanding.md)

Operators read and set the radio's general settings (key tone, backlight, power-on text, side-key functions, …) from Studio on both D890 targets. This page covers the **patch core** that all of it rests on, the **v1 field set** with its session store, the **Radio settings page** that reads a radio and sets overrides, and the **Write stepper's D890 Review step** that writes them, on their own or with the codeplug.

## Model

- **Overrides are session state.** A setting is a typed override (`fieldId`, value) held in memory for the session. It is never stored in the project, IndexedDB or YAML, and never written unless the app passes it to a Write.
- **A Write applies no overrides by default.** With none, every transmitted byte is identical to a Write before this feature (pinned by a golden-frame test).
- **Patch on the fresh read.** Each override becomes a field patch (address, new bytes, bit mask) applied to the fresh read of erase unit `0x3500000` inside the Write's read-modify-write. Nothing replays a stored image. Which bytes may be patched is a code **allow-list** of registered fields; wire addresses are in the [tier-3 memory layout](../../reference/radios/anytone/at-d890uv/memory-layout.md). The allow-list is enforced again in the protocol (`upload()` and `uploadSettingsPatches`) before any frame, so a hand-built patch outside it is refused. A settings-only Write does not populate the in-session download cache; a later codeplug Write still downloads first.
- **MM9PDY step keys use the same mechanism.** P1 short = TG next (14) and P2 short = TG previous (13) are two ordinary overrides, `keyShortP1` and `keyShortP2`. The persisted step-key switch is gone from the AT-D890UV (Export settings and the Write dialog); the Review nudge sets them (see below). The DM-32UV MM9PDY target keeps its switch, which has no settings page to carry a nudge.
- **Two patches for one field throw before any frame.** There is no precedence rule.

## Fields (v1)

Every v1 field has a typed value list in `src/core/radios/anytone/at-d890uv/radioSettings.ts`, an allow-listed spec (address, mask, encode and decode) and a decode from a settings read. Groups, in display order:

- **Call display:** call display mode, call sign colour, last caller, talker-alias priority and TX format, current contact and channel number on standby, channel type, time slot and colour code on the channel line.
- **Start-up:** power-on screen (default picture or text), the two text lines, start-up tone, start-up volume (fixed level or last knob position).
- **Volume and audio:** volume bar, maximum volume and headphone volume, audio profile (including the hidden Indoor and Outdoor), noise reduction, DRC, microphone gains.
- **Tones:** key tone, talk permit, call reset, idle tones, SMS and call alerts.
- **Display:** channel name or frequency, backlight level and timeout, menu exit time, colours, standby background, night mode, clock, date format, time zone.
- **Keys:** short and long press for PF1, PF2, PF3, P1 and P2 (65 functions, MM9PDY names on the MM9PDY target), long-press time.
- **Power and timers:** auto power-off and its type, TX timeout and pre-alert, power save.
- **DMR:** hang times, analogue call hold, preamble, voice header repeats, SMS format, own-ID missed-call filter.

**Advanced fields** (PR 5) sit behind the page's **Show advanced settings** switch: language (only what the read radio's region lock keeps), the power-on password, working mode (amateur or professional), repeater mode, accept remote stun/kill, accept remote monitor, answer GPS requests, encryption type, and auto repeater A and B. Each has a one-line warning shown once the field is set. Repeater mode also warns, in amber on its row and in the Review, when it is On (a Read plus your changes) and the read radio's Sub-Channel Mode is off, its NOAA alert is on or its AM/FM function is FM radio: the radio switches repeater mode off again at start-up. It also needs channels A and B to be both DMR or on different bands (one VHF, one UHF); Studio cannot check that and says so. The warning never blocks a Write, and Studio offers no one-click fix because it does not model those three fields. Values, offsets and firmware evidence: [optional-settings](../../reference/radios/anytone/at-d890uv/optional-settings.md).

Studio offers the range the **firmware** honours, not always the CPS's: for example call display mode has two values (the radio resets "Name based" at power-on), the audio profile has four, and the call sign colour has a hidden black. A value the radio holds that Studio does not offer (a custom start-up picture, for instance) is read and shown but cannot be set. Wire detail, clamps and the fields not offered: [optional-settings.md](../../reference/radios/anytone/at-d890uv/optional-settings.md).

## Session store

`atD890RadioSettingsSession` holds, per build and in memory only: the overrides, the last settings Read of a radio (identity, band code, language lock and every decoded field) and the fleet-write tick. A Read fills the "radio" column and **sets no override**; copying every readable value into overrides is an explicit action. Nothing touches the build, `exportSettings`, IndexedDB, localStorage or YAML, and a page refresh empties it.

## Radio settings page

Route `/builds/:id/export/radio-settings`, reached from **Radio settings** in the build strip (after Export settings). The strip entry shows on builds with an AT-D890UV Web Serial egress, stock or MM9PDY; on any other build the route says "Radio settings are only available for the AT-D890UV". Components: `AtD890RadioSettingsEditor`, `AtD890RadioSettingRow`, `Mm9pdyStepKeysNudge`.

| State        | What it shows                                                                                                                                                                     |
| ------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Not read** | Every field "Keep radio's value"; the Radio column says "not read". **Read a radio**. Values can still be set                                                                     |
| **Read**     | Banner "Read from <name> (<serial>) at <time> · range <range>", read-only rows (frequency range, firmware "unknown", serial in full), the Radio column filled. No control changes |
| **Changed**  | A sticky footer: "N changes · Clear all", **Write settings…** and a link to Back up a radio                                                                                       |

- **Keep / Set per field.** Each v1 field is _Keep radio's value_ (default) or _Set to X_. Overrides are session-only: they survive moving between pages, not a reload, and are never saved in the project. A Read fills the Radio column and sets nothing. **Copy all from this radio** (after a read, with a confirm) and **Clear all** (with a confirm) are explicit buttons; **Clear** on a row returns that field to Keep.
- **Read a radio** reads only what the page needs (LocalInfo, the settings spans, the master ID name, the band code) and offers no backup; the page links to Backup / Restore. The session closes the orderly way, which sends `END`: the radio restarts (about 20 s), writes nothing and is usable again by itself. Without `END` the radio would stay in PC mode until power-cycled. The page says "The radio restarts after a read" afterwards. (Studio's choice for open point Q-C; the Write stepper follows the same rule.)
- **Rows** show the label, a tag (On radio menu / CPS only / Hidden, MM9PDY-aware), a line of help, the radio's value, and the control. Values the radio holds that Studio does not offer (custom pictures, "Name based") appear only in the Radio column. Key functions carry the MM9PDY names on the MM9PDY target.
- **Show advanced settings.** A switch in the toolbar, off by default, per tab: it is kept in memory with the session, never in the project. Off: no advanced row is visible and none can be set. Turning it off while advanced changes are set asks first and **discards them**, so a value the user cannot see is never written. Rows are "Keep radio's value" by default like the others, and "Copy all from this radio" never copies an advanced field.
- **Language.** Disabled until a radio has been read ("Read the radio first: its region decides which languages stick"). After a read the options are only what that radio's lock keeps: English, Chinese and Russian when free, English only (lock 1), Chinese only (lock 2). A language already set that a newly read radio forbids stays visible, marked "(not allowed here)", with a red line; the Review and the Write refuse it.
- **Power-on password.** One control over two fields: digits only (1 to 8), typed twice, shown in clear. The two overrides are only set when both entries are valid and match, and always together; a broken edit after a good one goes back to Keep. **Clear password** sets enable off and the eight bytes to `00`, and is available without a read; the latest action wins (typing after Clear replaces it, Clear after typing replaces the password). The Radio column says On or Off and never shows the radio's digits. The Review lists it as one change ("Power-on password: Off → On (4821)").
- **Text lines** take at most 16 printable ASCII characters; both lines of 8 or fewer use the large font; Custom text with an empty line 1 shows a warning.
- **Step-key nudge (MM9PDY target only).** After a read, when P1 short ≠ TG next or P2 short ≠ TG previous, a nudge "Your P1/P2 keys aren't set to TG previous / next" with **Use MM9PDY step keys** appears above the Keys section. The button sets two ordinary overrides (`keyShortP1` = 14, `keyShortP2` = 13), editable like any other. When the keys already match, nothing is shown. It is also hidden once the session overrides either key, since a different layout is a valid choice. There is no rule tying these rows to the build's persisted step-key switch; the switch is removed in the Write step.
- **Frequency range.** The banner names the range (`Amateur Europe`) and the read-only row gives name, code and transmit bands (`Amateur Europe (code 3) · TX 430–440, 144–146 MHz`), from `describeAtD890FrequencyRange` with the ident's band code.
- **Write settings…** (sticky footer) opens the Write stepper on the Export page with only Radio settings ticked.

## Export panel: the Radio settings card

On Export (Web Serial, either D890 target) the **Radio settings** card sits under the Write header. It reads "N changes this session · read from <name>" (or "No changes · read from <name>", or "Your radios keep their own settings" before any read) and has **Edit settings** (the settings page) and **Read a radio** (a settings-only read that fills the page's Radio column, as on the page itself). The header's one-line summary also counts the changes. The counts are what this session holds: the Review can still answer Keep for a radio other than the one read, so a change counted here is written only where Review says Apply. The card is absent on every other radio. Backups saved this session (from the Backup page or from Review) live in the radio-neutral `radioSessionBackups` store, kept per build and in memory only; the Backup card on the same panel and the Backup page list both read it.

## Language lock guard

The radio re-forces its language from LocalInfo `+0x04` at every load, so a language its region forbids is undone (or garbles the menus until then). Two checks, the same rule: in the **Review**, a Language override the read radio's lock forbids shows a red line ("This radio's region only allows English; the Language change can't be applied.") with **Clear the language change**, and **Write** stays off until that is done or **Keep its settings** is chosen; in the **services** (`writeAtD890SettingsOnly` and the codeplug Write after its pause), the same check throws `RadioWriteBlockedError` naming Language before any frame. Language values above 2 are refused by the field spec.

## Write: the Review step

Plug in, **Write radio**, tick the parts, **Connect & read**, then **Review**: always shown, with sections that appear only when they apply. The D890's sections, in order:

| Section                        | What it shows                                                                                                                                                                                                                                                                                                                      |
| ------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **This radio**                 | Model, radio-ID name, serial (in full), firmware "unknown", and the **frequency range** from the ident's band code (the radio's own sanitised value: a locked maintenance code 14 reads as 0), as `Amateur Europe (code 3) · TX 430–440, 144–146 MHz`                                                                              |
| **Channels**                   | "N channels will be written." If any fall outside this radio's **transmit** range, "⚠ M channels are receive-only on this radio (range: …)" with an expandable list. They are **written anyway**: the radio listens on them and refuses PTT. The list is `listAtD890ReceiveOnlyChannels` for the read band code. Nothing is stored |
| **Radio settings** (if ticked) | Each change as _this radio now → after_; fields the radio already holds at that value are left out                                                                                                                                                                                                                                 |
| **Backup**                     | "No backup of this radio this session. **Save backup now**" or "✓ Backup saved 14:02". A nudge, never a gate                                                                                                                                                                                                                       |
| **Time**                       | "About 1 min 40 s"                                                                                                                                                                                                                                                                                                                 |

- **Radio settings part.** Ticked by default only when this session has changes; otherwise unticked and disabled with _Set up…_. With changes the row reads "3 changes · Edit" and lists the first few in words; **Edit** opens the settings page and the ticks come back when the stepper reopens.
- **Fleet rule.** If the Write is for the radio the settings were read from, the changes are listed and applied with no choice. For any other radio, or when nothing was read this session, the inline choice **Apply** / **Keep its settings** is shown, **Keep preselected**, plus **Review its settings**: no frame is sent, this radio's values are stored as the page's read, the settings page opens with your changes still set, and the session closes (see Q-C below). The Done screen's **Don't ask again for other radios until I reload** sets `applyToEveryRadio`; while set, Apply is preselected and Review says so.
- **Settings only.** With Radio settings the only part ticked, Write uses `writeAtD890SettingsOnly`: it reads the four settings spans, shows Review, then patches only erase unit `0x3500000`. On another radio with Keep preselected the Write button is disabled until Apply (Keep would write nothing). The Write button names what will be sent: with Keep chosen on another radio it does not say "settings".
- **Backup from the read.** A codeplug Write has already read the whole radio, so **Save backup now** packs that read into the same zip a Backup page backup makes (`packAtD890BackupFromSession`), from a copy of the cache taken at the pause so the upload cannot change it; nothing more is sent to the radio. A settings-only Write read only the settings, so the button reads "Read the rest of the radio and save a backup (about N s)" and runs the download in the held session first. Each saved backup is recorded for the session (name, serial, time) for the Backup page to list.
- **MM9PDY step-key nudge.** On the MM9PDY target, when the read P1/P2 short aren't TG next / TG previous, Review shows "Your P1/P2 keys aren't set to TG previous / next" with **Use MM9PDY step keys**. The button sets the two ordinary overrides, ticks Radio settings and selects **Apply** (asking for the keys is asking for them to be written, even on another radio where Keep was preselected); the Write then applies them like any other change (the transmitted bytes are the same as the old switch's, pinned by the golden-frame test). When the keys match, or the session already overrides them, nothing is shown.
- **Stun/kill flag.** A radio whose LocalInfo `+0x00` or `+0x01` is non-zero is refused before anything is read or written, and the session leaves without `END` (see the [protocol reference](../../reference/radios/anytone/at-d890uv/protocol.md), [#1288](https://github.com/pskillen/codeplug-studio/issues/1288)).

## Behaviour

| Piece                 | What it does                                                                                                                                                                                                                                                                                                                                                                               |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Preserved check       | A staged block outside the modelled set may differ from the fresh read only in patched bits; anything else aborts the Write before the first frame                                                                                                                                                                                                                                         |
| Verify                | The cross-session "Preserved settings" compare expects each kept span to read `before ⊕ patches`. A step-key Write no longer reports a false FAIL ([#1394](https://github.com/pskillen/codeplug-studio/issues/1394)). Payloads stored before patches existed verify as before                                                                                                              |
| Settings-only upload  | Writes only erase unit `0x3500000` with the patches applied, through the same RMW core (plausibility checks, marker filter, transmit fence, no `END` on failure). Needs no Download                                                                                                                                                                                                        |
| Settings read         | Four reads (LocalInfo, settings main, power-on block, master ID) plus the ident band code; for the confirm step and the settings page                                                                                                                                                                                                                                                      |
| Pause before transmit | After the in-session read and before the first `W` frame, every Write calls the stepper back with the neutral Review context plus, on the D890, its serial, settings spans and a copy of the read. The answer is `apply`, `keep` or `cancel`, or `apply` with the overrides as they stand at the pause (the nudge can add some). No callback means `keep`; `cancel` stops before any frame |

## Decisions

- Overrides are **sparse typed field patches** applied to the fresh read, not a settings image.
- **Whole-region replay stays Restore-only.** The settings-only upload reuses the Write RMW core and never Restore's region replay.
- **Session-only** state; the default Write is unchanged.
- The persisted step-key switch is **removed for the AT-D890UV** (nudge instead, 70- §8); the DM-32UV MM9PDY target keeps it. A stored `exportSettings.assignMm9pdyStepKeys: true` on a D890 build is ignored: it loads, saves and validates, and writes no patch.
- **Review is always shown**; the backup is a nudge, never a gate.
- **Write every channel the hardware can receive; warn on the transmit range at Review.** Nothing about the range is stored.
- **Read a radio closes with `END`**, as every Studio read does, so the radio is never left in PC mode. So do Cancel on Review, Review its settings and a settings-only session that writes nothing: `END` restarts the radio (about 20 s) and changes nothing, where leaving PROGRAM without it would leave the radio in PC mode until power-cycled (Q-C). The stepper tells the user the radio restarts.

- **Owner rulings (2026-10-26), for every Write and settings screen.** (1) **The serial is shown in full everywhere** it is shown (Review, the This radio row, backup lists): nothing truncates it, because the user is deciding which radio gets written. (2) **Overrides are session-only**; no settings choice is stored in the project or the browser. (3) **Keep is the default** for every field and every part, so a Write changes only what the user asked it to. (4) **The latest user action wins** over any earlier choice or derived state (typing after Clear replaces it; a broken edit goes back to Keep), and **an indicator shows the state that will be written**, not the state last configured. (5) **The Write button names only what is sent** ("Write codeplug", "Write codeplug + settings", "Write 3 parts").
- **Advanced fields are opt-in per tab and per field.** The switch, the per-field warning and "Keep" as the default keep a wrong value from being a one-click mistake; hiding the switch discards what it hid.
- **The password is written whole or not at all** (enable and digits together, `00` padding, never `FF`), 1 to 8 digits, because the firmware compares until the first `00` and an erased password with the enable byte set is a lock nobody can type.
- **Where the brief and the CPS audit disagree, the firmware wins.** The audit's addresses matched the brief for every advanced field; its value lists carry no ranges, so the ranges are the firmware's.

## Not done / rejected

- Stored settings images, and per-radio settings profiles keyed by serial: they would copy one radio's settings onto another.
- Auto-repeater limits and offset indexes (range-dependent tables and an unwritten offset list), the start-up channel, the key-lock scope (bits not settled), the MM9PDY store at `+0x200`, LocalInfo writes, frequency range: later PRs.
- Fields the CPS offers but the firmware never reads, and the Bluetooth test mode: never offered.

## Digital protocol and NXDN

Studio offers no Digital protocol or NXDN mic gain setting. A Write leaves `+0x152` and `+0x153` as read (a test pins this); the protocol is switched on the radio. The one exception is Reset Digital Protocol (`+0x154`): on an MM9PDY radio that reports NXDN enabled, a Write sets it to Off so the menu choice survives every boot. Whether a Write sends NXDN channel fields depends on the radio: see [NXDN channel fields](../../reference/radios/anytone/at-d890uv/nxdn.md).
