# Browser radio read / write

In-browser read and write of handheld radios over **Web Serial** (and related transports such as BLE), so operators can program a radio without leaving Studio after assembling a **radio build**. File export (CSV, `.neonplug`, YAML) remains first-class; Studio does not claim to replace vendor CPS as the only path.

**Tracking:** Epic [#594](https://github.com/pskillen/codeplug-studio/issues/594) · Spike [#603](https://github.com/pskillen/codeplug-studio/issues/603)

**Constitution:** [DESIGN.md](../../../DESIGN.md) — intentional browser radio I/O with attribution to CHIRP / NeonPlug lineages.

**Layer rule:** library and domain stay vendor-neutral. Binary protocols, baud/handshake, and memory maps live in `src/integrations/radio-io/` and tier-3 `docs/reference/<family>/` — never in core models or library CRUD.

## Concepts

| Concept              | Meaning                                                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Transport**        | Browser byte pipe (Web Serial, optional BLE) — port request, baud, timeouts                                                                                                                                                                                                                                                                                                                             |
| **Protocol kit**     | Reusable session, codecs (PROGRAM+R/W, PROGRAM→QX, Anytone DMR R/W, V-probe, OpenGD77 serial, …), `MemoryMap`, progress                                                                                                                                                                                                                                                                                 |
| **Radio module**     | Per-model descriptor, handshake, image layout, encode/decode                                                                                                                                                                                                                                                                                                                                            |
| **Clone image**      | Contiguous (or sparse-assembled) memory dump decoded offline                                                                                                                                                                                                                                                                                                                                            |
| **Hydration**        | Unmodelled / full-image state on the **Web Serial `EgressPath`** (`hydration`) when an adapter still requires a stored bag for **Write-codeplug** (escape hatch parallel to NeonPlug donor retain). DM-32UV still stashes for Write **and** overlays onto an in-session content read. RT95 still stashes for Write. AT-D890UV, OpenGD77, and UV-17Pro family Write use this PROGRAM session instead. Hydration is not the inspect surface and must not be persisted for backup. |
| **Write codeplug**   | Export-tab Web Serial write: modelled build overlay via `assemble` / `prepareRadioWriteImage` / `upload`. Not restore.                                                                                                                                                                                                                                                                                  |
| **Backup / inspect** | Strip tab `/builds/:id/backup`: live `download()` → auto-download zip + RAM session, or open a zip offline. Leaving the tab discards RAM. Legacy `/radio-info` and `/radio-image` redirect here. See [backup-restore.md](backup-restore.md).                                                                                                                                                            |
| **Restore**          | Replay **restorable** zip regions onto a matching radio via `restoreFromBackup`. Never `assemble`. AT-D890UV does not restore LocalInfo. Serial mismatch is a hard refuse.                                                                                                                                                                                                                              |
| **Experimental**     | Direct radio Export shows an orange **Web Serial is experimental** warning — browser write is under active development and riskier than established CPS until each adapter is marked stable.                                                                                                                                                                                                            |
| **V-frame**          | Discrete probe/info frames (e.g. DM-32) — not the kit’s default shape                                                                                                                                                                                                                                                                                                                                   |

New adapters: follow [adding-a-radio-adapter.md](adding-a-radio-adapter.md). **Write-codeplug** always goes through `RadioBuild` + active egress + `assemble`; when the radio target has **`MxNChannelExpansion`**, app services run the shared **`expandAllMxNChannels`** projection (same as CPS export / wire preview) before mapping to `RadioChannelDto[]`. Do **not** tell operators to stash for Write on AT-D890UV, OpenGD77, or UV-17Pro family — those overlays use this PROGRAM session. DM-32UV still persists `radio-clone` hydration for Write **and** bulk-reads live block contents before overlay. RT95 still persists `radio-clone` hydration for Write until parked ephemeral-radio-info work resumes. **Backup / Restore** never persists the zip on the project and never `assemble`s. MVP Read does **not** import channels into the library.
