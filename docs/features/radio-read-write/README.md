# Browser radio read / write

In-browser read and write of handheld radios over **Web Serial** (and related transports such as BLE), so operators can program a radio without leaving Studio after assembling a **radio build**. File export (CSV, `.neonplug`, YAML) remains first-class; Studio does not claim to replace vendor CPS as the only path.

**Tracking:** Epic [#594](https://github.com/pskillen/codeplug-studio/issues/594) · Spike [#603](https://github.com/pskillen/codeplug-studio/issues/603)

**Constitution:** [DESIGN.md](../../../DESIGN.md) — intentional browser radio I/O with attribution to CHIRP / NeonPlug lineages.

**Layer rule:** library and domain stay vendor-neutral. Binary protocols, baud/handshake, and memory maps live in `src/integrations/radio-io/` and tier-3 `docs/reference/<family>/` — never in core models or library CRUD.

## Concepts

| Concept          | Meaning                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Transport**    | Browser byte pipe (Web Serial, optional BLE) — port request, baud, timeouts                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Protocol kit** | Reusable session, codecs (PROGRAM+R/W, PROGRAM→QX, Anytone DMR R/W, V-probe, OpenGD77 serial, …), `MemoryMap`, progress                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| **Radio module** | Per-model descriptor, handshake, image layout, encode/decode                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Clone image**  | Contiguous (or sparse-assembled) memory dump decoded offline                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Hydration**    | Unmodelled / full-image state persisted on the **Web Serial `EgressPath`** (`hydration`) so write-back stays valid (same escape hatch as NeonPlug donor retain). **Radio image** secondary nav appears when that bag is stored, not only while Web Serial is the active Export pathway ([#668](https://github.com/pskillen/codeplug-studio/issues/668)). DM-32UV ([#672](https://github.com/pskillen/codeplug-studio/issues/672)), UV-5R Mini ([#675](https://github.com/pskillen/codeplug-studio/issues/675)), RT95 VOX ([#732](https://github.com/pskillen/codeplug-studio/issues/732)), OpenGD77 DM-1701 ([#624](https://github.com/pskillen/codeplug-studio/issues/624)), and AT-D890UV ([#751](https://github.com/pskillen/codeplug-studio/issues/751)): page shows on-radio counts, what Write replaces from the build, and decoded retain-only settings. |
| **Experimental** | Direct radio Export shows an orange **Web Serial is experimental** warning — browser write is under active development and riskier than established CPS until each adapter is marked stable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **V-frame**      | Discrete probe/info frames (e.g. DM-32) — not the kit’s default shape                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

New adapters: follow [adding-a-radio-adapter.md](adding-a-radio-adapter.md). Write always goes through `RadioBuild` + active egress + `assemble`; when the radio target has **`MxNChannelExpansion`**, app services run the shared **`expandAllMxNChannels`** projection (same as CPS export / wire preview) before mapping to `RadioChannelDto[]`. MVP **Read** hydrates the egress (read-only settings), and does **not** import channels into the library.

**Residual gap:** [#688](https://github.com/pskillen/codeplug-studio/issues/688) hardware/research backlog under [#636](https://github.com/pskillen/codeplug-studio/issues/636) (lab smoke for zone membership, emergency tag, scan IDs 16–32, etc.). Encode fidelity tickets ([#661](https://github.com/pskillen/codeplug-studio/issues/661), [#666](https://github.com/pskillen/codeplug-studio/issues/666), [#708](https://github.com/pskillen/codeplug-studio/issues/708)) closed 2026-07-25.
