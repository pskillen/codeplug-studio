# Browser radio read / write

In-browser read and write of handheld radios over **Web Serial** (and related transports such as BLE), so operators can program a radio without leaving Studio after assembling a **radio build**. File export (CSV, `.neonplug`, YAML) remains first-class; Studio does not claim to replace vendor CPS as the only path.

**Tracking:** Epic [#594](https://github.com/pskillen/codeplug-studio/issues/594) · Spike [#603](https://github.com/pskillen/codeplug-studio/issues/603)

**Constitution:** [DESIGN.md](../../../DESIGN.md) — intentional browser radio I/O with attribution to CHIRP / NeonPlug lineages.

**Layer rule:** library and domain stay vendor-neutral. Binary protocols, baud/handshake, and memory maps live in `src/integrations/radio-io/` and tier-3 `docs/reference/<family>/` — never in core models or library CRUD.

**MM9PDY modded firmware** uses the same AT-D890UV (and, when shipped, DM-32UV) Web Serial codecs as the stock targets. The radio target changes what is assembled — one channel per repeater, zone as the scan — not a second encoder. An AT-D890UV MM9PDY Write with no zone-derived lists still writes one scan list containing the first channel so the occupancy bitmap is not empty. See [modded firmware](../modded-firmware/README.md).

## Concepts

| Concept              | Meaning                                                                                                                                                                                                                                                                                                                |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Transport**        | Browser byte pipe (Web Serial, optional BLE) — port request, baud, timeouts                                                                                                                                                                                                                                            |
| **Protocol kit**     | Reusable session, codecs (PROGRAM+R/W, PROGRAM→QX, Anytone DMR R/W, V-probe, OpenGD77 serial, …), `MemoryMap`, progress                                                                                                                                                                                                |
| **Radio module**     | Per-model descriptor, handshake, image layout, encode/decode                                                                                                                                                                                                                                                           |
| **Clone image**      | Contiguous (or sparse-assembled) memory dump decoded offline                                                                                                                                                                                                                                                           |
| **Hydration**        | Opaque retain on an **egress**. Web Serial Write does **not** persist `radio-clone` bags. **NeonPlug `donorRetain`** on a NeonPlug file egress is a separate labelled escape hatch ([neonplug merge](../import-export/neonplug/README.md)). Hydration is not the inspect surface and must not be persisted for backup. |
| **Write codeplug**   | Export-tab Web Serial write: `assemble` → overlay modelled projection onto an **in-session** radio download (`resolveRadioWriteImageForUpload`) → `upload`. Never a blank/`0xff` image and never a persisted clone bag. Not restore.                                                                                   |
| **Backup / inspect** | Strip tab `/builds/:id/backup`: live `download()` → auto-download zip + RAM session, or open a zip offline. Leaving the tab discards RAM. Legacy `/radio-info` and `/radio-image` redirect here. See [backup-restore.md](backup-restore.md).                                                                           |
| **Restore**          | Replay **restorable** zip regions onto a matching radio via `restoreFromBackup`. Never `assemble`. AT-D890UV does not restore LocalInfo. Serial mismatch is a hard refuse.                                                                                                                                             |
| **Experimental**     | Direct radio Export shows a one-line **Web Serial is experimental** note with a **Details** link (the orange warning text); the Backup page keeps the full alert. Browser write is under active development and riskier than established CPS until each adapter is marked stable.                                      |
| **V-frame**          | Discrete probe/info frames (e.g. DM-32) — not the kit’s default shape                                                                                                                                                                                                                                                  |

New adapters: follow [adding-a-radio-adapter.md](adding-a-radio-adapter.md).

### Inspect vs Write vs Restore

| Composition            | Where                                                                                                         | What it does                                                                                                                                                                                                                                                       |
| ---------------------- | ------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Inspect / snapshot** | **Backup / Restore** strip tab (`/builds/:id/backup`). Legacy `/radio-info` and `/radio-image` redirect here. | Live `download()` → zip on disk + RAM inspect, or open a zip offline. Not a Write precondition.                                                                                                                                                                    |
| **Write codeplug**     | Export tab Web Serial panel                                                                                   | Overlay the modelled build on a **same-session** radio read. Never stash-then-write; never blank/`0xff` Write ([i001](../../investigations/i001-d890-write-commit-failure/README.md), [i002](../../investigations/i002-d890-program-error-after-write/README.md)). |
| **Restore**            | Same Backup / Restore tab                                                                                     | Zip → `restoreFromBackup`. Never `assemble`. LocalInfo and isolated calibration are not restored from the zip.                                                                                                                                                     |

**Write-codeplug** always goes through `RadioBuild` + active egress + `assemble`; when the radio target has **`MxNChannelExpansion`**, app services run the shared **`expandAllMxNChannels`** projection (same as CPS export / wire preview) before mapping to `RadioChannelDto[]`. Do **not** tell operators to Read-and-stash for Write. **Backup / Restore** never persists the zip on the project. MVP Read does **not** import channels into the library. NeonPlug file **donor retain** is a different egress — not Web Serial Write.

After a successful DM-32 Write, stock and MM9PDY tell the operator to power the radio off and on before keypad use, because the session leaves the previous page map in place ([protocol](../../reference/radios/baofeng/dm-32uv/protocol.md#write-codeplug-4kb-block)).

Encode fidelity tickets ([#661](https://github.com/pskillen/codeplug-studio/issues/661), [#666](https://github.com/pskillen/codeplug-studio/issues/666), [#708](https://github.com/pskillen/codeplug-studio/issues/708)) closed 2026-07-25.
