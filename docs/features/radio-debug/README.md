# Radio debug

**Status:** In progress · **Tracking:** https://github.com/pskillen/codeplug-studio/issues/1692

The Debug hierarchy groups radio profiles, browser storage and serial transport tools. Debug pages are gated on production by developer mode. The selected radio profile is an expectation; it does not identify the connected radio or its firmware.

## Behaviour

The radio debug page (`/debug/radios/:radio`) is dark throughout: the whole page sits inside one `DesignSystemV2Provider scheme="dark"` and the app shell paints its background and footer dark for these routes, so on a light app theme it shows as one dark page with no light islands (dropdowns open inside the page, not on `body`).

RT95 debug captures include the clone programming image and a separate inspect-only main-body EEPROM prefix relayed via the head. PC ident is head evidence; clone channel and settings storage is unknown. See the [RT95 calibration reference](../../reference/radios/retevis/rt95/calibration.md) for coverage and limits. The Calibration tab (shared `CalibrationTab`, built by `rt95/debugCalibrationView.ts`) opens with Read and Overlay pickers, then labelled charts (VHF and UHF power with Low/Mid/High lines against MHz, squelch and S-meter steps, FQC trim on its raw 0-255 scale, ppm unknown), striped value tables (production record with the serial in full, per-band values with VHF and UHF side by side, program password), the unused ranges and the raw bytes, folded. The Read pick is the page's selected read, so it also switches Memory, Settings and Hex; Overlay is for Calibration only and is separate from the Compare A/B pair. Old archives show Not captured and malformed regions are refused. Provenance ([head], [body] or [unknown]) is stated once per section on the RT95 Memory tab (clone channels and P-keys: storage MCU not documented; MMD1 zones: main board), not on every cell; the Overview, Hex, Coverage and Compare views still tag values. RT95 zones list only occupied, readable members as "Radio name / description" and count the members that point at empty or unreadable slots. Password bytes (the stored program password in the calibration prefix, the power-on password in the programming image) are masked as `••` in the field list, raw dumps, Hex, Compare and the decoded diff until the operator presses **Show password**; they are hidden again whenever another read or archive is shown. The unconfirmed program-password row (calibration `0x3B18`, 4 bytes) shows, once revealed, its hex and its ASCII when every byte is printable, labelled "encoding unconfirmed". The archive file itself still holds every byte.

The radio profile shells can open compatible radio-backup ZIPs without a library or build. The Backup tab lists the archive’s named ranges and sidecars and can download the original archive. Gaps between listed numeric ranges are unclassified because entries may use different address spaces; the archive does not establish completeness outside its entries. An invalid or incompatible file leaves the current archive in place. Archive identity fields are reported as archive evidence, not live radio identity. The RT95 profile can make a live read using the existing Backup reader behind a read-only frame allow-list; the resulting archive stays in the tab until downloaded. The RT95 programming-image range is classified against its known clone map and a complete image has a channel summary. Coverage shows SHA-256 hashes for captured regions and classifies the RT95 programming image against its known map. The RT95 EEPROM prefix is classified separately from clone offsets. Other address spaces remain unclassified. The Hex tab pages through captured regions. Memory shows RT95 clone slots and all 73 registered settings fields (with trust, raw bytes, named unclaimed byte runs (meaning or unused, with confidence) and a masked power-on password) from available captured bytes, including raw record details and unavailable fields. Compare opens a second archive and compares matching RT95 programming-image and EEPROM bytes and decoded channel names and settings; regions with unknown address space or representation are incomparable, as are missing bytes. Trace export and other live capture adapters remain unavailable. The existing UV-5R Mini read and AT-D890UV erase-unit probe remain separate tools; the latter can write during erase passes. IndexedDB inspection is read-only; local storage permits deleting individual keys. Serial reopen sends test bytes and requires a cable without a radio attached. Legacy storage and transport links redirect to the new hierarchy, retaining path parameters, query and hash.

The UV-5R Mini profile can capture the clone address space through the guarded read-only session. Its archive stores decoded clone bytes and preserves wire bytes and F/M replies as sidecars. The clone address space is not a physical flash or firmware dump. Ordinary Mini backup MEM entries use packed offsets; coverage maps these to their radio addresses and preserves a separate zones entry. Calibration is only captured when its actual range is present. A validated live format-2 MM9R report is compatible report evidence; an absent, invalid or unsupported report, and an archive without live provenance, leave firmware identity unknown. The shared page shows decoded span hashes, wire and decoded hex, tab-local history, calibration and comparisons for complete captures. Its Calibration tab is the shared tab: PA-bias frequency charts (x in MHz) and squelch step charts as labelled cards, each with a folded Numeric table, plus striped value tables. The Mini keeps its reads in the shared history store, so `/debug/uv5r-mini` (own page, own read store) no longer shares reads with it. Archives opened from Compare enter the same tab-local history as other imports, are available to the other viewers, and are included in Download all reads. It can open the legacy multi-read ZIP and display channels and zones when their required bytes are present. The legacy Mini debug page remains available while shared-page parity is verified ([#1747](https://github.com/pskillen/codeplug-studio/issues/1747)).

The DM-32UV profile (stock / MM9PDY) captures the configuration window through a guarded read-only session and makes a partial standard radio-backup archive. It reads exactly the blocks the product Read reads; other blocks the radio reports are listed as discovered but not read, with their tags. The factory sector is kept only when both reads match and is shown as its own address space. Every frame is checked against an allow-list before the transport and the session runs one frame at a time; any refusal, failure or cancellation stops it with no retry. There is no END command: the radio leaves PROGRAM mode after about 2 seconds of silence, so wait a few seconds, or power-cycle the radio, before using it. A factory-sector mismatch keeps nothing and the capture continues; a malformed factory-sector reply, a missing V-frame `0x0A`, a bad reply, a timeout or a short read fails the capture with no archive. Coverage lists every 4 KiB window block as captured, discovered but not read, or not discovered, with its tag and live or duplicate calibration role; a build Backup archive classifies the same way, with discovery not recorded. Identity shows the PSEARCH model and V-frame replies as returned. V01 is the stock base version and does not identify a mod. The radio has no readable serial, and the V02 chip UID is not a serial. "MM9PDY-compatible data present" appears only for a decodable channel location page, which is persistent data, not running firmware. Running firmware and mod stay unknown. The Calibration tab (read-only, "Not validated on hardware") decodes the live calibration page and the factory sector from the open archive, live read or file, using only the layout traced in stock `DM32.01.L01.048`, on the shared Calibration tab (`dm32uv/debugCalibrationView.ts`): Read and Overlay pickers, then cards for TX power (UHF and VHF, low / mid / high at the five TX frequency points; the drive byte is DAC ÷ 16), squelch thresholds (each band's two level-1 and level-9 pairs at the five RX frequency points, plotted by an inferred pairing, and the 108–136 MHz pair by point number) and the battery threshold and ADC scale, each with its Numeric table. Below them, striped tables by group (band limits, frequency points, TX power, level pairs, scalars, boot scalars, audio levels, ADC calibration, tables, adjust-mode test frequencies, factory options) show offset, width, raw hex, decoded value where known, the firmware consumer address and separate layout and meaning confidence; spans nothing reads are folded as unused ranges and every other byte is in the folded raw bytes. No oscillator trim is traced, so there is no trim card. The live page is the lowest in-window tag `0x02` page, shown with its address and SHA-256; duplicates are listed, not decoded, and regions the coverage rules refuse are listed with their reason and never searched. `calibration.json` and `factory-sector.json` are only cross-checks. The anti-clone key is raw hex only, the chip UID is labelled as not a serial, and the captured V01 is compared with the layout basis with a warning when it differs. The Memory tab (read-only, "Not validated on hardware") lists channels, zones and scan lists decoded from the open archive without a project, library or build. It accepts only whole 4 KiB blocks the coverage rules accept, lists refused entries with their reasons, and takes page order only from the capture's discovery map: a build Backup archive has none, so channels and zones say "Page order not established" and are not guessed (scan lists have a single tag and still work). The channel count is the u16 at the first channel page; slots keep their one-based numbers and each record is decoded only when its 48 bytes were captured, so an erased slot (all `0xFF`), a blank record, an invalid-BCD frequency, a missing TX frequency and a record that was not captured are shown separately. A channel's TX contact, radio ID and RX group resolve against the captured lists (TX contact by one-based position in the talk-group list, radio ID by zero-based index with `0xFF` none, RX group as slot n = group n, labelled "assumed 1-based; not verified on hardware"), and each reads none, resolved, out of range, absent, not decoded, list not captured or not captured; a channel's scan list resolves to the captured scan list or reads absent. Zones and scan lists keep radio order; a member is a channel slot number resolved against the decoded channels (resolved, out of range, empty, not captured, unresolvable, or unreadable), duplicates kept; a zone member count above 64 is shown raw and reads no members; a scan list stores its named members plus one, and its hang, priority and designated-TX bytes are raw hex only. A zone or scan-list page that was not captured reads "Not captured", never zero entries. The radio has one name field, so that complete label is searched and sorted, and separate callsign data is unavailable. Talk groups (the first `0x44` page: 24-byte entries after one header byte, at most 170 of the 800 hardware entries; the stored count from the quick-access page `0x0B` is shown beside the decoded count with a mismatch warning; pages `0x45` to `0x48` are listed as present, layout not established, so the list is never called complete), radio IDs (count byte, 16-byte entries, cap 250) and Contacts decode from the open archive. A page is used only when exactly one accepted block carries its tag; several are listed as "Several pages tagged 0xNN, not decoded", and a missing page is "Not captured", never zero entries. Talk groups and radio IDs have a name only, searched and sorted by name and DMR ID, and callsign data is unavailable. Contacts always says the digital address book (V-frame `0x0F` bank) is not captured, and shows the analogue (DTMF) contact count and raw 32-byte records as hex only. RX groups (tag `0x0F`: a u32 bitmask whose set bits mark present groups, so slots can have holes; 109-byte entries with an 11-byte name and 32 member positions of 3-byte DMR IDs) keep stored order and duplicates and show empty positions as empty; a member is matched to a talk group by DMR ID only when exactly one decoded talk group has it, and the per-member time-slot store is read only when its marker and the group's check match. Each talk group's Referenced by lists the captured channel TX contacts and RX group members that refer to it, and says partial when channel, TX contact or RX-group coverage is incomplete. Settings (tag `0x04`; read-only, grouped as Display, Tones & alerts, Power & battery, Keys & buttons, GPS / APRS, DMR & calls, Privacy / lock and Other) decodes the single accepted `0x04` page against the stock DM32.01.L01.048 layout in the settings reference, traced by static analysis and verified against synthetic fixtures only, not hardware. Each field shows a confidence (traced, partly traced when its name or unit rests on the vendor CPS label order and is labelled inferred, unknown when the name is a guess) and its 048 evidence address. A field is decoded only when its whole span was captured and is never gap-filled; unsupported values (a hemisphere byte that is not a letter, a time zone above 25) stay raw. Every field has an address and raw-byte view ("Show raw bytes + address"); areas whose reads are traced but whose records are not decoded (one-key call, one-touch, Fun+ with its 12 entries, menu-row enable bits) are raw rows labelled "documented, not decoded"; bytes nothing in 048 reads are listed as unused (free, not read by 048, or reserved for MM9PDY) and any captured byte that nothing covers is counted and listed as unknown. The power-on, write and read passwords are hidden until **Show password** is pressed, and hidden again when the archive changes. Hex and Compare mask the same three passwords at the address the `0x04` page was captured at (display only; the archive keeps every byte). No page reads "Not captured" and several `0x04` pages read "Several pages tagged 0x04, not decoded". Emergency systems and encryption keys (tag `0x10`) are never shown there and stay in the Hex tab. It sends no frames and adds no read: the page is already in the capture. Frame list: [protocol.md](../../reference/radios/baofeng/dm-32uv/protocol.md#debug-capture-allow-list).

The AT-D890UV profile captures sparse configuration and four separately requested vital units in a partial standard radio-backup archive. Occupancy-skipped records remain uncaptured; NXDN reads beyond the virtual map and unknown archive entries stay separate. Each vital unit is read twice and compared before a successful capture; the second tune request is shown as returned and is not an independent physical copy. Firmware can divert vital reads. Hashes identify the archived bytes, not physical storage. The same bytes, ranges, metadata and identity evidence are shown when the archive is reopened.

The debug session uses fixed 16-byte reads and sends no write commands. It checks LocalInfo flags before the bulk read and freshly again before END. A set or unreadable flag, failure or cancellation leaves END unsent; power-cycle the radio before continuing. The final check and END are not radio-side atomic. Captures can take time and are incomplete, not firmware images. The ident model, band code and protocol version and full LocalInfo serial are captured evidence; V100 does not identify running firmware. Missing markers do not prove stock. Firmware and mod remain unknown. Scan list and settings inventories remain unavailable. Hardware validation is separate.

The AT-D890UV Calibration tab is the shared Calibration tab over `atD890CalibrationView` (`at-d890uv/debugCalibrationView.ts`). It decodes only the live tune unit: the `vital-tune-a` entry requested at `0x04F00000`, inspect-only, with a manifest length matching its bytes. A wrong address, role, model or length is refused with a reason, and the as-returned tune B entry is never used in its place; an archive without the live unit shows "Not captured". The tab has the Read and Overlay pickers (tune A of a second retained read; tune B is never substituted), the "Not validated on hardware" notice and a facts line (region, captured length, V1.05 static-trace basis, byte order). Chart cards, two to a row: UHF power (400–520 MHz) and VHF/220 power (136–174 and 220–225 MHz) with Low, Mid, High and Turbo lines, UHF and VHF/220 squelch flatness with main and sub lines, and the oscillator trim on its 0–4000 editor scale with neutral 2000 and 0.0217 ppm a step. Each card has a one-line meaning, **About this chart** (index rule, sources, caveats) and one **Numeric table** (hex and decimal, with the difference from the reference entry); lines are visual guides only, and missing entries stay gaps. Below: power references (UHF and VHF/220 by level), squelch and meter references (UHF, VHF and 220 by main and sub), the other loaded fields and the loaded-but-never-read fields (both folded), unused ranges and the raw bytes (folded). A captured prefix decodes what it covers: partial fields are unavailable and missing entries are never bridged. 289 loaded bytes are named, 77 of them loaded but never read; 261,057 bytes the firmware never loads show as unused. Watts, dBm and Hz of deviation are unknown, and no limits or health verdicts are given. Field layout and sources: [calibration.md](../../reference/radios/anytone/at-d890uv/calibration.md).

The AT-D890UV Memory tab is a read-only viewer for MR channels and zones, decoded from the open archive without a project, library or build, and without importing anything. It accepts only recognised `sparse-<address>` configuration entries that are inspect-only, lie inside the memory map and whose stored bytes match the manifest length. Vital and unclassified entries are excluded; duplicate entries and entries that overlap another are refused whole, and each refusal is listed with its reason. Coverage is the bytes actually captured: adjacent entries jointly cover a span, but a gap or a truncated tail is never filled with default bytes. An inventory is listed only when its complete occupancy bitmap was captured; otherwise the panel says "Not captured", never zero entries. Channels keep their one-based slot numbers and need both record halves; an occupied slot with a missing half stays listed as "Not captured", and a captured record with no RX frequency is shown as an empty record, distinct from missing data. Each row shows identity, RX and TX, bandwidth, power, mode, tones, colour code and timeslot for digital modes, flags, and the TX contact, scan list and RX group references as unresolved numbers; no contact or group inventory is decoded. Each radio channel carries one name field, so that complete label (including any callsign) is shown, searched and sorted, and separate callsign and name data is unavailable. Zones keep their slot numbers, unnamed zones and member order including duplicates. A zone name and its member list are decoded independently, each only when its whole span was captured. A name ends at its first NUL or erased `0xFFFF` code unit. Each zero-based member index resolves to channel slot index plus one, and a member that is absent, not captured, unreadable, out of range or unresolvable because the channel bitmap is missing is shown with its own explanation. The zone A and B channel tables select a channel within a zone, are not member lists and are not shown. Counts use the hardware capacities (4,000 channels, 250 zones) and separate occupied slots from decoded ones; missing coverage does not imply unused capacity, and bitmap bits above the capacity are reported but not listed. The tables support search and temporary column sorting and default to slot order; there is no reorder, edit or permanent sort. Replacing the archive resets the rows, references and selected zone. Limitations: zone hide flags, NXDN channel fields, AM airband banks, scan lists, contacts, talk groups, RX groups and settings are not decoded; those sections read "Coming in a later piece". The decoders are verified against synthetic fixtures only, not hardware.

The DM-1701 and MD-9600 (OpenGD77) profiles capture through a guarded read-only session: ping, FirmwareInfo, the CPS screen command, the calibration working copy (16 reads of 32 bytes at `0x10000`, first after the CPS screen command), the settings struct tail (3 reads of 32 bytes at `0x6060`, debug-only), the four registered FLASH spans, the occupied User Database only when **Also read the User Database** is ticked on the Backup tab (unticked by default; unticked skips just that region), and the CPS close. Every frame is checked byte for byte against an allow-list before the transport; any refusal latches the session, and cancel sends only the CPS close. A radio whose type the profile does not accept stops after FirmwareInfo, before the CPS screen. The archive is a partial, inspect-only radio-backup zip with the raw FirmwareInfo reply as a sidecar, kept in the tab until downloaded, and it reopens offline with the same evidence. Identity shows only what FirmwareInfo reports (radio type, revision, build date, flash id, feature bits) and says so; there is no serial, radio type does not separate DM-1701 from RT-84 or MD-9600 from RT-90, and fork and mod stay unknown. Coverage lists the spans as captured, partial or missing, the gaps between them as not read, and the User Database as a packed header and entries, not contiguous flash (or Not captured when it was not ticked). It never claims a full flash image or firmware dump. Memory is Partial: a read-only viewer decodes the captured FLASH spans with the existing OpenGD77 codecs into Channels, Zones, Contacts, RX groups and the User Database. A bank (channel bank, zone bank, the 1024-slot contact bank, the RX group bank) is decoded only when every byte was captured, otherwise it reads "Not captured" (never an empty inventory); slots keep their one-based numbers; the same power step shows the DM-1701 or the MD-9600 ladder percent for the page's model. Contacts show call type (an unknown value is listed as Unknown with its raw value) and the raw time-slot byte. RX group members the product decoder cannot resolve are counted and listed as unresolved with a reason (contact bank not captured, or contact slot empty), never dropped. The User Database is shown as captured, with its header, true flash addresses (the archive stores it packed) and honest truncation reporting (a header count above the stored bytes or above the 520,646 product cap); it is paged at 100 rows and searched by DMR ID prefix or text with results capped at 200, so a very large database is never rendered whole. A read-only Settings tab decodes the firmware settings struct (59 members at flash `0x604B`; magic `0x4780` and the model are checked, and the data is labelled flash copy as of the last power-off or CPS save, or backup copy on the MD-9600) from the captured spans plus the debug-only tail `0x6060-0x60BF` (a current capture holds the whole struct; an older archive without the tail shows Not captured for the rest) and the codeplug device info and general settings, with confidence and source evidence per field and bytes nothing reads shown as unused (no reader). APRS, DTMF and the satellite bank are not decoded. Synthetic fixtures only, not hardware ([debug-memory.md](../../reference/radios/opengd77/debug-memory.md)). The Calibration tab (Partial, read-only, "Not validated on hardware") is the shared Calibration tab over `openGd77CalibrationView` (`opengd77/debugCalibrationView.ts`), with the Read and Overlay pickers. It decodes the 512-byte OpenGD77 working copy and always says "OpenGD77 working copy, not stock factory calibration" (plus, on the DM-1701, that the copy is scaled from the factory values at import and the very-low slot is synthesised), the layout basis, the radio's reported revision and whether the local marker at `0x1B0` is present. Per band (UHF, VHF) it draws chart cards for power (High, Mid, Low and the low slot, whose name follows the model: very-low on the DM-1701, mid-low on the MD-9600, each with its watt point), RX front-end tuning, squelch open and close at levels 1 and 9, and the oscillator tune as a trim (signed trim = byte - 128, ppm scale unknown), each with a Numeric table. The power and RX tuning charts draw x in MHz on the grids the firmware itself uses (UHF 400 to 480 MHz every 10 MHz; VHF power 135, 145, 155, 165, 175 MHz on the DM-1701 and 136, 145.5, 155, 164.5, 174 MHz on the MD-9600; VHF RX tuning 136, 145.5, 155, 164.5, 174 MHz, kept in `core/radios/opengd77/calibrationGrids.ts` with the source lines) and their Numeric tables list the point index with its MHz; the squelch chart keeps the point index (0 first) on x, because those stock rows have no reader and no stated grid, and the stock frequency-point table that would name each point's frequency is inferred and on UHF its first point is overwritten by the marker. Reference, CTCSS, DCS and gains are striped tables (UHF beside VHF), frequency points are a folded table in MHz, the 24 unnamed ranges read "not used by OpenGD77; stock meaning unknown", and the raw working copy is folded. With the marker absent there are no charts or decoded values, raw bytes only. It reads Refused with a reason when the archive does not identify the model (no FirmwareInfo, an invalid one, or a radio type that does not belong to the profile) or the region is malformed, and "not captured" for a Backup archive or an older read. An overlay read of a different model or marker state is not drawn and says why. No ranges or health verdicts are given. Both profiles keep every live read and opened archive in the shared tab-only history (separate per profile, labelled A, B, C...): select a read to drive Overview, Backup, Hex and Compare, download one archive or all as a history ZIP that reopens on the same Open archive control, clear with confirmation, and get Stay or Leave and reload warnings while reads are undownloaded. A read with the User Database ticked includes up to the whole database, so retaining several such reads uses a lot of tab memory (about 14 MB each at most). Compare takes a second retained read and compares matching `flash-span-N` bytes and the packed User Database (a longer database counts its tail as missing, not changed), then lists a decoded evidence diff of the FirmwareInfo fields, the User Database header and the calibration rows (Unavailable without a valid region and marker); invalid or missing sources are Unavailable, and there is no responding-unit or provenance verdict. Wire detail: [protocol.md](../../reference/radios/opengd77/protocol.md#debug-capture-allow-list), [debug-capture.md](../../reference/radios/opengd77/debug-capture.md).

## Tabs: Memory and Settings

The page's tab list comes from the radio's descriptor: Overview, Backup, Calibration, Memory, **Settings** (only for a radio whose descriptor has a Settings view), Hex, Compare, Trace.

**Memory** shows channels, zones, lists and contacts, one category at a time chosen from a **Category** dropdown (`MemoryCategories`; the last choice per radio is remembered in the browser under the app's `mm9pdy-codeplug-studio.` prefix, and the item count shows in the option where it is cheap, for example "Channels (42)"). The categories a radio does not decode are named in one dimmed line under the dropdown from its descriptor's `memoryNotDecoded` (RT95: scan lists, contacts, talk groups). Categories drawn by the shared `MemoryCategoryPanel` (count sentence, caveat folded after two lines behind **More**, search, sortable v2 table, details of the clicked row; sentences live in each radio home's `debugMemoryText.ts`, the Mini's in `uv5r-mini/debugRead/memoryText.ts`):

- Channels: RT95, UV-5R Mini, DM-32UV, AT-D890UV, OpenGD77. The RT95 table has no Occupancy column (its provenance is stated once in the caveat). The Mini panel has Slot, Identity, RX MHz, TX MHz and Bandwidth; click a row for tones and power.
- Zones: AT-D890UV and OpenGD77 (click a row for its members). Zones and Scan lists: DM-32UV.

Only the UV-5R Mini's Zones keeps its own panel; see Known gaps. The page works without browser storage.

**Settings** is a tab of its own for RT95, DM-32UV, AT-D890UV, OpenGD77 (DM-1701, MD-9600) and UV-5R Mini, shown when the descriptor has a `settings(archive)` function. The radio home builds a radio-neutral `SettingsView` (`dm32uv/`, `rt95/`, `at-d890uv/`, `opengd77/debugSettingsView.ts`, `uv5r-mini/debugRead/settingsView.ts`) and the shared `SettingsTab` and `SettingsTable` draw it: summary, intro, search, **Show raw bytes + address**, **Show password** only when a row is sensitive, one striped table per group with Setting, Value, optional Default and Confidence columns at the same widths in every group, trailing sections folded. A value that was not read says "Not captured" in Value, Address and Raw. Raw numbers show only behind **Show raw bytes + address**. Password fields stay masked until revealed.

- RT95: layout from CPS and/or CHIRP reads as partly traced, one source alone as inferred.
- AT-D890UV: registered fields take confidence and evidence from a debug-only map (`at-d890uv/debugSettingsConfidence.ts`, keyed by field id, sourced from the optional-settings reference page); named-byte rows keep theirs. Settings and Memory share one memoised decode, so it runs once per archive (also DM-32UV).
- UV-5R Mini: shows its Default column (the firmware default from the decoder) and puts its Address column behind the raw toggle, with the settings frame and VFO A and VFO B as separate groups.
- OpenGD77: the firmware settings struct and the codeplug device info, general settings and boot password groups, with the programming password and boot PIN as sensitive rows.

## Radio name, label and description

Each capture archive can carry the three optional descriptive fields of a radio backup (radio name, label, description; see [Backup / Restore](../radio-read-write/backup-restore.md#radio-name-label-and-description)). Type them above **Read radio** to stamp the next capture, or edit them under **Your notes on this capture** for the selected read or opened archive. In a shared read history, editing rewrites only that read's manifest and counts a live read as not downloaded again; the picker shows each read's letter, time, radio name and label so several radios' reads can be told apart, and the history ZIP and single downloads carry the fields. They are descriptive only and are never used to match or compare captures.

## Decisions

- One shared kit (`src/app/components/debug/`) draws every debug tab. Its components are named by use case and know no radio; each radio home builds plain view models.
- Number format follows the [debug pages styleguide](../../reference/styleguide/debug-pages.md#rules).
- The radio debug page is dark throughout, set by `DesignSystemV2Provider scheme="dark"` and the `AppLayout` dark-path flag.
- The Calibration **Read** pick is page-wide; **Overlay** applies to Calibration only.
- RT95 power is plotted as the drive the radio uses (row base plus entry minus reference). FQC trim is shown on its raw 0-255 scale, labelled "ppm scale unknown".
- OpenGD77 power and RX tuning are plotted in MHz from the traced per-model grids; squelch uses the point index, and the card says why.
- DM-32 squelch thresholds are plotted against the RX frequency points, an inferred pairing stated on the card.

## Known gaps

- UV-5R Mini: the Settings tab shows the settings and VFO frames decoded from the archive's decoded clone, on the shared table (the old `/debug/uv5r-mini` page keeps its own tables and is unchanged); an archive without a whole clone reads "not captured". The Mini has no password fields.
- RT95 calibration is not validated on hardware; the head may return stale or zero relay filler without a main-board reply.
- DM-32UV: editing or exporting settings, the digital address book (V-frame `0x0F`), MM9PDY location pages and other blocks outside the product read set, and the firmware build stamp are not captured or decoded yet. The capture is verified against synthetic sessions only, not hardware. Tracking: https://github.com/pskillen/codeplug-studio/issues/1698 (capture) and https://github.com/pskillen/codeplug-studio/issues/1751 (history and comparison).
- OpenGD77 (DM-1701, MD-9600): APRS, DTMF and additional-settings blocks, the satellite bank and the factory calibration compare are not decoded; the calibration layout comes from two source snapshots and is not hardware-validated ([#1716](https://github.com/pskillen/codeplug-studio/issues/1716)); the factory security-register data is not read; the capture is verified against synthetic sessions only, not hardware. A full User Database read can be up to about 14 MB and takes a long time; it is opt-in per read.
- Other profiles await read-only adapter verification. Coverage classifications and decoded inventories for other radios await their capture and hydration adapters. The current clone summary does not provide callsigns or zone membership relationships.
- Mini parity tests, then redirecting `/debug/uv5r-mini` to the shared page — [#1747](https://github.com/pskillen/codeplug-studio/issues/1747).
- UV-5R Mini Zones still draws its own table rather than `MemoryCategoryPanel` (the Mini's zone view stays with the old page until it retires). Every other Memory category on the RT95, AT-D890UV, DM-32UV and OpenGD77 now uses the shared panel. The OpenGD77 User Database keeps its opt-in, paged, whole-database search form; the panel's own search box beside it only filters the page on screen.
- AT-D890UV Settings confidence is from the reference page and the V1.05 decompile, not a radio: menu-list-only and CPS-only fields read partially traced until a trace or radio check is cited — [#1861](https://github.com/pskillen/codeplug-studio/issues/1861).
- Open label questions: the RT95 FQC ppm scale and neutral, whether the DM-32 has a trim, whether the D890 has battery thresholds, and the Mini PA bias units — [#1692](https://github.com/pskillen/codeplug-studio/issues/1692).

RT95 and Mini keep each successful read and opened archive in separate per-profile histories in the current tab. Select a labelled capture to update the viewers; download one archive or download all as a versioned history ZIP, which can be reopened alongside single archives and legacy Mini ZIPs. Imports are validated before anything is added. Clear history explicitly removes the tab's references and selections. Leaving with undownloaded reads offers Stay or Leave; reload or close warns while any shared history has undownloaded reads. Navigation alone does not clear them. History is never persisted or uploaded, and tab closure, reload or process termination loses it. Retaining reads and generating ZIPs consumes tab memory.

RT95 debug reads also probe the chip guard and, when it passes, capture the inspect-only MMD1 table. The Memory tab shows zones and independently validated state even when clone details are unavailable. Probe bytes and outcome travel with the archive; the viewer rechecks them. See the [RT95 debug memory reference](../../reference/radios/retevis/rt95/debug-memory.md). The head can return checksum-valid zeros without a body reply; firmware and full physical coverage remain unknown.

D890 captures and opened archives remain in the tab history across navigation. Download individual captures or the history ZIP before closing or reloading; retained archives and overlays consume tab memory. The Calibration tab can overlay a second retained tune-A capture; tune-B is never substituted. Comparison checks the versioned acquisition claim against stored ranges, keeps sparse data and each requested vital unit separate, and compares captured intersections even when sparse boundaries differ. Missing or ambiguous bytes are incomparable. Byte divergence is paged both per range and as every changed byte run with before and after values. Provenance divergence (differing acquisition claims) is listed separately from byte divergence. A same or different responding-unit verdict appears only when both archives explicitly name a responding unit for that range; otherwise it reads Unknown, even for identical bytes, equal serials or a matching repeat read. Current reads never write such evidence: firmware may divert reads, and repeat agreement does not establish unit identity or calibration validity, so verdicts only ever echo an archive claim. Older captures without the acquisition claim are refused for byte comparison, but decoded differences still show. Decoded differences reuse the Memory and Calibration decoders: channels, zones, contacts and talk groups, RX groups and scan lists are matched by radio slot, settings and calibration by field. Additions and removals are reported only when both captures have their occupancy bitmap; a record or field not captured on one side is unavailable, never zero or deleted, and entries not captured on either side are counted rather than listed. Member lists keep order and duplicates and raw references; unsupported setting values stay raw. The comparison and overlay selection is part of the tab history, so it survives navigation and is cleared with the history. Each range row shows both captures' requested unit, responding-unit claim and own repeat-read claim; sparse ranges beyond the real memory map are listed as unclassified and never compared. Changed runs keep every byte, shown in pages. Diffed settings keep their firmware-dependent meaning caveats, and an unavailable field shows the captured value and which capture lacks it. Overlay tables show differences only where both values are available. See the [acquisition provenance sidecar](../../reference/radios/anytone/at-d890uv/read-provenance.md).

DM-32 stock and MM9PDY reads share an in-tab history. Reads remain available across navigation until cleared, reloaded or the tab closes; undownloaded reads trigger navigation and reload warnings. Download archive saves the selected read and Download all saves a ZIP that can be reopened; either marks only the reads that were selected or present when the download began, and only after it succeeds. Clearing requires confirmation. Retaining captures and generating ZIPs consumes tab memory; Android process termination also loses the history. Comparison uses captured identity, calibration and factory evidence; a page address is not itself reported as a change, and sparse runs with different partitions may be incomparable. The Memory tab shows channels, zones, scan lists, talk groups, RX groups, radio IDs, contacts and settings; the calibration overlay and memory diffs remain future work.

### Compare: the byte model and per-radio adapters

Compare's byte diff is radio-neutral and lives in `src/integrations/radio-io/debugCompare/`: `diffBytes` (changed runs at absolute addresses, a length gap counted as missing and never changed, runs capped at 10,000 per section with exact counts kept), `regionSections` (a region is compared only when both sides name it at the same address with the same established address space and representation; models that differ are refused) and `compareVerdict` (only `compared` sections decide; `reported` and `skipped` ones do not; nothing compared is never "identical"). Each radio supplies a `compare` adapter on its descriptor, in its radio home: the region identity functions (RT95, DM-32, OpenGD77), the UV-5R Mini runbook sections (spans and calibration compared, the VFO and settings frames reported, the four log sectors skipped) and the AT-D890UV acquisition spans (one section per span; unclassified or ambiguous spans incomparable). Every radio with a capture (RT95, DM-32UV, OpenGD77, AT-D890UV, UV-5R Mini) uses the shared summary and hex diff below.

**Picking A and B.** Every radio with a capture keeps a read history (`readHistory` on its descriptor), and its Compare tab starts with two selects, **Compare A** and **Compare B**, over that history plus a **Swap A and B** button (`ComparePicker`). By default A is the previous read and B the latest; a pick stays through new reads and navigation, and a read that leaves the history sends its side back to the default. The pair is stored in the history apart from the calibration overlay pick, so choosing one never changes the other. With fewer than two reads the tab says so and offers **Open archive** (opened files join the history); the same read on both sides shows a notice and no compare. Above the pickers a **read-to-read strip** (`compare/ReadStrip`) gives one line per read after the first, each against the read before it: `B = A, identical` (green) or `E ≠ D, 3 bytes` (amber), grey for nothing comparable. It uses the radio's byte adapter and the same verdict as the banner, and clicking a line sets A and B to that pair.

**Summary and hex diff** (every capture radio; `compare/RadioCompare`). Under the pickers the tab opens with a verdict banner: green **Identical** ("A and B match in every compared region", with N regions and X bytes, and the list of what was not compared), amber **A and B differ** (changed bytes, regions, and bytes present on one side only) or grey **Nothing comparable**, never green. Only `compared` sections decide the verdict. A **Bytes by region** table lists region, range, kind, and result (green _identical_, amber _N bytes_, grey for skipped or incomparable); an amber row lists its changed 16-byte row addresses (first 32, then "+N more") with a Copy button, and choosing a row sets the hex diff to that region, filtered to its changes, and scrolls to it. Provenance tags (RT95 `[body]`, `[unknown]`) show once per region, not per line. The **Hex diff** shows A over B in 16-byte rows on absolute boundaries (the first and last rows of a region may be short) with changed bytes marked in amber and bold, plus a count column (`3≠`) so colour is not the only cue. **Only changed rows** is on by default when the region differs, with 0, 1, 2 or 4 **context rows** (default 1) and "… 0x0100–0x01FF identical (16 rows)" separators, 20 hunks to a page; turned off it pages the whole region 256 bytes at a time. **Previous change** and **Next change** step through changed rows, and **Go to address** opens the full view at that address. When one side is longer the longer tail is stated once ("B has no bytes after 0x…", counted as missing, not changed). Masked password bytes stay `••` on both sides but a byte that differs is still marked and the row says "[masked bytes differ]"; one **Show password** toggle covers the tab and hides the values again whenever A or B changes. The decoded changes for every radio render below in the shared decoded view (next section). On the UV-5R Mini the verdict keeps the runbook meaning: the four log sectors are skipped, the VFO and settings frames are reported without deciding, so a read that differs only in a log sector is still green. On the AT-D890UV the **Responding unit unknown** notice stays, and below the hex diff a provenance panel lists each acquisition range's claims and responding-unit verdict (Same or Different only when both archives name a unit), the differing claims, ; the panel and decoded changes show even when the acquisition claim is refused (the byte compare then says so). A long run of changed rows is split into short chunks so a whole-image difference pages instead of rendering thousands of rows.

### Decoded compare

The same module holds the decoded diff model, and `compare/DecodedDiffView` shows it on the Compare tab for every radio whose adapter has `decoded` (RT95, UV-5R Mini, DM-32UV, AT-D890UV, DM-1701 and MD-9600: every radio uses the same compare, with no radio-specific decoded views). The view has a **Category** select (All plus the adapter's domains) and **Only changes** (on by default). Each changed record is a block headed `Slot N · identity` (callsign first, then name; a rename reads `(was …)`; the RT95, Mini and DM-32 records have no callsign, so the name shows alone) with a kind badge (amber _changed_, teal _added_, red _removed_, grey _not comparable_) and a `Field | A | B` table; changed cells are marked, a value the capture lacks reads _Not captured_, and a changed password reads _changed_ with no values until **Show password** (the same toggle as the hex diff). Only changes off lists every record with every field, 30 at a time. The summary banner adds a **Fields by category** table (changed fields, changed, added, removed and not-comparable records); choosing a category jumps to the view filtered to it.

The model sits beside the byte model. An adapter's optional `decoded(archive)` returns a `DecodedSnapshot`: domains (channels, zones, settings, calibration) of records matched by a stable `key`, each with fields whose `value` is undefined when not captured. `diffDecoded(a, b)` returns per-domain counts and one `RecordDiff` per record (changed, added, removed, unchanged or incomparable). A field without a value on a side is incomparable, never zero. Added and removed need both captures to say which records exist (`occupancyCaptured`); otherwise a record is incomparable. A `sensitive` field (a password) reads changed without exposing either value unless the caller passes `revealSensitive`. The RT95 adapter decodes channels (radio name, then description; the RT95 record has no callsign), zones (members by slot, when MMD1 and the chip guard evidence hold), settings and calibration. The UV-5R Mini adapter decodes channels (each field as its masked bytes, so unmodelled bits show up; slots 248 and 249 keep their caveat), zones, the settings and VFO frames, and calibration. The DM-32 adapter (`dm32uv/debugCompareDecoded.ts`) decodes an identity and calibration evidence domain (the same fields and unavailable rule as the older evidence list), channels (the single radio name; the record has no callsign), zones and scan lists (members by channel slot), talk groups, RX groups and settings, where the three passwords are sensitive. Talk groups never report added or removed while overflow pages (tags 0x45-0x48) exist, since those are not decoded; analogue contacts and radio IDs are not yet decoded.
The AT-D890UV adapter (`atD890DecodedDiff.ts`, an app per-radio file because it needs `selectAtD890TuneRegion`) decodes the same rows as the older D890 diff as domains: evidence and provenance (the archive's acquisition claims per read range, never proof of the responding unit), channels, zones, contacts and talk groups, RX groups, scan lists, settings (the power-on and program and band-settings passwords are sensitive) and calibration (live tune unit A only). The OpenGD77 adapter (`opengd77/debugCompareDecoded.ts`, DM-1701 and MD-9600) decodes identity and User Database header evidence, channels, zones, contacts, RX groups, firmware and codeplug settings (`prgPwd` and the boot PIN are sensitive) and the calibration working copy. Neither the OpenGD77 channel nor the contact record has a callsign, so only the name shows; a User Database that was not captured reads unavailable, not zero. The D890's own panel (`AtD890Compare`, the descriptor's `CompareExtra`) now holds only the acquisition ranges and provenance divergence; its decoded rows, and the old OpenGD77 evidence list, are gone in favour of the shared view. A category whose domain was not captured on a side (for example RT95 Zones without MMD1) reads _not captured_ in Fields by category, never 0. Adapter `notes` (the D890's responding-unit limits) render once, collapsed, above the summary. With fewer than two reads, or the same read on both sides, only the picker speaks; the compare body adds nothing. A refused D890 byte compare (missing claim) shows the single "Cannot compare" alert and still the decoded changes.

### Passwords: the sensitive-range hook

Which bytes are secret is a radio-home fact: a descriptor's `sensitiveRanges(archive, regionId)` (`descriptors.ts`) calls a function in the radio's integration module (RT95, DM-32, OpenGD77 and AT-D890UV; the others have none yet). OpenGD77 (DM-1701, MD-9600) masks the CPS programming password `prgPwd` (`0x100`) and the boot PIN (`0x751C`, packed BCD, evidence: firmware source, DM-1701 tree; MD-9600 layout unconfirmed); its Settings tab decodes both behind **Show password**, and Hex, Compare and the RT95 calibration view mask what it returns until **Show password**. AT-D890UV masks the power-on password (ext optional settings `+0x40`, 8 ASCII digits) and the decode program (LocalInfo `+0x28`) and band-settings (LocalInfo `+0x0B`) passwords, 4 ASCII characters each; its Settings tab shows all three in Privacy / lock as `Hidden (password)` with `••` raw bytes until **Show password**, and Hex and Compare mask the same bytes. The D890 Compare masks them in the shared hex diff (a masked byte that differs is marked and the row says "[masked bytes differ]") and hides the power-on password's values in its decoded differences until **Show password**. Hex also masks the same LocalInfo offsets (`+0x0B`, `+0x28`) inside the `vital-tune-b` and `vital-local-info-upper` units, in case they mirror LocalInfo; unconfirmed, no real read has been checked. The shared Compare byte table (RT95, DM-32, OpenGD77) takes each side's ranges from that side's own archive and region (the D890 sections carry a region id per side, since two reads can chunk one span into differently named regions) and marks a row "[masked bytes differ]" when hidden password bytes differ, never showing the values. No radio literal lives in the shared viewer files. Masking is display-only.
