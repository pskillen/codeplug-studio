# Radio debug

**Status:** In progress · **Tracking:** https://github.com/pskillen/codeplug-studio/issues/1692

The Debug hierarchy groups radio profiles, browser storage and serial transport tools. Debug pages are gated on production by developer mode. The selected radio profile is an expectation; it does not identify the connected radio or its firmware.

## Behaviour

The radio profile shells can open compatible radio-backup ZIPs without a library or build. The Backup tab lists the archive’s named ranges and sidecars and can download the original archive. Gaps between listed numeric ranges are unclassified because entries may use different address spaces; the archive does not establish completeness outside its entries. An invalid or incompatible file leaves the current archive in place. Archive identity fields are reported as archive evidence, not live radio identity. The RT95 profile can make a live read using the existing Backup reader behind a read-only frame allow-list; the resulting archive stays in the tab until downloaded. The RT95 programming-image range is classified against its known clone map and a complete image has a channel summary. Coverage shows SHA-256 hashes for captured regions and classifies the RT95 programming image against its known map. Other address spaces remain unclassified. The Hex tab pages through captured regions. Memory shows RT95 channel slots and settings when a complete programming image is available. Compare opens a second archive and compares RT95 programming image bytes and decoded channel names and settings; regions with unknown address space or representation are incomparable, as are missing bytes. Trace export and other live capture adapters remain unavailable. The existing UV-5R Mini read and AT-D890UV erase-unit probe remain separate tools; the latter can write during erase passes. IndexedDB inspection is read-only; local storage permits deleting individual keys. Serial reopen sends test bytes and requires a cable without a radio attached. Legacy storage and transport links redirect to the new hierarchy, retaining path parameters, query and hash.

The UV-5R Mini profile can capture the clone address space through the guarded read-only session. Its archive stores decoded clone bytes and preserves wire bytes and F/M replies as sidecars. The clone address space is not a physical flash or firmware dump. Ordinary Mini backup MEM entries use packed offsets; coverage maps these to their radio addresses and preserves a separate zones entry. Calibration is only captured when its actual range is present. A validated live format-2 MM9R report is compatible report evidence; an absent, invalid or unsupported report, and an archive without live provenance, leave firmware identity unknown. The shared page shows decoded span hashes, wire and decoded hex, tab-local history, calibration and comparisons for complete captures. It can open the legacy multi-read ZIP and display channels and zones when their required bytes are present. The legacy Mini debug page remains available while shared-page parity is verified ([#1747](https://github.com/pskillen/codeplug-studio/issues/1747)).

The AT-D890UV profile captures sparse configuration and four separately requested vital units in a partial standard radio-backup archive. Occupancy-skipped records remain uncaptured; NXDN reads beyond the virtual map and unknown archive entries stay separate. Each vital unit is read twice and compared before a successful capture; the second tune request is shown as returned and is not an independent physical copy. Firmware can divert vital reads. Hashes identify the archived bytes, not physical storage. The same bytes, ranges, metadata and identity evidence are shown when the archive is reopened.

The debug session uses fixed 16-byte reads and sends no write commands. It checks LocalInfo flags before the bulk read and freshly again before END. A set or unreadable flag, failure or cancellation leaves END unsent; power-cycle the radio before continuing. The final check and END are not radio-side atomic. Captures can take time and are incomplete, not firmware images. The ident model, band code and protocol version and full LocalInfo serial are captured evidence; V100 does not identify running firmware. Missing markers do not prove stock. Firmware and mod remain unknown. Memory inventories remain unavailable. Hardware validation is separate.

The AT-D890UV Calibration tab decodes only the live tune unit: the `vital-tune-a` entry requested at `0x04F00000`, inspect-only, with a manifest length matching its bytes. A wrong address, role, model or length is refused with a reason, and the as-returned tune B entry is never used in its place; an archive without the live unit shows "Not captured". The tab shows the requested address, captured length, the V1.05 static-trace basis and "Not validated on hardware". Trim, squelch and meter references (16-bit, little-endian assumed), power references, power tables and squelch-flatness tables are listed with offsets, raw and decoded values, sources and separate layout and meaning confidence. Tables are charted against their index, with lines as visual guides only, and listed numerically with each entry's difference from the reference entry. A captured prefix decodes what it covers: partial fields are unavailable, missing table entries stay missing and charts never bridge them. Every other byte stays unknown and is shown in paged raw hex. No physical units, limits or health verdicts are given. Field layout and sources: [calibration.md](../../reference/radios/anytone/at-d890uv/calibration.md).

## Known gaps

- Other profiles await read-only adapter verification. Coverage classifications and decoded inventories for other radios await their capture and hydration adapters. The current clone summary does not provide callsigns or zone membership relationships.
- Mini parity tests, then redirecting `/debug/uv5r-mini` to the shared page — [#1747](https://github.com/pskillen/codeplug-studio/issues/1747).
