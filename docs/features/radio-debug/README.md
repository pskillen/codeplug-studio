# Radio debug

**Status:** In progress · **Tracking:** https://github.com/pskillen/codeplug-studio/issues/1692

The Debug hierarchy groups radio profiles, browser storage and serial transport tools. Debug pages are gated on production by developer mode. The selected radio profile is an expectation; it does not identify the connected radio or its firmware.

## Behaviour

RT95 debug captures include the clone programming image and a separate inspect-only main-body EEPROM prefix relayed via the head. PC ident is head evidence; clone channel and settings storage is unknown. See the [RT95 calibration reference](../../reference/radios/retevis/rt95/calibration.md) for coverage and limits. The Calibration tab shows captured fields and raw bytes; old archives show Not captured and malformed regions are refused. Values carry [head], [body] or [unknown] provenance tags.

The radio profile shells can open compatible radio-backup ZIPs without a library or build. The Backup tab lists the archive’s named ranges and sidecars and can download the original archive. Gaps between listed numeric ranges are unclassified because entries may use different address spaces; the archive does not establish completeness outside its entries. An invalid or incompatible file leaves the current archive in place. Archive identity fields are reported as archive evidence, not live radio identity. The RT95 profile can make a live read using the existing Backup reader behind a read-only frame allow-list; the resulting archive stays in the tab until downloaded. The RT95 programming-image range is classified against its known clone map and a complete image has a channel summary. Coverage shows SHA-256 hashes for captured regions and classifies the RT95 programming image against its known map. The RT95 EEPROM prefix is classified separately from clone offsets. Other address spaces remain unclassified. The Hex tab pages through captured regions. Memory shows RT95 clone slots and retained settings from available captured bytes, including raw record details and unavailable fields. Compare opens a second archive and compares matching RT95 programming-image and EEPROM bytes and decoded channel names and settings; regions with unknown address space or representation are incomparable, as are missing bytes. Trace export and other live capture adapters remain unavailable. The existing UV-5R Mini read and AT-D890UV erase-unit probe remain separate tools; the latter can write during erase passes. IndexedDB inspection is read-only; local storage permits deleting individual keys. Serial reopen sends test bytes and requires a cable without a radio attached. Legacy storage and transport links redirect to the new hierarchy, retaining path parameters, query and hash.

The UV-5R Mini profile can capture the clone address space through the guarded read-only session. Its archive stores decoded clone bytes and preserves wire bytes and F/M replies as sidecars. The clone address space is not a physical flash or firmware dump. Ordinary Mini backup MEM entries use packed offsets; coverage maps these to their radio addresses and preserves a separate zones entry. Calibration is only captured when its actual range is present. A validated live format-2 MM9R report is compatible report evidence; an absent, invalid or unsupported report, and an archive without live provenance, leave firmware identity unknown. The shared page shows decoded span hashes, wire and decoded hex, tab-local history, calibration and comparisons for complete captures. Archives opened from Compare enter the same tab-local history as other imports, are available to the other viewers, and are included in Download all reads. It can open the legacy multi-read ZIP and display channels and zones when their required bytes are present. The legacy Mini debug page remains available while shared-page parity is verified ([#1747](https://github.com/pskillen/codeplug-studio/issues/1747)).

The DM-32UV profile (stock / MM9PDY) captures the configuration window through a guarded read-only session and makes a partial standard radio-backup archive. It reads exactly the blocks the product Read reads; other blocks the radio reports are listed as discovered but not read, with their tags. The factory sector is kept only when both reads match and is shown as its own address space. Every frame is checked against an allow-list before the transport and the session runs one frame at a time; any refusal, failure or cancellation stops it with no retry. There is no END command: the radio leaves PROGRAM mode after about 2 seconds of silence, so wait a few seconds, or power-cycle the radio, before using it. A factory-sector mismatch keeps nothing and the capture continues; a malformed factory-sector reply, a missing V-frame `0x0A`, a bad reply, a timeout or a short read fails the capture with no archive. Coverage lists every 4 KiB window block as captured, discovered but not read, or not discovered, with its tag and live or duplicate calibration role; a build Backup archive classifies the same way, with discovery not recorded. Identity shows the PSEARCH model and V-frame replies as returned. V01 is the stock base version and does not identify a mod. The radio has no readable serial, and the V02 chip UID is not a serial. "MM9PDY-compatible data present" appears only for a decodable channel location page, which is persistent data, not running firmware. Running firmware and mod stay unknown. Calibration and Memory are not yet available for this profile. Frame list: [protocol.md](../../reference/radios/baofeng/dm-32uv/protocol.md#debug-capture-allow-list).

The AT-D890UV profile captures sparse configuration and four separately requested vital units in a partial standard radio-backup archive. Occupancy-skipped records remain uncaptured; NXDN reads beyond the virtual map and unknown archive entries stay separate. Each vital unit is read twice and compared before a successful capture; the second tune request is shown as returned and is not an independent physical copy. Firmware can divert vital reads. Hashes identify the archived bytes, not physical storage. The same bytes, ranges, metadata and identity evidence are shown when the archive is reopened.

The debug session uses fixed 16-byte reads and sends no write commands. It checks LocalInfo flags before the bulk read and freshly again before END. A set or unreadable flag, failure or cancellation leaves END unsent; power-cycle the radio before continuing. The final check and END are not radio-side atomic. Captures can take time and are incomplete, not firmware images. The ident model, band code and protocol version and full LocalInfo serial are captured evidence; V100 does not identify running firmware. Missing markers do not prove stock. Firmware and mod remain unknown. Scan list and settings inventories remain unavailable. Hardware validation is separate.

The AT-D890UV Calibration tab decodes only the live tune unit: the `vital-tune-a` entry requested at `0x04F00000`, inspect-only, with a manifest length matching its bytes. A wrong address, role, model or length is refused with a reason, and the as-returned tune B entry is never used in its place; an archive without the live unit shows "Not captured". The tab shows the requested address, captured length, the V1.05 static-trace basis and "Not validated on hardware". Trim, squelch and meter references (16-bit, little-endian assumed), power references, power tables and squelch-flatness tables are listed with offsets, raw and decoded values, sources and separate layout and meaning confidence. Tables are charted against their index, with lines as visual guides only, and listed numerically with each entry's difference from the reference entry. A captured prefix decodes what it covers: partial fields are unavailable, missing table entries stay missing and charts never bridge them. Every other byte stays unknown and is shown in paged raw hex. No physical units, limits or health verdicts are given. Field layout and sources: [calibration.md](../../reference/radios/anytone/at-d890uv/calibration.md).

The AT-D890UV Memory tab is a read-only viewer for MR channels and zones, decoded from the open archive without a project, library or build, and without importing anything. It accepts only recognised `sparse-<address>` configuration entries that are inspect-only, lie inside the memory map and whose stored bytes match the manifest length. Vital and unclassified entries are excluded; duplicate entries and entries that overlap another are refused whole, and each refusal is listed with its reason. Coverage is the bytes actually captured: adjacent entries jointly cover a span, but a gap or a truncated tail is never filled with default bytes. An inventory is listed only when its complete occupancy bitmap was captured; otherwise the panel says "Not captured", never zero entries. Channels keep their one-based slot numbers and need both record halves; an occupied slot with a missing half stays listed as "Not captured", and a captured record with no RX frequency is shown as an empty record, distinct from missing data. Each row shows identity, RX and TX, bandwidth, power, mode, tones, colour code and timeslot for digital modes, flags, and the TX contact, scan list and RX group references as unresolved numbers; no contact or group inventory is decoded. Each radio channel carries one name field, so that complete label (including any callsign) is shown, searched and sorted, and separate callsign and name data is unavailable. Zones keep their slot numbers, unnamed zones and member order including duplicates. A zone name and its member list are decoded independently, each only when its whole span was captured. A name ends at its first NUL or erased `0xFFFF` code unit. Each zero-based member index resolves to channel slot index plus one, and a member that is absent, not captured, unreadable, out of range or unresolvable because the channel bitmap is missing is shown with its own explanation. The zone A and B channel tables select a channel within a zone, are not member lists and are not shown. Counts use the hardware capacities (4,000 channels, 250 zones) and separate occupied slots from decoded ones; missing coverage does not imply unused capacity, and bitmap bits above the capacity are reported but not listed. The tables support search and temporary column sorting and default to slot order; there is no reorder, edit or permanent sort. Replacing the archive resets the rows, references and selected zone. Limitations: zone hide flags, NXDN channel fields, AM airband banks, scan lists, contacts, talk groups, RX groups and settings are not decoded; those sections read "Coming in a later piece". The decoders are verified against synthetic fixtures only, not hardware.

The TX contact resolves against the captured contact bank slot (already one-based, never by DMR ID) and reads as the slot with its identity and call type, or as absent, not captured, unreadable, out of range or unresolvable when the bank bitmap is missing. Contacts and Talk groups share one 10,000-slot bank, decoded from the inverted `TalkgroupSet` bitmap only when all of it was captured, with bits above the capacity reported but not decoded. Contacts are private-call records; Talk groups are group and all-call records. A record is classified only when its complete `0xC8` span is captured, its DMR ID is decimal BCD and its call type is 0, 1 or 2; a not-captured, malformed or unknown-type slot stays listed, labelled unclassified, in both tabs and is never counted as an empty contact or talk group. Each row shows slot, DMR ID, type, callsign then name, and city. Talk groups add a Referenced by column listing only captured channel TX contacts and RX group members, labelled partial when channel or RX group coverage is incomplete. The separate DMR ID database is outside the accepted capture map and is not decoded. RX groups decode occupancy against 250 lists, the name and the up-to-64 member indices independently (stored positions, order and duplicates kept; empty `0xFFFFFFFF` positions skipped), resolve each member to bank slot index plus one, and show TS1/TS2 overrides only when the tail bytes were captured. Counts use the hardware capacities (4,000 channels, 250 zones, 10,000 bank slots, 250 RX groups) and separate occupied slots from decoded ones; missing coverage does not imply unused capacity, and bitmap bits above the capacity are reported but not listed. The tables support search and temporary column sorting and default to slot order; there is no reorder, edit or permanent sort. Replacing the archive resets the rows, references and selected zone or RX group. Limitations: zone hide flags, NXDN channel fields, AM airband banks, scan lists and settings are not decoded; those sections read "Coming in a later piece". The decoders are verified against synthetic fixtures only, not hardware.

## Known gaps

- RT95 calibration is not validated on hardware; the head may return stale or zero relay filler without a main-board reply.

- DM-32UV: calibration and memory viewers, the digital address book (V-frame `0x0F`), MM9PDY location pages and other blocks outside the product read set, and the firmware build stamp are not captured or decoded yet. The capture is verified against synthetic sessions only, not hardware. Tracking: https://github.com/pskillen/codeplug-studio/issues/1698
- Other profiles await read-only adapter verification. Coverage classifications and decoded inventories for other radios await their capture and hydration adapters. The current clone summary does not provide callsigns or zone membership relationships.
- Mini parity tests, then redirecting `/debug/uv5r-mini` to the shared page — [#1747](https://github.com/pskillen/codeplug-studio/issues/1747).

RT95 and Mini keep each successful read and opened archive in separate per-profile histories in the current tab. Select a labelled capture to update the viewers; download one archive or download all as a versioned history ZIP, which can be reopened alongside single archives and legacy Mini ZIPs. Imports are validated before anything is added. Clear history explicitly removes the tab's references and selections. Leaving with undownloaded reads offers Stay or Leave; reload or close warns while any shared history has undownloaded reads. Navigation alone does not clear them. History is never persisted or uploaded, and tab closure, reload or process termination loses it. Retaining reads and generating ZIPs consumes tab memory.

RT95 debug reads also probe the chip guard and, when it passes, capture the inspect-only MMD1 table. The Memory tab shows zones and independently validated state even when clone details are unavailable. Probe bytes and outcome travel with the archive; the viewer rechecks them. See the [RT95 debug memory reference](../../reference/radios/retevis/rt95/debug-memory.md). The head can return checksum-valid zeros without a body reply; firmware and full physical coverage remain unknown.

D890 captures and opened archives remain in the tab history across navigation. Download individual captures or the history ZIP before closing or reloading; retained archives and overlays consume tab memory. The calibration viewer can overlay a second retained tune-A capture; tune-B is never substituted. Comparison checks the versioned acquisition claim against stored ranges, keeps sparse data and each requested vital unit separate, and compares captured intersections even when sparse boundaries differ. Missing or ambiguous bytes are incomparable. Byte divergence is paged both per range and as every changed byte run with before and after values. Provenance divergence (differing acquisition claims) is listed separately from byte divergence. A same or different responding-unit verdict appears only when both archives explicitly name a responding unit for that range; otherwise it reads Unknown, even for identical bytes, equal serials or a matching repeat read. Current reads never write such evidence: firmware may divert reads, and repeat agreement does not establish unit identity or calibration validity, so verdicts only ever echo an archive claim. Older captures without the acquisition claim are refused for byte comparison, but decoded differences still show. Decoded differences reuse the Memory and Calibration decoders: channels, zones, contacts and talk groups, RX groups and scan lists are matched by radio slot, settings and calibration by field. Additions and removals are reported only when both captures have their occupancy bitmap; a record or field not captured on one side is unavailable, never zero or deleted, and entries not captured on either side are counted rather than listed. Member lists keep order and duplicates and raw references; unsupported setting values stay raw. The comparison and overlay selection is part of the tab history, so it survives navigation and is cleared with the history. Each range row shows both captures' requested unit, responding-unit claim and own repeat-read claim; sparse ranges beyond the real memory map are listed as unclassified and never compared. Changed runs keep every byte, shown in pages. Diffed settings keep their firmware-dependent meaning caveats, and an unavailable field shows the captured value and which capture lacks it. Overlay tables show differences only where both values are available. See the [acquisition provenance sidecar](../../reference/radios/anytone/at-d890uv/read-provenance.md).

DM-32 stock and MM9PDY reads share an in-tab history. Reads remain available across navigation until cleared, reloaded or the tab closes; undownloaded reads trigger navigation and reload warnings. Download all saves a ZIP that can be reopened, and clearing requires confirmation. Retaining captures and generating ZIPs consumes tab memory; Android process termination also loses the history. Comparison uses captured identity, calibration and factory evidence; sparse runs with different partitions may be incomparable. Calibration overlay and channel, zone and settings viewers and diffs remain future work.
