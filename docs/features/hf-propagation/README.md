# HF/RF propagation visualiser

Tier-1 hub for the **Propagation Visualiser** — an interactive 3D globe (plus 2D top-down and vertical cross-section views) that lets an operator place an idealised HF transmitter (antenna type, power, frequency, location) and see where the signal actually goes: groundwave footprint, skywave skip zones and hop landing points, and NVIS coverage, shaped by day/night ionospheric state and solar activity. A planning/teaching tool, not a coverage guarantee.

**Tracking:** Epic [#1162](https://github.com/pskillen/codeplug-studio/issues/1162) (child of Milestone 2 [#495](https://github.com/pskillen/codeplug-studio/issues/495))
**Navigation:** reached from the Tools strip (`Tools → Propagation Visualiser`, `/reference/rf-propagation`), reachable with **no active project** — like Maidenhead locator and Band plan, unlike the project-scoped Tracking Dashboard. The Tools entry is hidden on prod builds; the route remains.
**Components:** [HfPropagationGlobe](../../../src/app/components/HfPropagationGlobe/HfPropagationGlobe.md), [PropagationTopDownMap](../../../src/app/components/PropagationTopDownMap/PropagationTopDownMap.md), [PropagationVerticalSlice](../../../src/app/components/PropagationVerticalSlice/PropagationVerticalSlice.md)

## Concepts

- **Client-only, independent of the library** — reachable at `/reference/rf-propagation` with **no active project**; the page's control state (`HfPropagationPage`) is local `useState`, with no dependency on `useProjects`, `useLibrary`, or `ProjectPersistence`. Orbital/RF math runs entirely in the browser once later phases add it; no Studio backend.
- **Single-vertical-plane ray tracing in v1** — the traced path is one bearing at a time, not a full elevation×azimuth sweep; this applies across the 3D globe, top-down, and vertical-slice views alike. Full-azimuth coverage (the true 3D lobe for directional antennas) is a credible future epic, not part of this one.
- **Core domain scaffold** — `src/core/domain/hfPropagation/` holds `AntennaPatternFamily`, `AntennaConfig`, `SolarActivityPreset`, `IonosphericLayerState`, `PropagationMode`, `RayTraceParams`, and `RayPathResult`. `computeIonosphericLayers` produces TX-local D/E/F1/F2 state for the Reading-panel fc (and ray tracing); the globe shaders apply the same day/night bands spatially from the subsolar point. `criticalFrequencyMhz` drives the fc readout; MUF is `maximumUsableFrequencyMhz` at the antenna's peak-gain takeoff angle. `antennaGain` / `wavelengthM` implement the four closed-form pattern families (relative weight in `[0, ~2]`, not dBi). `traceRay` / `traceRayFan` classify a single vertical plane as groundwave / skywave / NVIS / escaped / absorbed. Path points are `{ lat, lon, altitudeKm }` along the transmitter azimuth (`destinationPoint` in `geoDistance.ts`). Skywave/NVIS `relativeSignalStrength` is D-layer attenuation (inactive D / night → 1.0; below ~0.02 reclassifies as absorbed). `RayTraceParams.atMs` is on the Worker contract and unused by the domain math. `computePropagationRing` / `skipZoneOuterRadiusM` in `footprint.ts` build the isotropic skip-zone / NVIS-coverage ring (not a full azimuth sweep).
- **3D globe rays** — `HfPropagationPage` calls `usePropagationRayTrace` (200 ms debounce, ignore stale in-flight) against `rayTraceClient` for the **antenna azimuth** from the Environment transmitter site. Results feed `HfPropagationGlobe`'s `rays` / `txLat` / `txLon` props **and** `PropagationTopDownMap`'s `rays` / `transmitter` (same state — switching to top-down does not start another Worker request). The vertical slice reuses those rays when its bearing matches heading (within 0.5°); otherwise a **second** hook instance requests `azimuthDeg: sliceBearingDeg`. Mode colours live in `MODE_COLORS` (`buildGlobeData.ts`); layer colours stay in `colorForLayer`. Reading-panel Mode is the dominant non-escaped/absorbed-preferring ray.
- **View switcher** — a `SegmentedControl` (`'globe'` / `'top-down'` / `'vertical-slice'`) selects which single renderer occupies the viewport; only one view renders at a time. All three views are shipped.
- **Top-down map** — Leaflet OSM plan view (`PropagationTopDownMap`). Centres on the Environment transmitter. Draws an isotropic groundwave ring (`GROUNDWAVE_MAX_RANGE_KM`), a dashed skip-zone / NVIS ring from `skipZoneOuterRadiusM`, and the **first** traced ray's ground track in `MODE_COLORS` (not the full elevation fan the globe shows). Known gap: not a 360° coverage picture — same single-bearing cut as the rest of v1.
- **Vertical slice** — SVG height-vs-distance chart (`PropagationVerticalSlice`). Active ionospheric layers are translucent bands at their altitude range; the dominant ray is a polyline in `MODE_COLORS`. Horizontal scale is the slice picker's `distanceM`. Off-heading slices (directional antennas) can show a shorter/weaker path than the globe's on-heading fan because they use a different `azimuthDeg` in the Worker. No x-axis place-name ticks (deferred).
- **Environment date & time** — visible value is `dd/mm/yyyy HH:mm` (24-hour, local). A calendar button opens the native picker (`showPicker`) so the OS locale cannot rewrite the field as US 12-hour AM/PM. Globe shells follow that instant **across the globe**: D/F1 on the day hemisphere, merged F2 (lower bound 150 km) on the night hemisphere. The Reading-panel fc still uses TX-local `computeIonosphericLayers` at the Environment transmitter location. Night-side shade is always drawn on the 3D globe. **Show day/night terminator** (Display, default off) adds a bright dashed greyline ring and a sun-direction marker.
- **Transmitter location** — Environment panel: Maidenhead-style lat/lon `NumberInput`s plus [`UseMyLocationButton`](../../../src/app/components/UseMyLocationButton/UseMyLocationButton.tsx). Local `useState` only (no library). Neutral placeholder **0°, 0°** (Gulf of Guinea) until the operator types a site or geolocates; denied geolocation leaves the fields unchanged and shows the button's existing error text (no extra banner). `MapLocationPicker` is not used here — the control panel is already dense. The same `{ lat, lon }` drives ionospheric layers, the Worker (`RayTraceParams.txLat`/`txLon`), the globe marker/skip ring, the top-down map centre/rings, and slice-plane locator/address **From** (`pathMetricsBetween(transmitter, farPoint)`).
- **Slice-plane picker** — `SlicePlanePicker` on `HfPropagationPage` (Vertical slice view only). Modes: direct bearing (defaults to antenna azimuth when that family uses heading, independently overridable; range default **4,000 km**), Maidenhead **To** locator, and address look-up via `@integrations/geocode/` (Mapbox/Photon). Output type `SlicePlaneResult` `{ bearingDeg, distanceM }` drives the vertical slice's Worker azimuth (when off-heading) and `maxRangeM`, and the 3D globe's volumetric cutaway plane (same bearing; antenna heading until the picker has been used). From/TX comes from Environment. No Channel look-up mode.
- **Cutaway and ray corridor** — Display-group toggles on `/reference/rf-propagation`, both **off** by default. Cutaway clips the globe shells along the slice bearing (`cutawayPlaneNormal` in `src/core/domain/hfPropagation/cutawayPlane.ts`). Ray corridor adds a `TubeGeometry` ribbon beside the always-on thin ray line. Not device-gated yet — Android cost is for #1174.

## Out of scope

- Full-wave EM antenna solvers (NEC-2/NEC-4-class modelling) — the antenna pattern library (#1166) uses closed-form gain functions instead.
- Live space-weather data (NOAA SFI/Kp, GIRO ionosonde network, IRI-2020, VOACAP) — surveyed as candidates, none committed; v1 uses canned solar-activity presets.
- Any `Library`/`RadioBuild` overlay (repeater/channel coverage preview) — this feature has no library dependency.
- Full-azimuth sweep (the actual 3D coverage lobe for directional antennas) — v1 traces one bearing at a time; see "Single-vertical-plane ray tracing" above.
- Terrain/ground-conductivity modelling; particle-flow ray animation.
