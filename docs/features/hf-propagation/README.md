# HF/RF propagation visualiser

Tier-1 hub for the **Propagation Visualiser** — an interactive 3D globe (plus 2D top-down and vertical cross-section views) that lets an operator place an idealised HF transmitter (antenna type, power, frequency, location) and see where the signal actually goes: groundwave footprint, skywave skip zones and hop landing points, and NVIS coverage, shaped by day/night ionospheric state and solar activity. A planning/teaching tool, not a coverage guarantee.

**Tracking:** Epic [#1162](https://github.com/pskillen/codeplug-studio/issues/1162) (child of Milestone 2 [#495](https://github.com/pskillen/codeplug-studio/issues/495))
**Navigation:** reached from the Tools strip (`Tools → Propagation Visualiser`, `/reference/rf-propagation`), reachable with **no active project** — like Maidenhead locator and Band plan, unlike the project-scoped Tracking Dashboard. The Tools entry is hidden on prod builds; the route remains.
**Components:** [HfPropagationGlobe](../../../src/app/components/HfPropagationGlobe/HfPropagationGlobe.md)

## Concepts

- **Client-only, independent of the library** — reachable at `/reference/rf-propagation` with **no active project**; the page's control state (`HfPropagationPage`) is local `useState`, with no dependency on `useProjects`, `useLibrary`, or `ProjectPersistence`. Orbital/RF math runs entirely in the browser once later phases add it; no Studio backend.
- **Single-vertical-plane ray tracing in v1** — the traced path is one bearing at a time, not a full elevation×azimuth sweep; this applies across the 3D globe, top-down, and vertical-slice views alike. Full-azimuth coverage (the true 3D lobe for directional antennas) is a credible future epic, not part of this one.
- **Core domain scaffold** — `src/core/domain/hfPropagation/` holds `AntennaPatternFamily`, `AntennaConfig`, `SolarActivityPreset`, `IonosphericLayerState`, `PropagationMode`, `RayTraceParams`, and `RayPathResult`. `computeIonosphericLayers` produces TX-local D/E/F1/F2 state for the Reading-panel fc (and later ray tracing); the globe shaders apply the same day/night bands spatially from the subsolar point. `criticalFrequencyMhz` drives the fc readout. `antennaGain` / `wavelengthM` implement the four closed-form pattern families (relative weight in `[0, ~2]`, not dBi). `traceRay` / `traceRayFan` classify a single vertical plane as groundwave / skywave / NVIS / escaped / absorbed. Path points are `{ lat, lon, altitudeKm }` along the transmitter azimuth (`destinationPoint` in `geoDistance.ts`). Skywave/NVIS `relativeSignalStrength` is D-layer attenuation (inactive D / night → 1.0; below ~0.02 reclassifies as absorbed). `RayTraceParams.atMs` is on the Worker contract and unused by the domain math.
- **View switcher** — a `SegmentedControl` (3D Globe / Top-down / Vertical slice) selects which single renderer occupies the viewport; only one view renders at a time, not three simultaneous panels.
- **Environment date & time** — visible value is `dd/mm/yyyy HH:mm` (24-hour, local). A calendar button opens the native picker (`showPicker`) so the OS locale cannot rewrite the field as US 12-hour AM/PM. Globe shells follow that instant **across the globe**: D/F1 on the day hemisphere, merged F2 (lower bound 150 km) on the night hemisphere. The Reading-panel fc still uses TX-local `computeIonosphericLayers` (placeholder TX 0, 0 until a dedicated transmitter-location control). Night-side shade is always drawn on the 3D globe. **Show day/night terminator** (Display, default off) adds a bright dashed greyline ring and a sun-direction marker.
- **Slice-plane picker** — `SlicePlanePicker` on `HfPropagationPage` (Vertical slice view only). Modes: direct bearing (defaults to antenna azimuth when that family uses heading, independently overridable; range default **4,000 km**), Maidenhead **To** locator, and address look-up via `@integrations/geocode/` (Mapbox/Photon). Output type `SlicePlaneResult` `{ bearingDeg, distanceM }` is held on the page for #1172; the picker does not collect a From/TX point. No Channel look-up mode.

## Out of scope

- Full-wave EM antenna solvers (NEC-2/NEC-4-class modelling) — the antenna pattern library (#1166) uses closed-form gain functions instead.
- Live space-weather data (NOAA SFI/Kp, GIRO ionosonde network, IRI-2020, VOACAP) — surveyed as candidates, none committed; v1 uses canned solar-activity presets.
- Any `Library`/`RadioBuild` overlay (repeater/channel coverage preview) — this feature has no library dependency.
- Full-azimuth sweep (the actual 3D coverage lobe for directional antennas) — v1 traces one bearing at a time; see "Single-vertical-plane ray tracing" above.
- Terrain/ground-conductivity modelling; particle-flow ray animation.
