# Satellite tracking

Tier-1 hub for the **Tracking Dashboard** — client-side pass prediction (SGP4), observer location, SatNOGS transmitter enrichment on the satellite detail page, and 3D/2D orbital visualization. Consumes curated TLEs from the [Satellite keps](../satellite-keps/) library; does not write keps to radios.

**Tracking:** Epic [#860](https://github.com/pskillen/codeplug-studio/issues/860) (child of Milestone 2 [#495](https://github.com/pskillen/codeplug-studio/issues/495))  
**Depends on:** [#848](https://github.com/pskillen/codeplug-studio/issues/848) curated TLEs (at least #850–#853; frequencies when #854 lands)  
**Navigation:** reached from the Tools strip (`Tools → Tracking Dashboard`, `/tracking`), not a top-level tab — [#978](https://github.com/pskillen/codeplug-studio/issues/978)

## Concepts

- **Client-only** — Orbital math and visualization run in the browser (Web Workers for pass sweeps); no Studio backend.
- **Depends on keps library** — Enabled satellites and TLEs come from [#848](https://github.com/pskillen/codeplug-studio/issues/848); this epic adds prediction and visualization only.
- **Styleguide** — Follow Studio map/list chrome; design-doc “neon war room” visuals are illustrative, not a theme mandate.
- **Pass grid filters** — client-only, applied to the already-computed pass list (no Worker re-run): min-elevation filter, satellite multi-select-with-search (`SatelliteFilter.tsx`), and an **only with TX/RX frequencies** toggle (default on). Satellite-level filters compose into a shared **interested satellites** set (`interestedSatellites.ts`) that drives the pass grid, 2D ground-track map, and 3D globe together. Frequency qualification reads `Satellite.transmitters` directly. Per-satellite display colour is derived from NORAD id (`colorForNoradId`) and shared by the pass-row swatch, 2D polylines, and 3D dots/trails/footprints. The look-ahead window (default 12h) is debounced 300ms before triggering a new Worker pass-prediction sweep. Large pass lists use windowed row virtualization on the v2 `DataTable`.
- **SatNOGS enrichment vs. TLE source** — SatNOGS answers "what does this satellite transmit / is it alive," a different provenance question from `SatelliteSource` ("where did this TLE come from" — CelesTrak/AMSAT). That provenance distinction is now modelled per-transmitter as `SatelliteTransmitter.source: SatelliteTransmitterSource` (`'manual' | 'satnogs'`), rather than a whole-satellite session-cache tag: SatNOGS-derived rows carry `'satnogs'`, operator-entered rows carry `'manual'`. Enrichment is merged directly into the persisted `Satellite.transmitters[]` list, keyed by SatNOGS transmitter UUID ([#1037](https://github.com/pskillen/codeplug-studio/issues/1037)) — refresh from the satellite detail page or as part of the Satellite Keps "Update from CelesTrak/AMSAT" flow; see [SatNOGS reference](../../reference/remote-directories/satnogs/README.md). Operators add, edit, and delete transmitter rows directly in the Satellite Keps editor; a "Refresh from SatNOGS" action there merges live data into existing rows (matched by SatNOGS UUID) without overwriting manual entries or previously-synced labels. Tone stays manual-entry only, since SatNOGS transmitter data carries no tone field. The satellite detail page's `SatelliteDetailPanel` and the Next Pass card both render the persisted `transmitters[]` list directly (dismissed rows hidden on the detail page) — no session-scoped enrichment cache remains anywhere in the tracking UI.

## Out of scope

- Radio keps write ([#848](https://github.com/pskillen/codeplug-studio/issues/848))
- Space-Track.org
- Offline / paid map tile productization
- 3D/2D viewport toggle — both viewports exist as of [#866](https://github.com/pskillen/codeplug-studio/issues/866), so the toggle is technically unblocked, but building it is tracked separately as [#1009](https://github.com/pskillen/codeplug-studio/issues/1009), not part of this epic's shipped scope
- Dedicated Mode / operational-status columns in the pass grid — the grid shows TX/RX frequencies only; mode and status are visible on the satellite detail page's transmitter list, not per-row in the grid
