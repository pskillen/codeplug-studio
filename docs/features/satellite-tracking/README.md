# Satellite tracking

Tier-1 hub for the **Tracking Dashboard** — client-side pass prediction (SGP4), observer location, SatNOGS transmitter enrichment on the satellite detail page, and 3D/2D orbital visualization. Consumes curated TLEs from the [Satellite keps](../satellite-keps/) library; does not write keps to radios.

**Tracking:** Epic [#860](https://github.com/pskillen/codeplug-studio/issues/860) (child of Milestone 2 [#495](https://github.com/pskillen/codeplug-studio/issues/495))  
**Depends on:** [#848](https://github.com/pskillen/codeplug-studio/issues/848) curated TLEs (at least #850–#853; frequencies when #854 lands)  
**Navigation:** reached from the Tools strip (`Tools → Tracking Dashboard`, `/tracking`), not a top-level tab — [#978](https://github.com/pskillen/codeplug-studio/issues/978)

## Concepts

- **Client-only** — Orbital math and visualization run in the browser (Web Workers for pass sweeps); no Studio backend.
- **Depends on keps library** — Enabled satellites and TLEs come from [#848](https://github.com/pskillen/codeplug-studio/issues/848); this epic adds prediction and visualization only.
- **Styleguide** — Follow Studio map/list chrome; design-doc “neon war room” visuals are illustrative, not a theme mandate.
- **Pass grid filters** — client-only, applied to the already-computed pass list (no Worker re-run): min-elevation filter, satellite multi-select-with-search (`SatelliteFilter.tsx`), and an **only with TX/RX frequencies** toggle (default on). Satellite-level filters compose into a shared **interested satellites** set (`interestedSatellites.ts`) that drives the pass grid, 2D ground-track map, and 3D globe together. Frequency qualification accepts library uplink/downlink fields or session SatNOGS transmitter data until enrichment is merged onto `Satellite` ([#864](https://github.com/pskillen/codeplug-studio/issues/864)). Per-satellite display colour is derived from NORAD id (`colorForNoradId`) and shared by the pass-row swatch, 2D polylines, and 3D dots/trails/footprints. The look-ahead window (default 12h) is debounced 300ms before triggering a new Worker pass-prediction sweep. Large pass lists use windowed row virtualization on the v2 `DataTable`.
- **SatNOGS enrichment vs. TLE source** — SatNOGS answers "what does this satellite transmit / is it alive" (`SatelliteEnrichmentSource`), a different provenance question from `SatelliteSource` ("where did this TLE come from" — CelesTrak/AMSAT). Enrichment is fetched and merged live per session, keyed by NORAD id, and is **not** persisted as part of the `Satellite` model. Refresh from the satellite detail page or as part of the Satellite Keps "Update from CelesTrak/AMSAT" flow — see [SatNOGS reference](../../reference/remote-directories/satnogs/README.md). The Satellite Keps editor merges SatNOGS transmitters straight into the persisted `Satellite.transmitters[]` list by SatNOGS UUID ([#1040](https://github.com/pskillen/codeplug-studio/issues/1040)) — tone stays manual-entry only, since SatNOGS transmitter data carries no tone field. The satellite detail page's `SatelliteDetailPanel` renders that persisted `transmitters[]` list directly (dismissed rows hidden) rather than the session-scoped enrichment ([#1041](https://github.com/pskillen/codeplug-studio/issues/1041)); the session enrichment provider still backs the Next Pass card's primary mode + Doppler shift until [#1037](https://github.com/pskillen/codeplug-studio/issues/1037) phase 5 finishes the migration.
