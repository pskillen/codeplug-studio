# MM9PDY modded firmware

Operators who run the **MM9PDY** firmware want one channel per repeater and the zone as the scan sequence. Stock Anytone and DM-32 targets keep m×n channel expansion and dedicated or zone-derived scan lists. Pick the radio target whose label says **MM9PDY modded firmware**.

The library stays vendor-neutral. `RxGroupListMember.timeSlotOverride` is already a library field. These targets write that hint on the radio only where the MM9PDY firmware has a store for it. They do not clone contacts or suffix talk-group names with `TS1` / `TS2`.

Wire layouts stay in the stock radio docs: [AT-D890UV](../../reference/radios/anytone/at-d890uv/README.md) and [DM-32UV](../../reference/radios/baofeng/dm-32uv/README.md).

**Tracking:** [codeplug-studio#1312](https://github.com/pskillen/codeplug-studio/issues/1312)

**Getting the firmware onto the radio:** the [firmware flasher](../firmware-flashing/README.md) (Tools → Firmware flasher).

**If something goes wrong:** [Recovery](../firmware-flashing/README.md#recovery).

## Write rules

1. **One channel per repeater.** The channel's RX group is the talk-group list. The channel contact is the first selection. Studio does not expand one repeater into a channel per talk group.
2. **The zone is the scan.** There is no parallel scan-list inventory. Build nav hides Scan lists.
3. **Timeslot is per RX-group member** on the AT-D890UV and DM-32UV MM9PDY targets, stored from `timeSlotOverride`. Omitted members stay unset. The stock writes fill that store with the unset sentinel. Layout: [AT-D890UV](../../reference/radios/anytone/at-d890uv/) · [DM-32UV](../../reference/radios/baofeng/dm-32uv/contacts-zones-lists.md#per-member-timeslot-store).

4. **Channel positions** are written only by the MM9PDY targets, into storage the stock firmware and the official CPS never use (an exception to "write only what the codeplug models": Studio owns those regions outright). A channel goes in the table when _Use location_ is on and it has a usable position. Each entry carries a fingerprint of the encoded channel (name and RX frequency), so the radio hides a position that no longer matches its channel. Stock targets never write or touch the table, and say so in a note when the build has positions. After an official-CPS or stock write, write from the MM9PDY target again. Spec: `firmware-mods/features/channel-distance.md`.

Assigning TG previous / TG next on the MM9PDY targets is an optional export setting, off unless the operator turns it on. Official CPS shows those functions as item 15 Record (TG next) and item 14 Record Switch (TG previous). The radio's own key menu shows the MM9PDY names.
