# Contact directories

Tier-1 reference for **DMR digital contact / ID directory** workflows — searching remote ID databases and staging IDs in the local directory shadow before copying into the vendor-neutral library.

**Tracking:** [#374](https://github.com/pskillen/codeplug-studio/issues/374) (epic, parent [#272](https://github.com/pskillen/codeplug-studio/issues/272)) · [#377](https://github.com/pskillen/codeplug-studio/issues/377)–[#379](https://github.com/pskillen/codeplug-studio/issues/379) · Anytone export [#376](https://github.com/pskillen/codeplug-studio/issues/376)

**Source:** `src/integrations/radioid/`, `src/app/components/contacts/`, `src/app/routes/library/AddFromRadioidPage.tsx`

## Problem

Many CPS suites (OpenGD77, qDMR, …) offer one-click DMR ID import. **Anytone CPS does not** — operators download CSV from e.g. RadioID.net and manually rewrite columns for `DMRDigitalContactList.CSV`. Studio fetches provider data at the integration boundary, stages enriched IDs in the **directory shadow store**, and lets operators copy rows into library contacts for format export.

## Terminology

Two kinds of DMR ID record, with one name each in the UI ([#1430](https://github.com/pskillen/codeplug-studio/issues/1430)):

| UI term          | What it is                                                                                                                                            | Model / store                                        |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------- |
| **Contacts**     | Records the operator curates: selectable and callable on the radio, referenced from channels and RX group lists, exported with the build.             | Library `DigitalContact`                             |
| **ID directory** | Bulk downloaded IDs (e.g. RadioID.net, 100k+ rows). The radio uses them only for incoming-call alias lookup; the operator cannot browse or call them. | `digitalIdDirectory` IDB store (not in project YAML) |

**Add to contacts** promotes one ID directory entry to a contact. Older docs and code identifiers say "directory shadow (store)", "RadioID directory", "digital ID directory" or "library contacts" for the same two concepts. Vendor names for the lookup store (OpenGD77 User Database, DM-32 DMR-ID list, AT-D890 ID database) stay in the format and radio reference docs.

### Routes

- `/library/contacts/directory` — browse shadow store (paged)
- `/library/contacts/add-from-radioid` — fetch/import from RadioID.net into shadow store

## Architecture

- Provider HTTP client in `src/integrations/radioid/` — maps API rows → directory shadow entries at boundary (`mapRadioidUserToDirectoryEntry`); library mapping (`mapRadioidUserToDigitalContact` / `mapDirectoryEntryToDigitalContact`) for copy-to-library and verify flows.
- CORS bridge: `GET /api/radioid/dmr/user/` (trailing slash required; Pages Function + Vite dev proxy) — see [radioid reference](../../reference/remote-directories/radioid/README.md).
- UUID `id` FKs internally; wire names only on format build export.
- **Contact export name style** is an export-time build setting (not import-time): library stores `name` and `callsign` separately; Anytone/OpenGD77 CPS export **and OpenGD77 Web Serial Write** compose the contact wire name per `exportSettings.digitalContactExportNameMode`.
- Duplicate import gate (directory): match on `digitalId` in the shadow store (not display `name`).
- **Bulk import persistence (filtered search):** **Import all results** writes directory rows in batched IndexedDB transactions (one batch per RadioID.net results page, up to **200** rows) inside `runWithoutNotifications` (library **and** directory listeners coalesced to one event). **Entire database** streams `user.csv` in batches of **2000** with relaxed IDB durability — upsert by `digitalId` without hydrating the partition for duplicate detection.
- **Directory browsing scale:** `queryDigitalIdDirectoryPage` ([#989](https://github.com/pskillen/codeplug-studio/issues/989), [#1123](https://github.com/pskillen/codeplug-studio/issues/1123)) — UI must not `getAll` the partition into React state. Search-page “in directory” dimming uses `getDigitalIdDirectoryEntriesByIds` for the current result page only. IDB stores lowercase index fields (`callsignLower`, `nameLower`, `digitalIdStr`) for prefix scans; they are persistence-only and not in interchange YAML/CSV.
- **Portable interchange:** native project YAML and Google Drive sync include **library rows only** — the directory shadow is excluded from `ProjectSeed` / `ProjectAggregate`. Operators may optionally download or import a separate directory file (YAML or CSV) or a local zip containing project YAML plus directory file ([#986](https://github.com/pskillen/codeplug-studio/issues/986)–[#988](https://github.com/pskillen/codeplug-studio/issues/988)). Large directory exports buffer all shadow rows in memory before download.
- **Delete all recovery:** when a huge **library** import leaves the tab unusable, **Delete all** clears the digital contact partition via `deleteDigitalContactsForProject` (IDB key cursor — no full hydrate for delete) after cascade-clearing refs. This does **not** clear RadioID directory downloads. IndexedDB-primary browsing ([#428](https://github.com/pskillen/codeplug-studio/issues/428)) remains deferred.
- Session cache (≤5 min) + per-provider rate-limit cooldown after HTTP 429.

### Dual-bank Web Serial Write (`SeparateDigitalIdList`)

Radios with trait `separateDigitalIdList` expose separate **library contact** and **RadioID directory** stores on Write.

| Radio                   | Library contacts                                                                                               | RadioID directory                                                                                     | Overlap (`digitalId` in both)                                                       |
| ----------------------- | -------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| OpenGD77 1701 / MD-9600 | 1024-slot DMR contact bank (`Contacts.csv` / FLASH `0xa7620`)                                                  | Firmware **User Database** (incoming-call lookup) — Web Serial sidecar; **not** a second contact bank | **Keep** the ID in both stores                                                      |
| DM-32                   | Address book `0x0F`                                                                                            | Same address book `0x0F` (Web Serial; serial cap `ADDRESS_BOOK_WRITE_MAX`, not CPS 250)               | **Skip** directory rows (shared bank — **P2**)                                      |
| AT-D890UV               | Contacts list (talk-group list), as private entries after talk groups, shared 10,000; always with the codeplug | ID database (DMR contact DB, 500,000) — Contacts part                                                 | **Skip** directory rows whose ID is a build contact (radio names from the DB first) |

| Action                  | Library contacts | RadioID directory |
| ----------------------- | ---------------- | ----------------- |
| **Write codeplug**      | Off until chosen | Off until chosen  |
| **Write contacts only** | Per source       | Per source        |

DM-32 maps directory rows to the **address book** (`0x0F`) on Web Serial Write (RadioID/Both **replace** that bank; library wins on duplicate `digitalId`). Operator radio IDs (`0x67`) stay channel `dmrId` values. **CPS export** warns and does **not** write directory into `DigitalContacts.csv` or `DMR-ID.csv`. OpenGD77 maps directory to User Database on Web Serial only ([user-database.md](../../reference/radios/opengd77/user-database.md)). Large directory writes stream from IndexedDB — see `collectDualBankDirectorySlice` ([#991](https://github.com/pskillen/codeplug-studio/issues/991), [#1211](https://github.com/pskillen/codeplug-studio/issues/1211), [#1220](https://github.com/pskillen/codeplug-studio/issues/1220)) and CPS `enrichCpsExportOptionsWithDirectory` ([#993](https://github.com/pskillen/codeplug-studio/issues/993)).

### AT-D890UV dual-bank contacts

The AT-D890UV has two contact stores ([#1433](https://github.com/pskillen/codeplug-studio/issues/1433)). The **Contacts list** (talk-group list) is what the radio shows under Contacts and what channels and RX group lists point at. The **ID database** only names incoming calls, and the radio looks there first.

- **Contacts always ride with the codeplug.** Every Write that writes the radio image puts the build's talk groups (group calls) and then its contacts (private calls) in the Contacts list, within the shared 10,000. Talk groups go first; contacts past the cap are left out with a warning, and a channel that calls one is written with no TX contact (also warned).
- **The Contacts part fills the ID database.** **Contacts** writes the build's contacts, **ID directory** writes directory rows, **Both** writes both. Unticked leaves the ID database as it is.
- **Overlap.** Directory rows whose DMR ID is a contact in this build are always skipped, so the radio shows the contact's own name. The same ID in both stores is harmless: both carry the same name.
- **Contacts without the codeplug.** The Write still re-sends the whole projected codeplug image (channels, zones, talk groups and contacts, RX groups) before the ID database: the Codeplug tick does not gate what the AT-D890 image encode sends.

No profile is single-bank any more; the earlier AT-D890 single-bank modes ([#992](https://github.com/pskillen/codeplug-studio/issues/992), [#994](https://github.com/pskillen/codeplug-studio/issues/994)) are gone. A stored pre-#1433 CPS single-bank choice is read once as the dual-bank checkboxes. Radio wire detail: [AT-D890UV talk-group record](../../reference/radios/anytone/at-d890uv/talkgroup-record.md); CPS files: [Anytone talk groups](../../reference/export-formats/anytone/talk-groups.md).

The contact units are written like the official CPS does ([#1406](https://github.com/pskillen/codeplug-studio/issues/1406)): each touched erase unit starts from erased flash, is filled from the projected contacts and is never read, so a shorter list leaves no stale tail and a 1,000-contact Write sends about 6,000 frames instead of 21,000 plus 3,000 reads. Wire detail: [digital-contacts.md](../../reference/radios/anytone/at-d890uv/digital-contacts.md).
