# AtD890Memory

## Purpose

Read-only AT-D890UV Memory viewer: MR channels, zones, contacts, talk groups, RX groups, scan lists decoded from the open debug archive, without a project, library or build. Settings are their own page-level tab (`AtD890Settings`), which reads the same memoised projection (`projectAtD890Archive` in `debugProjections.ts`), so the decode runs once per archive.

## Props

| Prop      | Meaning                                                                               |
| --------- | ------------------------------------------------------------------------------------- |
| `archive` | Optional open `DebugArchive`. Absent shows a no-capture state; a non-D890 is refused. |

## Usage

`RadioDebugPage` mounts it in the Memory tab of the `at-d890uv` profile. It sits under the existing design-system v2 provider.

## Behaviour

Its categories (Channels, Zones, Contacts, Talk groups, RX groups, Scan lists) are chosen from the shared [MemoryCategories](MemoryCategories.md) dropdown, not inner tabs.

Projection is in `integrations/radio-io/radios/at-d890uv/debugMemory.ts`: only recognised, length-matched, in-bounds sparse entries count; duplicates and overlaps are refused; coverage is byte-exact. Channels and zones list only after their complete occupancy bitmap is captured, otherwise the panel says "Not captured". Slots keep their one-based numbers. Missing record halves stay visible as "Not captured", distinct from a captured empty or unreadable record. Zone names and member lists decode independently; members keep radio order and duplicates, and each zero-based index resolves to channel slot index plus one, with distinct explanations for absent, not-captured, unreadable, out-of-range and unresolvable references. Identity is the single complete name field (it may contain a callsign); separate callsign and name are unavailable. Tables are v2 `DataTable`s with search and temporary sorting, default slot order. Contacts and Talk groups are views of one shared 10,000-slot bank (private-call records versus group and all-call records), decoded in `debugMemoryContacts.ts` only from a fully captured inverted `TalkgroupSet` and complete `0xC8` records. Unclassified slots (not captured, malformed BCD, unknown call type) are listed in both tabs and never counted as empty. Search covers slot, DMR ID, callsign, name, city and references; sorting is temporary and never renumbers slots. Talk groups show Referenced by from captured channel and RX evidence only, labelled partial when coverage is incomplete. RX groups decode name and members independently, resolve members and a channel's TX contact by one-based bank slot (never by DMR ID), and show time-slot overrides only when captured. The separate DMR ID database is not decoded. Scan lists (`AtD890MemorySettings.tsx`, projection in `debugMemorySettings.ts`) need the complete normal `ScanListSet` bitmap (250 lists; excess bits reported), use banked addresses (index 31 is `0x2103E00`, index 32 `0x2180000`) and decode name, the 100 zero-based member indices and the priority bytes independently, each only from a fully captured span. Members keep order, duplicates and the zone-style channel statuses. Priority words are one-based (`0xFFFF` Off, `0` Current Channel, `n` channel index `n-1`) and are shown even when not members; a member that matches a priority is labelled with its role without reordering. Unknown priority-select values stay raw. Settings cover the main and power-on optional-settings blocks: each registered field is decoded only when its exact address and length were captured, never from a gap-filled snapshot. Fields are grouped (Display; Audio & tones; Power & battery; Keys & buttons; DMR; GPS / APRS; Scan; Privacy / lock; Mod features; Other when needed); empty groups say the data is unavailable. The GPS template text block (`0x3501280`) is decoded as UTF-16 from all `0x42` bytes (the three optional-settings blocks plus the head of `GpsInfoTail`), and says when an archive holds fewer. The Mod features group reads the MM9PDY settings store (`0x03500200`) read-only, or says no valid record exists. Eight fields the allow-list refuses at zero (hang times, analogue hold, TX preamble 0-4, voice header repeats 0-1, power-on volume 0) show as real states with a firmware note; this is display only and never touches Write. Search covers label, id, group, value, raw bytes and address; "Show raw bytes + address" is a switch, and an unsupported value always shows its raw bytes. Captured bytes (or bits of a masked byte) that no field edits are named in an Other settings bytes table with confidence and evidence, including bytes the firmware never reads (shown as unused, not unknown); only bytes nothing names are listed as unknown; uncaptured bytes are counted as missing. Counts are captured and decoded fields, never capacity percentages. Meanings are the stock layout; target-specific names (key functions) are labelled conditional and nothing infers MM9PDY firmware. Replacing the archive remounts the viewer, resetting rows, references and selections.
