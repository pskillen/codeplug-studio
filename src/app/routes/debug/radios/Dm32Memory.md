# Dm32Memory

## Purpose

Read-only DM-32UV Memory viewer: channels, zones, scan lists, talk groups, RX groups, radio IDs, contacts decoded from the open debug archive (live read or file), without a project, library or build, and without opening a transport.

## Props

| Prop      | Meaning                                                                                  |
| --------- | ---------------------------------------------------------------------------------------- |
| `archive` | Optional open `DebugArchive`. Absent asks for a capture; a non-DM-32 archive is refused. |

## Usage

`RadioDebugPage` mounts it in the Memory tab of the `dm-32uv` profile with the selected retained read. It keys itself by archive identity (`archiveKey`), so replacing the archive resets search and sort.

## Behaviour

Its categories (Channels, Zones, Scan lists, Talk groups, RX groups, Radio IDs, Contacts) are chosen from the shared [MemoryCategories](MemoryCategories.md) dropdown, not inner tabs.

`buildDm32SparseCapture` (`integrations/radio-io/radios/dm32uv/debugMemory.ts`) takes accepted whole 4 KiB blocks from `classifyDm32DebugCoverage` and lists its refusals with reasons. Channel page order comes only from the `debug/capture.json` discovery map: channel page k is the k-th discovered block with tag `0x12` to `0x40` in tag order (`0x41` is the VFO bank and is excluded). Without a map the panel says "Page order not established". The channel count is the u16 at the first channel page; the stated count above the 4,000 hardware slots is reported, not listed. Each slot needs its 48 captured bytes; a page whose stored tag disagrees with discovery counts as not captured. States: decoded, empty (all `0xFF`), blank record (no name or RX, not erased; raw bytes shown), not captured. A decoded record shows "Invalid BCD" with raw bytes for RX/TX nibbles above 9, "No TX frequency stored" when the TX bytes are all `0xFF`, and the raw mode byte. Scan list, RX group and TX contact indexes are raw, unresolved numbers. Zones and scan lists (`debugMemoryZones.ts`) keep radio order and list only records within the stated count (capped at 250 zones and 32 lists); a record whose page was not captured is "Not captured", a record with no name is vacant. Zone pages come from the discovery map (tags `0x5C` to `0x64`, 28 records per page, the first page's records start at `+16`; header bytes are shown raw and the meaning of the stored count is unverified); the scan-list page is the single `0x11` page and works without a discovery map. Members are channel slot numbers resolved against the decoded channels with a DM-32 status set (resolved, out of range, empty, not captured, inventory not captured, unreadable), order and duplicates kept; a zone member count above 64 is shown raw and reads no members. A scan list stores named members plus one for the implicit current channel; hang, priority and designated-TX bytes are raw hex only. Selecting a zone or scan list shows its members; search covers the name and member labels. A channel's scan list id resolves to the scan list's name, or reads absent. Channels have one name field, so that complete label is searched and sorted; callsign data is unavailable.

Talk groups, radio IDs and analogue contacts (`debugMemoryLists.ts`, panels in `Dm32MemoryLists.tsx`) look a page up by its stored tag and use it only when exactly one accepted block carries it; several are listed ("Several pages tagged 0xNN, not decoded") and a missing page is "Not captured". Talk groups (tag `0x44`) are 24-byte entries after one header byte, ending at the first all-zero or all-`0xFF` entry, at most 170 per page; the quick-access page `0x0B` count (u16 at `+0`) is shown beside the decoded count with a mismatch warning, a count above 800 is reported and not listed, and tags `0x45` to `0x48` are listed as present or not captured, layout not established, so the list is never called complete. Radio IDs (tag `0x67`) use a count byte (cap 250) and 16-byte entries from `+0x10`; vacant positions are counted, not listed. Contacts always says the digital address book (V-frame `0x0F` bank) is not captured; analogue contacts (tag `0x06`) show the count byte at `+0x1FF` and raw 32-byte records from `+0x200` as hex only. Talk groups and radio IDs have a name only: search and sort cover name and DMR ID, and callsign data is unavailable.

RX groups (`projectDm32RxGroups`, tag `0x0F`) read the u32 LE bitmask at `+0` (bit i = group i + 1; bits at or above the 32 capacity are reported, not listed), then 109-byte entries from `+0x11`: an 11-byte name and 32 positions of 3-byte LE DMR IDs from `+0x0B`. Stored order and duplicates are kept; all-zero and all-`0xFF` positions are empty. Members are DMR IDs, not foreign keys: a member shows a talk group only when exactly one decoded talk group has that ID ("matched by DMR ID"); zero, several or unavailable talk groups say so. Time-slot overrides come from `decodeDm32RxGroupTimeSlotOverrides` only when the page marker and the group's check match (otherwise "no marker" or "check failed"). Selecting a group shows its members.

`resolveDm32ChannelReferences` resolves each decoded channel: TX contact by one-based position in the talk-group list (0 none; beyond the decoded first page it reads "not decoded", beyond the stored count "absent", above 800 "out of range"), radio ID by the zero-based byte at record `+0x2B` (`0xFF` none, cap 250), RX group from byte `+0x1F` bits 5-0 as slot n = group n, labelled "assumed 1-based; not verified on hardware" (0 is "none (assumed)"). Radio ID and RX group apply to digital channels only. A list that was not captured leaves the raw number with "list not captured". The same pass gives each talk group a Referenced by list (captured channel TX contacts and uniquely matched RX group members), labelled partial when channels, TX contact pages or RX groups were not fully captured; selecting a talk group shows it.

Settings are the page-level Settings tab (`Dm32Settings`), which shares the memoised decode (`decodeDm32Archive` in `debugProjections.ts`) with this viewer. Settings (`projectDm32Settings` in `debugMemorySettings.ts`, panel in `Dm32MemorySettings.tsx`) reads the single accepted `0x04` page through a field registry written from `settings.md` (stock DM32.01.L01.048 layout traced by static analysis, synthetic fixtures only, not hardware). Each field has a confidence (traced, partly traced, unknown) and 048 evidence; bit fields share a byte through a mask. A field decodes only when `capture.covers` its whole span; values outside an enum stay raw. The panel shows groups with a confidence column, a search over label, group, value, confidence and raw hex, a "Show raw bytes + address" switch, documented-not-decoded rows (one-key call, one-touch, Fun+, menu flags), unused ranges (free, not read by 048, MM9PDY reserved) and counted unknown bytes. The three password strings (power-on, write, read; `sensitive` fields) show "Hidden (password)" and `••` bytes, and match no search, until **Show password** (`SensitiveRevealButton`, from `useSensitiveReveal`, which `Dm32Settings` owns and resets with the archive). Hex and Compare mask the same three strings through the descriptor `sensitiveRanges` hook (`dm32uv/debugSensitive.ts`). Emergency systems and keys (tag `0x10`) are not shown. No frames are sent.
