# RadioWriteStepper

## Purpose

The Write dialog for every Web Serial radio (#1393, workflow design §2): one ModalShell with six steps, replacing the old Write popup (`WriteRadioModal`) and the progress modal for Write.

| #   | Step            | What happens                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | --------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | What to write   | One tick per part (Codeplug, Digital contacts, Satellite keps; Radio settings on the AT-D890UV: ticked only when the session has changes, else disabled with _Set up…_; "3 changes · Edit" opens the settings page and keeps the ticks). Options show only under ticked parts. Rows a radio does not support are not shown. Button **Connect & read**, disabled with nothing ticked.                                                                                                                                                                                                                                                                                                  |
| 2   | Read            | Port picker, then the in-session read every Write already did, with the planned stage list. Ends with the radio's identity (model, full serial, name and firmware where known).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 3   | Review          | Always shown. Identity, "N channels will be written", contacts and keps counts, "About M min S s"; on the AT-D890UV also the frequency range, receive-only channels, Radio settings (now → after, fleet choice), backup and the step-key nudge ([AtD890ReviewSections](./d890/AtD890ReviewSections.md)). Write is disabled when it would send nothing (settings alone with Keep). Primary **Write codeplug / Write codeplug + contacts / Write 3 parts**; secondary **Cancel** (nothing is written).                                                                                                                                                                                  |
| 4   | Writing         | The full planned list (`RadioIoStageList`), abortable.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 5   | Restart & check | "Waiting for the radio to restart (about 20 s)", then optional **Check write** and, when keps could not share the codeplug's session, **Write keps**.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 6   | Done            | What was written (incl. "Radio settings written (N changes)"), warnings, whether the check ran; on the AT-D890UV the tick "Don't ask again for other radios until I reload" and **Copy write timings** (per-stage durations and `R`/`W` frame counts as one line of text, the same line logged as `[d890-write-timing]`; shown only when the upload returned timings, so not for keps after a restart or a settings-only Write; the same line is logged, with `outcome` `failed` or `aborted`, when a Write fails or is cancelled; if the clipboard refuses, the button says **Copy failed**). **Write another radio** (back to step 2, same ticks, fresh port prompt) and **Close**. |

The component is presentational. [`useRadioWriteFlow`](./useRadioWriteFlow.tsx) owns the state machine and the service calls and hands this component a `view` and `actions`; `BuildRadioIoPanel` wires them.

## Props

| Prop      | Type                 | Description                                                                                                                                                                      |
| --------- | -------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `config`  | `WriteStepperConfig` | Static facts: radio label, which part rows exist (`support`), summaries, the MM9PDY step-key switch (`stepKeys`), restart wait, whether a check exists, an optional success note |
| `view`    | `WriteFlowView`      | Current step, ticks, progress, rows, identity, review data, restart countdown, check status, summary                                                                             |
| `actions` | `WriteFlowActions`   | Callbacks for every button                                                                                                                                                       |

## Usage

```tsx
const flow = useRadioWriteFlow({ build, egress, descriptor, activeProjectId /* … */ });
<RadioWriteStepper config={config} view={flow.view} actions={flow.actions} />;
// flow.open() opens the dialog at step 1 with the defaults (codeplug ticked).
```

## Behaviour

- **Parts map to today's services.** Codeplug (with or without contacts) and contacts alone go through one `prepareRadioWriteImage` + `uploadPreparedRadioWrite` session: codeplug ticked means mode `codeplug` with the chosen contact source; contacts alone means `digitalIdList`. Keps use the keps adapter. No frame differs from the old buttons.
- **Held session, pause before transmit.** The session stays open from the read to the write. `uploadPreparedRadioWrite` calls `beforeTransmit` after the read and before the first frame; Review is that pause. Cancel rejects it: no `W` frame is sent and the session is closed the way a read-only session is (Studio still sends `END`, so the radio is usable again by itself). On radios that restart on `END` (the D890) the Review note says so: "the radio restarts (about 20 s)".
- **Hold time.** `RadioDescriptor.programHoldSafeMs` (AT-D890UV `Infinity`; others unset, treated as 30 s). If Review has been open longer when Write is pressed, the stepper reconnects and re-reads (step 2, "Reconnecting: the radio may have left programming mode") and then writes. If the read fails before any frame, the error offers **Reconnect and read again**.
- **Keps.** Keps always wait for step 5 and use a new session (new port prompt, as Check write does). On OpenGD77 `upload()` ends with SAVE_REBOOT. On the AT-D890UV the keps writer preserve-reads its unit, and an `R` after the codeplug's `W` frames would stop the radio committing (#1406), so it is the same restart step and **Write keps** button; the D890 plan has no keps stages. (`kepsSameSessionAfterUpload` stays in the plumbing for a radio whose keps writer needs no read; #1417 would bring the D890 back.) If the keps part fails or is cancelled after a same-session codeplug upload (the branch is unused today, but kept and tested), the session still closes (END commits the codeplug), the Check write is still offered, and step 5 and Done say the codeplug was written and the keps were not. Done also says "Satellite keps: not written" whenever keps were ticked and no keps result exists (for example **Finish without keps** on OpenGD77). A failed D890 Write that had already sent whole units adds a warning to the error (the units stay pending on the radio until a Write rewrites them; see the AT-D890UV protocol reference). Stage lists fold progress with the 4a stage cursor (`radioIoStageCursor.ts`), the same as `RadioIoProgressModal`.
- **Restart countdown.** Step 5's "Waiting for the radio to restart (about 20 s)" line and its deadline timer are the shared [`RestartCountdown`](../../radio-io/RestartCountdown.md) and `useRestartCountdown` (also used by the Danger zone's range change); behaviour is unchanged.
- **AT-D890UV interrupted Writes.** A Write that stopped after sending whole erase units, or a Write refused because an earlier one did, shows the error with the parts to tick (Codeplug, Digital contacts) and the time it was recorded. Under it, **I have rewritten this radio: clear warning** (asks again before it acts: **Yes, I have rewritten this radio** or **Keep the warning**) is for an operator who repaired the radio another way, the CPS for example. The record is per radio; Debug, LocalStorage can also delete it. See [protocol.md](../../../../docs/reference/radios/anytone/at-d890uv/protocol.md#abandoned-sessions-units-left-pending).
- **Step-key switch.** Still present under the Codeplug part on MM9PDY targets (removed for the AT-D890UV in a later PR; the DM-32 MM9PDY target keeps it).
- Leaving the page drops the session. The dialog cannot be dismissed while a transfer runs.
